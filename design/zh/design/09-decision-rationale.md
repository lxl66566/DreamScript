# 09 — 决策依据

状态：本文件是 `docs/en/design/08-decisions.md`（阶段 3 决策记录）的配套文档。对全部 42 个决策点，本文件详述决策的依据：起约束作用的条件（章程硬性要求、作者口味校准、预算上限、运行时基线）、胜出选项的决定性论据、每个落选选项的决定性反对论据、证据指针，以及该选择锁定了什么。完整选项分析（含先例细节）在目录 `01-07` 中；本文件记录每个选择为何落在它落的地方，仅在论证需要处复述目录原文。英文原版：`docs/en/design/09-decision-rationale.md`，以英文版为准。

阅读指南：每个点使用同一结构——约束 / 获胜理由 / 落选理由 / 证据 / 联动。「章程要求 N」指 AGENTS.md 的硬性要求；「research/0N §X」指研究笔记，其编号与目录引用一致。术语沿袭 08：「延后增量」指裁决为 1.0 范围之外、且保留无需破坏性变更的迁移路径。

## A. 定位

### A1 — 定位：独立内核加可嵌入的平台模式

**约束。** 章程要求 1（解释执行、允许内部 IR）与要求 3（超高性能、分层优化）都预设一个由本项目端到端掌握的运行时；作者的 TS+bun 工具口味要求一等公民的独立 CLI；嵌入有价值（Lua 的定位）但居次。

**获胜理由。** (c) 先造出性能章程本来就要的独立运行时，然后靠两个已有决策把嵌入拿下来：平台是导出效应处理器的普通包（06 H5b），跑在 E1d 处理器运行时上。嵌入不新增架构——它是同一运行时换由宿主进入。

**落选理由。** (a) 纯独立放弃了 (c) 几乎免费就能交付的嵌入定位。(b) 嵌入优先让宿主掌握分配与效应（Roc 姿态）；平台版本随之成为每个包的兼容单位，固定丰富的标准库故事被削弱（research/06 §2.6、§5.4）。(d) wasm 优先使值表示服从 wasm GC 约束，并迫使 E2b 纤程经 JSPI 形态的机制降级（research/03 §b.4；07 H1d 的权衡）——wasm 是 tier-3 的部署目标，不是架构。

**证据。** research/06 §5.4（按 RISC 伦理拆解的平台反转）、§7 组合 D（嵌入作为附加轴，作为独立答案过窄）；research/03 §b.12（后端风险清单）。

**联动。** H5(a)+(b)；A2 的工具优先级；「标准库不拥有效应」的文化承诺软着陆（默认平台就是 `ds` CLI 本身）。

### A2 — 主要工作负载：CLI/工具/脚本优先，游戏/仿真其次

**约束。** 工作负载的选择决定 v0 工具必须证明什么：启动延迟、编辑-运行循环、热重载。作者日常是小工具与脚本（TS+bun）；AI/数值工作必须可达但不反向塑造内核。

**获胜理由。** (a) 由分期计划中已有的决策直接支撑：mmap dsmod 即时启动（research/06 §6.3 的 10ms 内预算）、零配置脚本模式（H6c）、以及从不要求预热的解释器优先层。(c) 由双槽热重载运行时（06 H6 必选项 5）与查询编译器支撑——两者都因别的原因已承诺；Mun 是「这组搭配正是游戏重载所需」的先例。(d) 经 tier 3 保持可达，不为它花 v0 预算。

**落选理由。** (b) web 后端需要长时运行的监督与服务打磨；两者在内核就位后以 E2b nursery 与 E4d 式监督之上的库层到达，把它设为主负载会让 v0 围绕延后特性重排。(d) 设为主负载会把 B7 拉向完整数值塔与章程解释性预算拒绝的 Julia 式需求。

**证据。** research/06 §6.3（启动杠杆）、§4.5（热重载）、§1.10（脚本到包的生长路径）；research/03 §b.10（tier-1 的 3-10 倍目标）。

**联动。** H6(c) 脚本模式；双槽运行时在分期中的优先级。

### A3 — 兼容策略：1.0 前快速破坏，之后 semver；哈希落在包一级

**约束。** 1.0 之前必须能修检查器层面的错误（B1c 的不相交机制是风险最高的部分）；1.0 之后生态需要稳定性承诺。作者的 Nix 之痛（全局锁破坏依赖方、内部无文档）排除「上游更新级联破坏下游」的设计。

**获胜理由。** (a) 到 1.0 是 Roc/MoonBit 姿态，也符合现实：检查器成熟期没有可被破坏的用户。(b) 恰在生态动力学启动时接管。(c) 的哈希思想在文化代价为零处被采纳：包身份用 blake3 内容哈希级联，清单即锁，`follows` 式全局变更在构造上不可能存在（H6b）。

**落选理由。** (b) 从第一天起就冻结未定型语义——Cargo 纪律预设语言已稳定。(c) 作为源码级身份模型废除纯文本文件，git、grep、patch 与文本 LSP 都要经同步协议重造（research/06 §1.8）；便宜的借鉴是给 IR 工件与包身份做哈希，G3.5 的 dsmod 已经在做。

**证据。** research/06 §1.8（对 Unison 的评估）、§2.3（Zig `build.zig.zon` 依赖哈希级联，「清单即锁文件」）、§2.4（Inko `require URL VERSION CHECKSUM`）。

**联动。** H6(b)；G3.5 的内容哈希校验。

## B. 类型

### B1 — 类型基础：混合，名义标签按集合论组合

**约束。** 作者的集合论口味（章程哲学）与 README 的集合指令（`A = B | C`、`B & C`、`B - C`）；编译期错误优先于运行时错误；拆箱带类型寄存器 VM 基线（每个槽位的类型都是编译期常量，research/03 exec 6）；错误处理（B5/E4）与线性性（`~Copyable` 作为取反约束）都消费这里的代数。

**获胜理由。** (c) 把 README 的表层保留为名义原子之上的普通类型表达式，把穷尽检查锚在标签身份上（枚举覆盖难度——调研中实现最多的检查器，research/04 §4），让每个并集停留在 research/03 的拆箱标签+载荷成本上，并给 `~Copyable` 一个天然的家：集合取反与并集组合（`File[Open] | File[Closed]`）。它有最强的贴近生产的证据：MLstruct（OOPSLA 2022）正是这一模型并宣称主类型推断，TypeScript 的可辨识联合是其降级版量产形态。

**落选理由。** (a) 全结构内核表达力最大、风险也最集中：完整布尔代数上的主类型推断没有量产编译器（research/05 §2.3），名义封装消失，IC 需要形状哈希而名义标签只需一个 id。(b) 纯名义检查器最简单，已记录为可逆回退，但它删掉错误集合算术、「null/错误/enum 一套机制」的故事（Phi），并迫使到处包 Result——research/04 §12 风格 D 显示语法糖随即被花在补偿上。(d) 保留 README 语法，但其 `any` 回退把每次推断失败转成动态类型（违反章程），且非标签操作数上的差类型把 match 编译成谓词链——集合代数在这台 VM 上唯一不再免费的地方。

**证据。** research/04 §3（MLscript、Whiley、TS 收窄调研）、§12（风格 D 补偿阶梯）；research/05 §2.1-2.3（语义子类型脉络、解析即交集子类型）；research/01 跨领域注 1（可复制性作为取反集合约束）。

**联动。** B4(c)、B5(d)、E4(b)——`T?`/`?`/`or`/`.err` 表层只存在于并集之上；不相交检查器成为 B6(a) 的承重件；已记录回退是 B1(b)，届时 E4(b) 退化为基于 match 的处理。

### B2 — 推断：双向骨架加边界签名，再加流精化

**约束。** 解释性预算；脚本人体工学（REPL、免标注局部）；B1(c) 的代数必须在稳定点被检查；仿射流分析偏好写明的边界签名（research/05 §7.1：Hylo/Koka 的证据全部使用被检查的签名）。

**获胜理由。** (a)+(c) 组合让检查器的工作有界：标注把集合代数锚定在模块边界；精化只在局部收缩已知类型。精化是单调的，这是它能与交集、取反组合而无需求解器机制的结构性原因（Whiley 与 TS 都已量产；唯一的集合类型成本——重载组空性检查——组内二次方且可缓存，research/05 §2.2）。在不可变默认之下，流类型的两个已文档化难点（可变性、闭包捕获已收窄局部）大部分消失（research/04 §3）。

**落选理由。** (b) 不带代数的完整 HM 干净，但会把 B1 压向纯名义；带上代数它就是 MLscript 研究计划，其主类型结果没有量产编译器——v1 拒绝下注。并集/取反上的合一错误信息也是未解决的 UX 问题。(d) 处处标注是 Go/Zig 姿态——恰是作者不喜欢的两门语言，而且杀死 REPL 人体工学，那按章程使命是解释型语言一半的意义。

**证据。** research/04 §6（标注纪律：局部推断、顶层必需）、§3（流类型调研与已知限制）；research/05 §2.3、§7.1。

**联动。** `?` 传播检查变成对写明返回并集的集合包含判断（research/04 §11）；仿射检查器在每个边界拿到固定事实。接受的已知限制：不做经可变联合类型字段的收窄——不可变默认下罕见，若日后要求 `var` 联合字段则是真实的墙。

### B3 — 积与和：名义 structs/enums 加匿名元组

**约束。** 穷尽检查器成本；VM 布局稳定性（声明式布局、每型一个 type_id——research/03 的最优情形）；语法糖预算；临时聚合的人体工学；作者对「机制收益配不上语法糖」的厌恶。

**获胜理由。** (d) 给出声明式布局（VM 最优）、平凡的穷尽（覆盖声明 case）、低推断负担（名义原子做合一，元组是结构积），元组承担临时聚合；research/04 §2.5 保留集里的匿名 record 字面量以「编译器合成名义 record 的语法糖」找回结构化便利——且该语法糖延后到推断方案定型，v1 内核不为它付任何代价。

**落选理由。** (a) 匿名结构 record 让每个字面量的布局按形状派生、IC 按形状哈希，两个库的同形状类型按设计合一（TS 的粘合世界属性，对 TS 无妨，对想要名义封装的语言是负担）。(c) 行是整个目录中单位语法糖对应机制最重的：行合一把行变量漏进诊断、开放变体破坏穷尽匹配、行类型参数布局静态不可知（装箱或按形状 IC，research/05 §6.3）。Koka 只在效应这一无可回避处付费；Gleam、Roc、MoonBit 对数据全都拒绝了行。(b) 纯名义丢掉临时粘合，(d) 的元组把它找回。

**证据。** research/04 §2.5（保留集）、§14 / research/05 §5.1（moonbit-core 的 struct/tuple/enum 证据）；research/05 §6.3（IC 键控）。

**联动。** F7 第 25 行（record 语法糖延后）；D3 的下标操作在声明式布局上运行；拆箱错误返回获得稳定布局（research/03 的寄存器内 Result）。

### B4 — 可空性：`T?` 作为 `T | none` 的零语义别名

**约束。** Phi 论题（research/04 §3）：null、错误与 enum 是同一特性——并集中的单位成员，配 `is` 收窄与 `or` 提取；作者的 Kotlin/TS 肌肉记忆；语法糖预算。

**获胜理由。** (c) 是 (a) 的确切语义加一个熟悉拼写，成本只是一个别名：`none` 是若干单位类型之一，`T?` 即 `T | none`，同样的三个 token（`is`/`or`/match）服务 null、错误与 enum。在 B1(c) 下，`T | none` 与 `T | E` 字面上是同一构造，提取词汇只需陈述一次（research/04 §11：三个 token 对照 Kotlin 四个、Swift 五个）。

**落选理由。** (b) 语言级 null 让「缺失」成为错误并集旁的第二机制——恰是 Phi 记录的「三个特性干一个特性的活」结构——并拖进 elvis/`!!`/`?.` 写法（Kotlin 四项语法糖特性）。它还破坏 B5 的统一性：`?` 与 `or` 对 `T | none` 与 `T | E` 的操作完全一致。(a) 纯并集是同一语义配一个较不熟悉的拼写；别名不花钱，拒绝它不换来任何东西。

**证据。** research/04 §3（Phi 机制、`V | none` 扁平化限制——歧义处用显式 `Found[V] | none` 包裹，与 TypeScript 同限）、§11（token 记账）。

**联动。** `T | none` 的槽位 niche 打包仍是合法的后续优化 pass（引用永不为零）；`?.` 留在 v1 之外，真实代码确有需求时作为薄反糖补充。

### B5 — 签名中的错误载体：先并集成员，行作后续语法糖

**约束。** 错误必须保持可存储数据（nursery 收集、监督、缓存——research/02 §7.8）；传播在寄存器 VM 中必须便宜；通往完整效应的路径必须保持增量；单子提取口味（签名里不要包装类词汇）。

**获胜理由。** (d) 从研究确立的表示等价出发：返回类型里的 `T | E` 与 `exn` 行携带相同信息（Koka 的指称表让这一点字面成立，research/02 §7.8）。并集携带的错误保持数据身份、只花一次被预测的分支（research/03 exec 6）、按并集算术组合（Roc 的自动合并），并把 `throws(...)` 留作 v2 写法反糖到同一并集——是兼容演进，永远不会变成重构。

**落选理由。** (b) Result 包装重新引入嵌套（`Result<Option<T>>`）、把 Ok/Err 词汇放进每个可失败签名、且仍需 `?` 式传播语法糖——Rust 补了它——所以它是 (a) 的机制加一层包装。(c) 行要求完整 E1a 推断机制，哪怕只有错误在用；错误也不再是 nursery 无需具体化就能收集的值。(a) 单独看（标注可选的推断并集）与 (d) 同基底，只是没有说清效应就绪的桥；(d) 保留基底并点名了接缝。

**证据。** research/02 §7.8（可互定义性结论与推荐）、§7.7（单分支成本）；research/04 §11（该表层已效应就绪）；Effekt 的 `result`/`value` 对（research/02 §2）。

**联动。** E4(b)；后续 `throws` 语法糖必须无损反糖，因此 v1 传播用 Zig 包含规则（无隐式转换）。

### B6 — 多态：实例头两两不相交的一致集合论 trait

**约束。** 作者的反特化立场（章程哲学：泛型实例不得重叠，整体移除优先级规则）；B1(c) 的代数作为解析基底；对线性友好；字节码原生执行；一致性但不要孤儿规则的已知代价。

**获胜理由。** (a) 用一次可判定计算同时替换孤儿规则与特化：对同一 trait 的每对实例头，在声明时与链接期对最终实例环境证明 `H1 & H2 = Empty`。解析由此成为经肯定前件的交集子类型（OOPSLA 2020），唯一性从代数得出，任何优先级机制都不存在——「分派由类型与集合代数决定」即章程不变式原文。外来类型实例合法，删除了 Rust 的 newtype 包装与对 blanket impl 的否决（research/05 §3.2）。实例头是标签集合，使 H3(a) 的内联缓存无需打破平局。证据覆盖每个轴：Rust trait 的形状、MLstruct 的兼容性、.NET 按值类型的不可见模板化作为运行时先例。

**落选理由。** (b) 显式字典传递是对线性最友好的，保留为逃生口，但其样板墙正是 Scala 造出 implicit 搜索的原因；`_` 语法糖悄悄把它删掉的解析又请回来。(c) ML 模块直接顶到语法糖上限（签名、applicative 与 generative functor、一等打包），并让每个泛型容器变成两步实例化——OCaml 围绕这一摩擦长出了 ppx 代码生成。(d) comptime 泛型逃出集合代数（生成的头可能相交、生成之后才发现）、要求对生成代码做线性检查、并在启动时支付实例化扇出；research/05 §9 的裁决是采纳其反射一半（G1b）、拒绝其泛型一半。

**证据。** research/05 §2.2（解析即交集子类型；两两空性成本组内二次方可缓存）、§3.1-3.5（特化与一致性代价）、§6.3-6.4（证据词与 IC）、§9（评分表：(a) 是唯一同时满足全部四条硬性约束的选项）。

**联动。** H3(a) 的证据 ABI；不相交检查器承重，是 B1(c) 点名的进度风险；带作用域具名实例（b 精简版）延后增量，歧义永远报错。

### B7 — 数值塔：i64/f64 默认，溢出陷入，显式回绕

**约束。** 拆箱槽位是解释器的红利（research/03 exec 6——装箱是静态类型存在的意义所在的 2-10 倍项）；溢出策略在解释之下必须可预测（research/04 §8：陷入是唯一这样的策略）；算术快乐路径零检查（research/03 的 ADDOV 注记推荐 panic 而非 bigint 回退守卫）。

**获胜理由。** (a) 让 i64/f64 裸放槽位（`ADDI64` 是一次无标签的机器加法），让溢出成为确定性陷入——可复现、可调试、一条由 copy-and-patch 层折叠的冷溢出边——并给哈希/PRNG 代码显式的 `+%` 族。调试与发布行为一致，这是 Rust 的 debug-panic/release-wrap 分裂给不了的。后缀覆盖偶发宽度需求；数值塔日后可经数值 trait 接缝生长。

**落选理由。** (b) bigint 默认要么装箱每个 Int（整体删除拆箱槽位设计），要么跑双表示，其溢出迁移恰是 research/03 拒绝的守卫类——JIT 类型稳定性还在大小边界处 Julia 式劣化。(c) 完整数值塔花费宽度歧义规则、IC 预热前每次多态数值调用的证据词、以及 f16/f128 软件路径，而脚本甜点区很少需要。(d) 是 (a) 加一个计划；其 decimal 一半已作为库路径采纳（Roc 的 `Dec` 让 `0.1 + 0.2 == 0.3` 按构造成立），(d) 整体上没有更多要决定的了。

**证据。** research/04 §8（溢出策略调研与推荐）；research/03 §b.10、§b.2（解释器与 C 差距分解、ADDOV 指导）；research/05 §5.1（Roc `Dec`）。

**联动。** 除零与移位宽度溢出陷入；返回错误并集的算术变体是类型为 `T | ArithError` 的库函数；与 B9 的 float 相等选择相互作用（裸 f64 上的按位结构 `==`）。

### B8 — 字符串：不可变 UTF-8 加检查切片

**约束。** 诚实的相等与哈希；ASCII 密度（配置/日志文本是常见情形）；research/03 的一根裸指针槽位表示；字素诚实而不拖慢内核；FFI 边界允许转换（归属 06）。

**获胜理由。** (a) 即 research/04 §7 的建议原文：UTF-8 字节放在 `{type_id, rc, byte_len, bytes}` 后（Inko 的单次分配布局先例），切片必须落在字符边界上、经检查 API 返回 `String | none`（复用 B4 的并集纪律而非 panic），`chars` 迭代，字素在标准库。相等 O(n) 配长度快速拒绝；ASCII 重的文本内存 1 倍。

**落选理由。** (b) 驻留换得驻留后 O(1) 相等，但创建要付同步全局表查询，切片要么重新驻留（O(k)）要么失去驻留（两套相等机制），表驻留内存（Lua 已知行为），多核分片也不友好。(c) UTF-16 让 ASCII 内存翻倍、每个标量操作都带代理对逻辑——它的 O(1) 索引是 O(1) 的坑，正确的字符访问仍需感知代理对。(d) 是 (a) 加 rope 库类型；编辑器工作负载出现时作为未来补充采纳。

**证据。** research/04 §7（字符串调研与建议）；research/03 §b.4（字符串布局、切片即 (ptr,len) 槽位对）。

**联动。** 切片是由父对象 RC 保活的非持有借用——正是 B9/C2 已规定的借用操作数形态；H4 的不移动堆才让裸指针安全。

### B9 — 相等：带五处例外的通用结构化 `==`

**约束。** 全体性承重（自反性是字典键与去重可靠的基础——research/05 §5.2 破坏点 2）；不可变默认之下的值语义让身份几乎无意义（Roc 的论证，research/04 §9）；比较绝不能消耗仿射操作数；无样板口味。

**获胜理由。** (a) 由构造保证全体：函数比较静态拒绝（通常是 bug——Elm 的规则）；float 按位结构比较，`nan == nan` 成立、字典保持可靠，旁边配具名的 `is_float_eq`/`is_approx_eq` 提供 IEEE 语义；可变单元与 `~Copyable` 资源按身份比较（避开 OCaml 的遇环发散）；操作数只借用、绝不消耗。它删掉 MoonBit 手写的逐元组元数 `Eq` 实现（`builtin/tuple_eq.mbt`）与每一行 `#[derive(Eq)]`，而且不存在 `===`。按类型自定义语义仍可用具名方法（`equiv` 式）到达，按解释性预算那才是它该在的地方。

**落选理由。** (b) trait 中介相等把 `T: Eq` 约束撒进每个泛型签名，重新引入章程避开的连贯性问题；即便在 derive 丰富的语言里 MoonBit 的样板也是已文档化的代价。(c) 内建加 derive 在 float 选择为按位结构后坍缩为 (a)；两者中排序都保持 derive 中介。(d) 引用身份与语言自身的值语义作对，Go 对不可比较接口值的运行时 panic 是「身份优先只是更晚失败」的证据。

**证据。** research/05 §5.1（Roc `is_eq` 拆分、OCaml 多态比较、MoonBit derive、Kotlin/Swift 合成）、§5.2（五个全体性破坏点）、§5.3（结论）；research/04 §9；research/05 §1.9（Go）。

**联动。** `Ord`/`Hash`/`Show` 是 05 拥有的 derive；`==` 永不接受用户重载（F5）；哈希必须与结构化相等一致（`Hash` derive 的契约）。

## C/D. 线性性、所有权、内存、数据

### C1 — 线性性形态：仿射内核加可选的 `~Copyable` 线性层

**约束。** 章程要求 2 写的是「静态线性（或仿射）类型，编译期强制」——仿射是合法读法；要求 6 要低学习成本与低出错率同时保留性能收益；要求 3 要内存红利；研究共识是「人体工学上推导胜过书写，保证上书写胜过推导」（research/01 §a）。

**获胜理由。** (b) 把两半拆开：日常代码只有一条规则——仿射值的赋值即移动，被移动的绑定已死——普通可复制值从不会可观察地碰到它；保证住在可选的 `~Copyable` 层，在那里写下来才是意义（二次使用是编译错误；`deinit` 恰好执行一次；幻影状态与 B1(c) 并集组合）。检查器是 last-use/DI 分析——Austral 的单遍前向扫描，或 Hylo 本来就跑的抽象解释器。这直接回答作者的所有权开放问题：机制恰好存在于资源存在的地方，别处不可见。

**落选理由。** (a) QTT 在每个绑定符上放一个重量；GHC 的经验表明多态重量把 UR 约束漏进普通签名，research/01 §c 表 3 把签名噪音评为非常高——违反章程要求 6。(c) 隐藏线性按原文违反要求 2（需要改写章程），且把最难的编译器 pass 放在最前；其机制被采纳为分期的优化终局（Roc 与 Koka 都是先交付运行时唯一性检查、后做推断——research/01 §d 组合 6）。(d) 运行时借用检查把别名正确性封顶在运行时 panic——与编译期错误哲学相悖；其借用计数被采纳为 v0 诊断基底，便宜且可移除。

**证据。** research/01 §B.3（Swift SE-0390、Hylo `Copyable: Movable`）、§B.5（Austral 的单遍检查器）、§B.6（QTT/Granule/GHC 代价）、§B.8（Inko 可读的移动错误）、§B.12、§d 组合 6（分期次序）。

**联动。** C2(d) 成为必需（只有移动没有借用仍需一个读取通道）；与 C4(a) 的天然配对；C5(c) 的 deinit 住在这层；E3 的可发送性随之而来（线性值按构造即可发送）。

### C2 — 借用：二等参数传递模式

**约束。** without.boats 清单（research/01 §B.4）：moves、borrows、lifetimes、drop 是四个半耦合特性，难点在耦合——采用可行的最便宜耦合；任何地方都不出现生命周期标注；UFCS 调用点必须不带模式语法。

**获胜理由。** (d) 只在声明处放模式（默认借用、`mut` 排他、消耗），调用点零语法，`xs.push(1)` 不论模式读起来完全一样。二等借用无法逃逸出调用，因此检查是过程内的——没有生命周期、没有别名分析、逃逸分析成为编译期事实。下标把同样的模式扩展到元素访问，替换 getter/setter 协议。规则总量一页纸。

**落选理由。** (a) 移动加显式复制是 research/01 §B.4 记录的 clone() 文化——每个读取点都变成一次转移决策，而各种变通全都在「动态检查或动态计数」处会合。(b) 推断借用给出接近 C 的数字（Koka/Roc/Lobster），但那是过程间不动点，推断失败处没有用户可见契约（Roc issue 12420 的可观察性能效应），且先造它意味着第一个能跑的解释器之前先造最难的 pass——延后为纯优化。(c) 运行时借用计数作为面向用户的模型让别名 bug 变成确定性 panic；保留为 (d) 之下的 v0 诊断层，那里二等借用静态不可能悬垂，计数只会在 FFI/unsafe bug 上触发。

**证据。** research/01 §B.3（Hylo `let`/`inout`/`sink`/`set`、借用即 IR 级投影）、§B.4（耦合清单与变通目录）、§d 组合 3（「模式而非生命周期」综合）；Swift SE-0377 的 `borrowing`/`consuming` 作为工业界趋同。

**联动。** C3(b) 与 D1(b) 是同一机制再添两个用途——一个检查器三份工作；一等引用被永久排除，有意为之。

### C3 — 不可变性机制：const/var 加排他窗口，底下 FBIP

**约束。** 章程要求 5：绑定默认不可变，可变是显式、局部可见的选择；值语义需要排他的被调方修改（Hylo、Swift、Inko 都提供的形态）；Hylo 与 Swift 共同保持的非特性——不可变绑定不可修改（重绑定不可变性以边际语法糖换别名悖论，research/01 §B.3）。

**获胜理由。** (b) 让 `mut` 参数模式成为窗口：一次调用内的排他可变访问、静态保证、词法可见即调用本身——「局部可见」是语法的性质，无需纪律维护。窗口内零运行时检查（无别名已被证明）；窗口外一切共享不可变。(d) 的 FBIP 垫在底下作为运行时保证（C4a 交付），函数式更新在值唯一时同样原地执行——正是 Koka 的组合（var 局部 + FBIP）。

**落选理由。** (a) 仅局部 var 禁止了值语义需要的那一种修改形态，把原地算法推进 builder 模式。(c) 内部可变性（Cell/RefCell）解决的是窗口留下的「不可变绑定背后的共享修改」问题，代价是运行时借用检查与两条承重不变式（不可变数据上的无屏障 RC、代数检查的省略）；选了 (b) 之后该问题不存在，逃生口只会削弱纪律。(d) 作为全部表层（完全没有 var）让算法代码读起来像消耗-返回管线——那正是 FBIP/TRMC 研究要修的别扭。

**证据。** research/01 §B.3（Hylo `inout` 窗口、Swift `mutating` 加动态排他作为成熟语言的安全网）、§B.2（Koka FBIP 的保证复用引文）。

**联动。** `var` 关键词的含义（可重绑定局部）与 F2 的 `const`/`var` 组合；D1(b) 是同一决策从收敛侧看的样子。

### C4 — 内存策略：Perceus RC 加块复用，加逐帧 arena

**约束。** 确定性 deinit（C5c）排除对承载资源的值做追踪回收；零停顿零屏障排除写屏障体制；FFI pinning 想要不移动的堆；运行时必须小团队能造（Inko 的后事是这一证据类）；线性性让逃逸成为编译期事实（research/03 §a.7）。

**获胜理由。** (a)+(d) 是 research/03 §a.8 的处方原文：装箱/共享值用 Perceus 精确 RC 加复用——释放即时且缓存友好、终结器确定性、死亡块被复用时分配近乎免费——临时值用逐帧 bump arena，其可靠正来自线性性禁止静默逃逸（分配一次加法、回收一次恢复）。在 C1(b) 下，dup/drop 插入退化为「克隆时 incref、每个唯一死亡点 decref」，因为线性检查器给出使用计数（research/03 §b.6）。非原子计数在线程封闭下可靠，E3(b) 的 fork-join 所有权转移维持了这一点。

**落选理由。** (b) 带代引用让引用翻倍到 16 字节（塞不进拆箱寄存器栈帧模型），把静态保证换成访问时的动态检查；它是「仿射摩擦被证实比预期更糟时」的点名回退。(c) 追踪 GC 背着 Inko 的后事——immix 复杂难调、最终连 GC 一起移除换所有权+ARC——外加每层的安全点、精确栈图与屏障，移动式收集器还与裸指针字符串、内部指针、FFI 冲突；它也浪费线性红利（编译期逃逸分析）与不可变红利（无需屏障）。环这一 GC 的真正优势由类型级拒绝加 H4(d) 双钩子收集器接口作为增长路径处理。

**证据。** research/01 §B.2（Perceus PLDI 2021、kklib 钩子、FLR）、§B.7（Vale）、§B.8（Inko 的 GC 移除轨迹）；research/03 §a.7-8、§b.6（复用配对，「无借用分析、无干扰分析」）。

**联动。** H4(a) 实现它；诚实的记账（装箱/共享残余继续付 RC；复用 pass 是优化器工作，mimalloc 兜底）写进分期。

### C5 — 移动、丢弃、确定初始化：`~Copyable` 层上的 RAII deinit

**约束。** 仿射值需要明确的死亡点；终结器必须确定执行（research/01 §B.12 第 3 项）；纤程中止/取消需要清理钩子（research/02 §b.8）；可复制类型没有唯一死亡点（SE-0390 的规则）。

**获胜理由。** (c) 把 `deinit` 限定在 `~Copyable` 类型，在唯一实例死亡时恰好执行一次——覆盖提前返回、panic、取消收尾的每条路径。资源使用者什么都不写；资源作者写一个块。deinit 分派是静态调用（具体类型已知），它需要的 DI/last-use 机制是所有选项都要求的基础设施。这也是 E5 的清理故事：收尾遍历栈帧执行线性析构。

**落选理由。** (a) 只有隐式丢弃就没有钩子，File/Socket 无法作为安全类型存在——它杀死 C1(b) 资源层，而那层的意义就是钩子。(b) 全员显式 drop 重现 Austral 的「消耗即纪律塑造全部代码」代价，且提前返回与 panic 下的手动 drop 正是 RAII 要移除的 bug 类（Vale 为此造了 higher-RAII）。(d) 处理器式清理把内存设计耦合到效应时间表——章程拒绝的那种耦合——并把所有资源推迟到效应存在；Koka 同时提供 deinit 式资源与处理器组合子，所以 (c) 什么也没堵死。

**证据。** research/01 §B.3（SE-0390 deinit 语义）、§B.5（Austral）、§B.7（Vale higher-RAII：「所有权保证未来调用必发生」）；research/02 §b.8（析构函数即纤程中止钩子）。

**联动。** E5(a)+(b)；显式 `drop` 内建仅存为调试/FFI 工具。

### D1 — 可变性收敛：仅排他窗口

**约束。** 与 C3 相同（要求 5），从收敛侧看：可变可以碰哪里，谁来保证。

**获胜理由。** (b) 不需要任何额外机制——`mut` 窗口就是收敛。可变永远是对持有接收者的具名调用、静态排他、词法可见；共享可变按构造不可表示，而非靠纪律。

**落选理由。** (a) 仅函数局部 var 花掉真实表达力（无修改方法、无下标 setter），换来的安全不比 (b) 多——窗口本就静态排他。(c) 能力门控审计「谁可以改」而非「哪个别名排他」，所以无论如何底下仍需 (b)；若想要 E1c 式审计可后叠加（research/02 §d 组合 2 描述的进阶路径）。(d) 纯表层是正确的运行时行为（C4a 经复用交付）与错误的唯一通道——Koka 自己也在 FBIP 旁保留 var 局部。

**证据。** research/01 §d 组合 3（一个机制三个用途）、§B.3。

**联动。** 无新增——本行记录 C2(d)/C3(b) 已把它关闭。

### D2 — 集合：函数式 API 的线性可变 COW

**约束。** 「默认不可变」（要求 5）与「接近编译型语言的性能」（要求 3）必须对数据密集脚本同时成立；research/03 §b.9 的不对称是决定性的：持久化更新分配 O(log n) 个 RC 节点，仿射原地更新分配零个。

**获胜理由。** (b) 是两条章程同时为真的唯一语义：更新在 API 层是写时复制，当且仅当值被唯一持有时原地改写——保证且可观察（Koka 的 FBIP 契约；Roc 的 Borrow/Consume/COW 内建契约）。被共享时发生复制，表现为性能注记，永远不会变成错误。持久化 HAMT 仍是同一 RC 运行时上的普通库类型；`Bytes`/`Vec` 是同一模型的拆箱唯一端，达到 FFI 级。

**落选理由。** (a) 纯持久化放弃零拷贝缓冲，用节点搅动惩罚常见情形——正是 research/03 标记的不对称。(c) 双模式让标准库表面积翻倍、切换点变成教学话题；(b) 本就优雅降级。(d) 大小分类是 (b) 的结果（小值按值语义复制；大缓冲是唯一拆箱类型），不需要成为规则。

**证据。** research/03 §b.9；research/01 §B.2（FBIP 保证引文）、§B.1（Roc 所有权契约、issue 12420 的可观察反面）。

**联动。** C4(a) 的复用 pass 兑现承诺；「有别名即复制」是已文档化行为，不会变成错误。

### D3 — 迭代器：隐藏游标协议上的组合子，编译器融合

**约束。** 25x 数字（MoonBit 在零成本 `Iter` 上的编译器级融合，research/03 §a.10）显示融合的收益；多次恢复不得捕获线性值（research/02 §b.8）；库作者需要定义自定义迭代的方式；语法糖预算。

**获胜理由。** (d) 给用户他们已认识的表层（map/filter/reduce 链、`for` 循环），给编译器可融合的形式（带类型 SSA 的方向性规则），给标准库作者隐藏协议（线性游标，线性性即可消除边界检查，research/03 §b.7）。不可融合的形状落回同一游标语义，行为在融合是否触发时保持一致。隐藏层日后可升级为纤程（若 E2b 落地）而表层零变更——整个设计依赖的「隐藏机制、稳定表层」分期。

**落选理由。** (a) 线性游标作为公开协议可行，但重复了 `for` 加组合子所隐藏的东西，且其二等借用不能被存储（对被排他借用结构的游标不能存进另一个结构）。(b) 一等生成器在每个元素上花一次纤程切换而融合一次不花（25x 差距量的正是这个），第一天就需要线性捕获类型规则，并让本目录耦合 E2 的时间表。(c) 只用组合子没有给库定义迭代的协议——不规则遍历落回手写循环。

**证据。** research/03 §a.10、§b.7（融合与游标纪律）；research/02 §b.8（多次恢复 × 线性约束）；research/01 §B.2（TRMC 作为递归侧的类比）。

**联动。** `-*>'` 生成器箭头保持退役；允许 v0→纤程的升级路径并分期。

## E. 错误、效应、异步、并行

### E1 — 效应系统：表层推迟、运行时处理器化、能力惯用法

**约束。** 章程要求 7：效应只有在配得上其复杂性时才采纳。研究分解（research/02 §5.8）：异步/效应的四项收益——不炸线程的 IO 延迟、可组合取消、调度抽象、签名级审计——没有一项严格要求行语法；每个胜出的设计都把「颜色」装在恰好一个位置。

**获胜理由。** (d) 在 v1 表层零支付（没有要学的东西、没有行词汇、没有推断错误的 UX），同时建造让完整效应日后可增量的机制：运行时从第一天起就是处理器形态，证据传递只在 nursery 边界服务两个内部效应（`cancel`、`discontinue`）——成本集中在本来就需要它的地方。(c) 的能力惯用法成为标准库惯例（Zig 0.16 的 `Io` 参数是落地先例）：脚本用环境默认处理器，测试、嵌入与调度选择用显式能力——同一份代码跑阻塞、事件或自定义调度器。

**落选理由。** (a) 完整行把行变量放进用户写的每个组合子签名；行推断与线性/仿射合一的先例稀薄（research/02 组合 3）；OCaml 5 的处理器四年后仍标实验——卡住的是类型/API 故事，运行时没有。(b) 精简能力集便宜但永远粗粒度（类型中无法区分文件与网络），并堵死用户可恢复抽象。(c) 单独使用让审计只剩隐式、调度抽象沦为无基底的约定；作为唯一选择它还让「传 io」的噪音成为默认姿态——这正是研究自己把 B 排在 A 前的原因。

**证据。** research/02 §d（三段式答案与组合 6）、§1（Koka 证据传递）、§5.1（Zig 的 Io 能力）、§8（VM 成本分析：每次效应操作一次间接调用，尾式恢复操作零分配）、exec 第 18 项。

**联动。** E2(b) 是该运行时的第一个客户；B5(d) 的 v2 `throws` 语法糖走同一接缝；记录了两条长期类型义务（仿射恢复；多次恢复续延禁止捕获线性值），待 v2 激活时生效。

### E2 — 异步：强制 nursery 的 VM 纤程

**约束。** 作者的解耦哲学点名函数染色是典型的纠缠特性（章程；作者自己的文章引用了 "What Color is Your Function?"）；取消必须可组合；解释器必须保持快；TCO 必须存活。

**获胜理由。** (b) 把颜色搬进运行时：堆纤程是解释器数据（可增长的栈帧数组；Lua `CallInfo` 先例），spawn 是一次分配，切换是指针交换 O(1)——阻塞式代码因此不需要状态机、不需要 Pin 类似物、不需要重复 API。强制 nursery 引入 Trio 语义与 Kotlin Job 树的落地记录：任务生存期词法定界、首个失败取消兄弟、错误在边界以并集导出——泄漏与丢失错误在结构上不可能。抢占是分派循环里每 N 条指令一次的标志检查，比 Go 的信号方案简单得多。TCO 按纤程成立不受影响；spawn 后立即尾循环的纤程永不增长其段。

**落选理由。** (a) 异步即效应是最优雅的写法，但先要 E1a 的行推断进每个组合子。(c) 无结构 spawn 是无结构的无色：孤儿任务、`context.Context` 穿线、丢失错误是已文档化的生产故障形态（作者自己的链接引用的 fasterthanli.m 证据），而 nursery 无法在不破坏所有假定 detach 的 API 的前提下补装。(d) 染色 await 保留双世界标准库、传染性 `await`、以 drop 取消的坑；Rust 的 Pin/Send 约束史表明染色加所有权一起超出可容忍的学习预算（research/02 §5.6）——同时把作者的两个开放问题答错。

**证据。** research/02 §5.5（Trio）、§5.4（Kotlin Job 树）、§5.2（Go 缺陷）、§5.6（Rust 染色+所有权代价）、§8（纤程经济学）、表 1 与组合 1（「去掉致命缺陷的 Go」）。

**联动。** E5(a) 是同一机制从资源侧看；E3(b) 共享线程池；裸 detach 需要显式根 nursery。

### E3 — 并行：可发送性基底上的 fork-join

**约束。** 章程要求 3 必须对多核算力成立；类型系统已把竞态自由（无别名可变性）与可发送性（线性=可移动，不可变=可共享）证明为定理——research/02 §7.9 的清单显示缺的只是调度器、取消定界、监督。

**获胜理由。** (b) 建在 (a) 上恰好买下缺失的那块：`par_map`/`par_reduce` fork-join 组合子作用于不可变或线性划分的输入——确定、可重放、按定理免锁，Perceus 静态计数让 fork 侧快照便宜（research/03 exec 8）。学习成本是两个组合子；可发送性规则是两句话，对照 Pony 的六能力格（它存在的理由恰是 Pony 没有线性类型）。

**落选理由。** (c) actor/隔离需要邮箱、进程调度、可能每进程一个堆——运行时增量最大——且对细粒度数据并行最弱（research/02 组合 4）；线性移动式消息去掉 BEAM 在痛处的复制成本，所以 actor 层日后可作为库叠加（监督器 = 带重启策略的 nursery）。(d) 单线程加 FFI 把语言内算力封顶在一个核——与章程要求 3 直接冲突；颜色问题被驱逐到 FFI 边界，并没有解决。

**证据。** research/02 §7.9（免费推论清单）、表 4、§5.7（Swift SE-0414/SE-0430 作为「线性/不可变早已给出隔离系统重建的东西」的回补证据）、§6（BEAM/Pony/Inko）。

**联动。** 非原子 RC 靠 fork/join 处的所有权转移保持可靠；E4(d) 监督保留为库候选。

### E4 — 错误处理：`?`/`or`/`.err` 的并集错误，加不可捕获陷入

**约束。** 92% 数据（灾难性失败压倒性地来自对非致命错误的处理不当，Yuan 等，经 research/02 §7）要求对预期失败做类型化处理；程序缺陷需要响亮且不可捕获的通道；语法糖预算；错误必须保持可存储以供 nursery。

**获胜理由。** (b)+(a) 拆开两类失败：预期错误是并集成员——扁平（无 `Result<Option<T>>` 嵌套）、可存储（nursery 收集）、由三个 token 处理而语义只需在并集上陈述一次（`?` 带检查包含规则传播；`or` 惰性回退提取首个想要的成员；`.err(h)`/`.ok(h)` 是差集类型，剩余类型显示还剩什么没处理）。旧 README 的 `.err` 在这里被修复后保留：表达式只定型一次，处理器经集合差集做工作，修掉 research/04 §11 记录的非组合性。程序缺陷 `panic`：纤程中止、线性 deinit 执行、陷入在 nursery 边界浮出——在这台 VM 里近乎免费。

**落选理由。** (a) 单独的 Result 即数据加陷入，运行时机制相同，包装词汇是 Rust 阶梯展示的那套（`Some`/`Ok`/`unwrap_or_else` 噪音——research/04 §12 风格 D）。(c) 异常即效应需要 E1a 机制，且让错误不再是值（无具体化就不能缓存、不能被 nursery 收集）。(d) 监督是叠加在任意选项上的层，不是对手；需要长时运行系统时随时可作为库采纳。

**证据。** research/04 §11（表层调研、端到端示例、对历史想法的三缺陷审计）；research/02 §7（92% 数据、Rust/Zig/Swift/Inko 趋同）、§7.6（扁平并集先例：Ceylon、TS、Zig 错误集合、Kotlin elvis）。

**联动。** B5(d)；token 集已定稿（08 已解决问题 2）；`?` 内的 Rust `From` 转换被否决，采用 Zig 包含规则。

### E5 — 取消与资源：nursery 作用域取消加线性消耗即关闭

**约束。** 线性性既不给取消语义（谁取消谁）也不给收尾保证——恰是 research/02 表 4 点名的两条缺口；进行中的线性消耗绝不能被打断在半途；取消不得意味着线程中断。

**获胜理由。** (a)+(b) 用一对组合盖住两条缺口：取消是协作式且 nursery 作用域内，只在 await/抢占点被观察（一次标志检查），因此消耗要么完成、要么其 deinit 在收尾时执行——即执行线性析构的栈帧遍历（research/02 §7.9(4)、§8）。以消耗关闭是一次静态移动：无 drop 标志、无 GC 终结化、语言内句柄按构造防泄漏。

**落选理由。** (c) defer 块是纪律，(b) 是保证——忘写 defer 正是消耗即关闭按构造堵住的洞；保留为作用域退出语法糖，规则是取消之下在收尾时执行（Koka 的 `finally` 语义，多次恢复之下条件化清理是错的这一事实所要求的）。(d) 原语式超时把一种定时器抽象冻结进规范；处理器/组合子形态（`firstof(timer, action)`、Koka 纯库的 `timeout`）可组合、可嵌套，并教会「这些是库代码」。

**证据。** research/02 §7.9（缺口清单）、§8（收尾遍历机制）、§5.5（Trio 取消定界）、§1（Koka `linear effect` 加 `finally` 的可靠性证据）。

**联动。** C5(c) 供给析构；E2(b) 供给作用域；FFI pinning 规则（08 已解决问题 1）补完边界故事。

## F. 语法

### F1 — 整体形态：TS 系花括号

**约束。** 作者口味：日常 TS+bun 表层、被喜爱；历史 README 自身的函数形态就是 TS 系；解析器与工具的简单性（LSP 优先的作者）；无分号换行规则任何花括号家族都能带。

**获胜理由。** (a) 是四种演示风格中最不新颖的表层（research/04 §12）：每个块以可见 token 开启，文法面向行、无布局状态，TS 工具直觉直接迁移。它也是 README 自身的形态，历史语料读起来几乎是正确的 DreamScript。

**落选理由。** (b) Gleam/Roc 花括号是最强对手（`fn name(` 是最佳 grep 锚点；每个构造都是平凡 AST 节点），并作为解析器原型阶段发现箭头赋值文法冲突时的已记录回退——但其 `fn`/`let`/`|x|` 符号不带来任何 TS 迁移。(c) 显著缩进要求解析器、格式化器、REPL、错误恢复同时具备感知空白的设施，并背着 Python/Nim 永久的复制粘贴与重构敏感；Koka 是唯一健康的实例且它为此支付了工具成本。(d) Rust 系熟悉，但与地基作对：research/04 §12 的结论是它的语法糖花在补偿集合类型的缺失上（F1.d 重新引入的 `Result`/`Option` 包装正是 B1/B4 要删的东西）。

**证据。** research/04 §12（四风格演示）、§6（缩进调研）、§13。

**联动。** F2 的 const 箭头声明；块规则（换行、无分号、尾逗号）。

### F2 — 绑定、函数、标注、返回

**约束。** README 先例（`const f = (a: int) -> int`、前缀 `?` 返回标记）；函数是值（README 立场）；`?` token 已被 E4 的后缀传播占用；表达式导向（if/match 是表达式）。

**获胜理由。** `const`/`var` 是 README 的词、TS 习惯、五个字母的承诺（不可变就是默认拼写）；`val`/`var` 押韵但不带来 TS 迁移，`let`/`let mut` 增加一个没有别的东西需要的修饰符。const 箭头声明让绑定与函数只有一种形态（与函数即值一致），定义名在自身函数体内可见以支持递归。`name: T` 加 `-> T` 让冒号只意味着「类型是」、箭头只意味着「产生」，与函数类型箭头一致。末表达式返回让块成为值；`or return`/`or break`/`or continue` 复用 E4 的 `or` 作为提前退出语法糖而非新关键字。

**落选理由。** 专就返回而言，README 的前缀 `?` 与后缀 `?` 传播相撞——一个 token、两个不相关含义、只靠位置区分；机器解析得了，人和错误信息不行。解决方案 (i) 让该标记退役、`?` 保留给传播；裸 `return` 关键字日后可作为纯 S1 补充（什么也不堵死）。声明侧的替代（`fn` 关键字、`fun`/`fn` 拆分、两者都允许）各花一个关键字或制造风格分裂，预算拒绝；grep 锚点的顾虑由 `const name = (` 本身就是完全可 grep 的定义模式来回答。

**证据。** research/04 §6（绑定/关键字调研）、§11（token 冲突标记与解决方案选项）。

**联动。** F1(a)；B2 的边界标注规则（顶层签名必需）；泛型参数写法归 05。

### F3 — UFCS 与管道：完整 UFCS，管道延后

**约束。** 作者对 Koka UFCS 的欣赏；语法糖预算（Kotlin 花四项特性在扩展函数/属性上，UFCS 把它们删除）；解析绝不能变成优先级搜索（反特化）；E1c 的能力参数不能被点调用吞掉。

**获胜理由。** (a) 是一条反糖规则（`x.f(a)` = `f(x, a)`），零运行时成本、无候选搜索，在三门生产语言（Koka、D、Nim）验证且无混淆报告；research/04 §5 的结论。解析固定且简单：先自由函数、再 trait 方法、`Trait::f(x)` 限定是逃生口、歧义即错误。能力规则保住审计诚实：能力参数具名并排除在点位置之外，`println(io, msg)` 永远不能写成藏起 `io` 的 `msg.println()`。

**落选理由。** (b) `|>` 与链式调用是同一反糖的第二个习惯写法——Roc 以「与链式调用加 `?` 冗余」为由删除了自己的管道，所以它被延后（S1、增量）而非纳入。(c) 仅方法调用经 trait 后门重新引入扩展机制，并支付 Rust 的自动引用/解引用候选搜索这一隐藏 S3。(d) 无 UFCS 的管道优先删除全部点链语法糖，且它是柯里化产物。

**证据。** research/04 §5（四路对比、Roc 删除数据、Koka 验证过的语义）。

**联动。** 点位置的含义；Kotlin 第 13-15 项（infix、扩展）被本行删除。

### F4 — 模式匹配：带集合差集诊断的 Rust 形态分支

**约束。** 在 B1(c) 之下穷尽性是集合覆盖计算——诊断字面上就可以是缺失集合；守卫防止 Gleam 的分支嵌套膨胀；语法糖预算；线性 match 人体工学。

**获胜理由。** (a) 拿到守卫（`pat if cond`，与 Kotlin 2.1 稳定的守卫是同一特性）、或模式、解构、以及失败信息把缺失成员作为集合点名的穷尽检查（「missing: NotFound | Locked」）——在 B1(c) 下该诊断是一次集合计算，调研中无一语言能及，因为没有一个有这套代数（research/04 §4）。若 B1 退到纯名义，同一检查器优雅降级为点名缺失的 enum case。

**落选理由。** (b) Kotlin 的 `when` 是同一能力换第二个关键字与对照基线 `=>` 的 `->` 分支。(c) 无守卫的 Gleam 极简是已文档化的反面教材：扁平决策表膨胀成分支内嵌套 `if`。(d) OCaml 的 `when`/`as` 与 (a) 只差选词；`as` 读起来比绑定符长。`@` 绑定器本身排除出 v1：需要它的最常见模式（`u is User && u.age >= 18`）由原变量上的 `is` 精化覆盖，剩下的用途——解构的同时再绑定被移出的整体——有值得单独设计的仿射语义；延后增量。

**证据。** research/04 §4（穷尽调研与集合差集诊断）、§2.2（Kotlin 条目）、§6（Gleam 反面教材）。

**联动。** 账本第 8-10 行；旧 README 的 `.err`/`.ok` 打捞件作为非 match 处理路径住在旁边。

### F5 — 运算符：固定的 trait 驱动集合，冻结优先级

**约束。** 作者的约束「选中 Rust 的位置」（research/04 §10）；解释性（优先级必须一次学会、永久有效）；反优先级立场同样适用于运算符解析；溢出写法来自 B7(a)。

**获胜理由。** (a) 把固定 token 集映射到固定 trait——运算符调用即 trait 方法调用、可内联缓存，配一张冻结的 C 系优先级表在教程发布一次且永不扩展。`==` 是 B9 的结构化相等、永不接受用户重载；排序走 `Ord` derive。`+%`/`-%`/`*%` 族给哈希/PRNG 代码显式回绕；除零与移位宽度溢出陷入。

**落选理由。** (c) 自由重载加自定义运算符是 S3，让优先级变成声明局部，破坏 grep 能力与解释性预算——在上限之下标记很可能被拒。(b) 完全关闭重载恰在语言生长处受伤（BigInt、向量、小数要写成 `x.add(y)`），且数值塔日后可在同一 trait 接缝后扩展。(d) comptime 生成的按名算术是 F5(a) 未来的帮手，不是对手。

**证据。** research/04 §10（运算符调研）、§8（溢出表）；B7 的陷入策略。

**联动。** 账本第 21 行；`Deref` 式强转与用户表层一并排除。

### F6 — 字符串与字面量：显式边界的 Kotlin 插值

**约束。** 插值不得隐藏分配（章程的编译期错误口味延伸到成本可见性）；原始字符串、多行与 heredoc 应是一种构造；文本与线上协议工作需要 Char 与字节字面量。

**获胜理由。** (a) 是 research/04 §7 在除隐式字符串化外每一轴上的赢家——显式 `str()` 边界把那唯一一轴也补上（Roc 的规则）：`"${name.str().upper()}"` 把转换与其成本摆在明处。`$x` 裸标识符与 `${expr}` 表达式覆盖两种习惯；带哈希计数的 `r#"..."#` 原始字符串可嵌套任意深度、内嵌任意引号（Rust 证据；Go 反引号无法内嵌反引号；Zig 的 `\\` 行式最弱）；`'x'`/`b'x'` 对应 Rust 的 Char/字节对。

**落选理由。** (b) `\(x)` 与元组语法视觉相撞，每次插值多付两个字符。(c) 格式化函数占位符把插值挪出字面量进入调用，并招来格式规范迷你语言——除非检查否则就是 stringly-typed，与章程相悖。(d) 纯拼接是删除字面量可读性的 S0 选项。

**证据。** research/04 §7（调研、原始字符串对比、边界规则）。

**联动。** `str()` 是 05 点名的 Show 族投影；`T?` 值的插值仍要求显式处理——没有静默的「可选」打印。

### F7 — 语法糖预算：Balanced 档

**约束。** 章程要求 4：至多 Kotlin 的总语法糖面（按 research/04 §2 为 38 项特性 / 74-76 成本单位）；建议预算约 20 项 / 32 单位；账本必须覆盖 F1-F6 用到的每个构造。

**获胜理由。** Balanced（22 行 / 35 单位）覆盖定稿语法用到的每个构造，落在约为 Kotlin 特性数一半、加权表层 43% 的位置，仍留 16 项特性 / 40-42 单位余量——为延后增量队列（`|>`、record 语法糖、`@` 绑定器、vararg）刻意保留的储备。相对 research/04 §1 字面建议多出的两项来自把守卫、或模式、`.err`/`.ok` 各自单列一行；任意两项各共享一个教程段落，合并即回收字面预算。

**证据。** research/04 §2（上限与成本标尺）、§2.5（保留集与 Kotlin 对账表——第 4-8、27 项被集合类型整体删除）。

## G. 多态、元编程、模块、生态

### G1 — 元编程：comptime 求值加静态反射，不做宏

**约束。** 最小充分集（research/05 §4.3）：类型结构的静态反射、其上的编译期迭代/分支、普通代码的编译期求值、热点场景的内建 derive——Zig 演示前三项足以做任意 struct 的 JSON；调研中没有任何需求需要 token 改写；解释性预算（「一篇短教程完全讲清」）。

**获胜理由。** (b) 以元语言等于对象语言覆盖最小充分集：不存在替换，卫生性问题被结构性删除，这不是风格问题。C++26 P2996 的趋同（「反射，而非改写」）是业界抵达同一结论。内建 derive 叠加其上，热点场景一个词、编译快。

**落选理由。** (c) 卫生宏买到的是预算不付的语法糖，并把类型检查重实现进宏系统（Typed Racket 的负担）或把错误推迟到展开后 token（Rust 的）；有类型的成员生成——真正的 derive 需求——正是 Rust 的 derive 用 proc 宏而非 macro_rules 实现的原因。(d) proc 宏按构造不卫生，需要编译器即库的边界与独立构建步骤，并让「运行的是什么代码？」在不了解每个展开的情况下不可回答——可得的最大的解释性成本；宏生成的 impl 还可能重新打开 B6(a) 刚关上的不相交洞。(a) derive 之外不做把生态上限钉在编译器团队的发版日程上，把需求推给带着解析/再生成脆弱性的带外生成器。

**证据。** research/05 §4.1（光谱）、§4.2（卫生性代价具体化）、§4.3（最小充分集）、§1.8（C++26 P2996）。

**联动。** 分期：derive 先行、求值器 1.0 前补齐；G2(b) 是它的反射引擎。

### G2 — 一等类型：标签即数据之上的仅 comptime 反射

**约束。** 拆箱槽位基线（research/03 exec 6）禁止每槽位类型字；编译期错误优先；运行时类型问题应由数据本就携带的机制回答。

**获胜理由。** (b)+(d) 在阶段边界拆分问题：编译期类型问题交给反射（G1b 的引擎，零运行时成本）；运行时类型问题由 B1(c) 值本就携带的标签回答——`is` 与 match 即类型测试、即 IC 键、即穷尽检查对象，一套机制。在其上再加类型对象层只会用第二套更慢的机制复制标签系统。

**落选理由。** (a) 类型即值要么给每个槽位打标（与 exec 6 矛盾）要么只装箱动态路径（那它就是 (d) 加静态一半的 comptime）；Julia 自己的证据表明瓶颈从来不是分派而是推断失败（LU 案例研究），静态类型语言重新引入运行时类型值，等于重新引入它从未有过的类型不稳定悬崖。(c) 元数据表对每次分配收税、压迫统一装箱布局、并把反射错误移到运行时（Go 的 `reflect.DeepEqual` 经济学）。

**证据。** research/05 §4.3、§1.10、§2.4（Julia 分派研究 arXiv 1808.03370）、§6.2；research/03 exec 6。

**联动。** 存在类型仍以携带证据的 box（05 §8.1）供异构集合使用——唯一正当的装箱位置。

### H3 — 泛型执行：一份函数体、证据词、内联缓存、惰性 JIT 特化

**约束。** 反特化不变式，表述为裁决（research/05 §6.4、research/03 §8）：分派由类型与集合代数决定，从不由声明顺序或优先级决定；运行时可以缓存与特化任何本已唯一的分派。启动不得支付实例化扇出；泛型值不得装箱。

**获胜理由。** (a) 按构造满足不变式：运行哪些代码在任何缓存之前已定死（B6a 的唯一不相交实例），内联缓存是无正确性角色的性能提示（过期或冷缓存落回查找），JIT 的按类型特化表是 (b) 的表在划算的那一层惰性填充。静态可解的证据是常量操作数——多数调用点类型是静态的、无可查找；动态路径上不相交头保证按标签键控的 IC 无需打破平局。尾位置的泛型调用正常尾调用（证据词是普通寄存器参数）。

**落选理由。** (b) 字节码级单态化在首次调用每个新实例化时付物化暂停、字节码按实例化数增长、驱逐策略变成 VM 可见行为。(c) 擦除为泛型代码里的每个基本类型重新引入装箱——恰是 exec 6 要删除的 2-10 倍项——并在没有投机机制的情况下封顶 JIT。(d) comptime 单态化在加载时支付全部扇出、没有惰性层可修剪；在解释器里它是策略严格更差的 (b)。

**证据。** research/05 §6.1-6.4（两轴分解与裁决）、research/03 §8 与表 6（评分最高的行）、§2 第 1 项（IC 即提示）。

**联动。** 证据词调用约定；E1d 的处理器分派复用同一基底；变异性按集合包含，1.0 无 HKT/GAT（05 的变异性与 HKT 一节）。

### G3 — 模块系统：定义 < 文件 < 包 < 模块分层

**约束。** 作者的 Python 之痛（导入时执行、运行时才失败的循环、目录粒度可见性、`__init__` 样板——research/06 §1.7 的五机制分解）；对 `#include` 的厌恶（文本包含、无可评审 API 面）；热重载；启动；从脚本到包的零样板生长。

**获胜理由。** (b) 让模块体成为纯编译期声明——一条规则买三个设计：包内循环变成名字解析细节（交叉引用之痛解决）、热重载变安全（Erlang 模型不需要顶层副作用）、按依赖表惰性加载削减启动。同包文件共享一个命名空间、包内零导入语句；生成的 `.dsi` 是可评审的 API 差异（MoonBit 的 `.mbti` 实践：「.mbti 没变通常就是安全重构」）；`///|` 块给工具文件内更细粒度且是可选的——有无分隔符定义都顺序无关，无分隔符的文件就是一个块。跨包循环被禁止，因为环击溃按包的增量检查（第二个理由，research/06 §4.1）。

**落选理由。** (a) Rust 树可用，但付 `mod` 声明与 2018 版路径文法，并按包粒度失效——对脚本语言的 LSP 太粗。(c) Unison 废除纯文本，git/grep/patch/文本 LSP 都要经同步协议重造；其哈希思想被借进 G3.5 的内容寻址 dsmod，九成收益、零文化成本。(d) ESM 文件即模块需要 index 文件或 import map 才能成包（`__init__` 杂务重生）、需要外挂项目层做跨文件检查（tsconfig 处境）、并削弱热重载故事（按文件重新求值对照按版本换包槽）。

**证据。** research/06 §1.7（Python 五机制）、§1.9-1.11（MoonBit 模型、Inko 导入文法）、§4.1（增量性）、§6.3（启动杠杆）、G3.5（dsmod 契约）。

**联动。** G3.5 对所有选项生效；H6(b) 的存储缓存它的产物；五项工具承诺消费块模型。

### G4 — 可见性：带选择性导出的分层

**约束。** Python 的 `_` 约定之痛排除基于约定的答案；接口文件应是评审工件；包内循环让文件作用域可见性不成立（同包所有文件解析为一个命名空间，可见性附属于定义）。

**获胜理由。** (b) 给出三种拼写——默认私有、`pub(pkg)` 全包、`pub` 对依赖方并进 `.dsi`——加 Inko 式按符号选择/别名/条件导入与再导出。按定义的可见性让跨文件移动代码是重构中性的；内部包无需打开公共 API 即可表达；`.dsi` 差异本身就是门。

**落选理由。** (a) 二元 pub/priv 把「某一个兄弟包」与「全世界」混为一谈；中型库要么暴露内部要么过度发布。(c) 胶囊让每个可见性问题变成类型合一问题、以更高成本复制 E1c、并顶破语法糖上限。(d) Go 的大小写把 API 拼进标识符——重命名即 API 差异，且作者的口味已拒绝约定式私有。

**证据。** research/06 §1.9（`.mbti` 节）、§1.11（Inko `import mod (A, B as C)` 文法）、§1.3（Ada 概念祖先）。

**联动。** `.dsi` 兼任 LSP 悬浮源与增量边界；路径限定的 `pub(in ...)` 阶梯为留在上限之内被刻意排除。

### H5 — FFI 与嵌入：线性句柄作基底，平台叠加

**约束。** 「FFI 层是线性性挣饭吃的地方」（research/06 §5.1）：章程的线性层应把 C 资源纪律变成类型事实；Lua 与 Python C API 的教训——最小句柄足矣，指针加约定正是扩展 bug 的巢穴；嵌入要「两个嵌入者两台 VM」（设计上无 GIL）。

**获胜理由。** (a) 把约定变成类型错误：不透明外部资源是 `~Copyable` 句柄，双重释放无法通过编译，extern 借用是调用作用域的，回调跑在 VM 管理栈上，嵌入 API 是句柄表（`ds_push`/`ds_ref`，Lua registry 形态），`Value` 是对象表索引。(b) 把平台叠加为导出效应处理器的普通包——没有 Roc 巨石模型的嵌入、可按构建目标选择、`ds` CLI 自己就是默认平台。(c) 保留为有文档的逃生口（extern 声明就是 `ds bind` 在句柄包装前发出的东西）。

**落选理由。** (c) 作为策略丢弃线性层唯一独特买到的东西——「必须恰好释放一次」沦为 lint，嵌入 API 继承 Python 的约定泥潭。(d) wasm 优先约束值表示（带类型寄存器必须映射到 wasm GC 或装箱）并把原生 VM 从参考语义上降级；它是 (a) 的 tier-3 部署目标，不是 FFI 架构。

**证据。** research/06 §5.1-5.2（C API 对比表）、§5.4（平台反转拆解）、§5.3（WIT world）；08 已解决问题 1（pinning 规则）。

**联动。** C1(b)+C5(c) 在边界承重；dsmod 的 FFI-USED 标志在加载时声明 dlopen 需求。

### H6 — 生态：哈希存储内核加零配置脚本模式

**约束。** 作者的 UPM 文章（按包锁、输出哈希存储、FHS 链接、bin-first 构件）与 Nix 之痛（全局 `flake.lock` 破坏依赖方、无 FHS、内部无文档）；被喜爱的 bun 式脚本人体工学；LSP 优先的工具不是可选项。

## H. 运行时

### H1 — 执行管线：共享一套降级的三层

**约束。** 章程要求 1 与 3；research/03 的核心论断——动态 VM 的 JIT 大头是运行时类型/形状投机，静态类型无条件删掉约七成分层机制（§a.3、§b.3）；无去优化悬崖；脚本即时启动。

**获胜理由。** (a) 让一套 uop 集摊薄到所有层（BL-5：模板集与 uop 集一一对应），tier 2 copy-and-patch 因此是派生物件——不是第二个编译器（arXiv:2011.13127：比 LLVM -O0 快约 14%、编译速度快约百倍；CPython 以 PEP 744 落地）。层间转移是原位 J 变体操作码改写（LuaJIT 的 JFORL 技巧）；OSR 收敛为编译循环体，因而不存在栈帧变换机制。数据路径无守卫——四个残余出口是调试器、每函数入口的栈深比较、效应处理器入口（控制转移）与 B7a 的冷溢出边——这正是没有悬崖的原因。

**落选理由。** (b) 单方法 JIT 是已记录回退（若按架构模板 CI 矩阵主导维护成本），但背着 OSR 或认栽的债，并失去模板经济学。(c) 元追踪对静态语言是错误的交易：解释器本就是类型导向的，追踪把预算花在 tier-1 字节码已消灭的 AST 节点分派上；PyPy 的预热死区（0.2 秒内的脚本永不受益）与「内省会禁用 JIT」的语义恰落在调试器与热重载居住的地方；没有字节码工件意味着 BL-7 被堵死。(d) wasm-AOT 为主支付 E2b 纤程降级成本与值表示妥协；改为采纳为 tier 3 的部署模式。

**证据。** research/03 §a.3、§b.2-3（被删除子系统账本与去优化表）、§b.1（uop/模板/超级指令）、§d（管线 B+C+D 与排序段落）。

**联动。** BL-1 至 BL-7 作为固定输入；模板未验证的平台仅 ship tier 1（CPython 的按平台启用姿态）。

### H2 — 尾调用：第一天起保证，自身与互递归

**约束。** 章程要求 3 把保证 TCO 列为固定输入；逐语言证据表的规律干净——凡保证 TCO 的系统都掌握自己的调用约定（Lua、LuaJIT、Scheme、Koka、wasm 3.0 `return_call`），凡指望 JIT 日后做到的到 2026 年仍然没有（Ruby YJIT/ZJIT、V8 对照 ES6、CPython）。

**获胜理由。** (a) 是菜单上最便宜的保证：tier 1 中尾调用是参数滑动加栈帧复用（Lua 的 `luaD_pretailcall`、`CIST_TAIL`）；JIT 层中是标签循环（Koka 的 `kk__tailcall`）或槽位叠加 `jmp`（LuaJIT CALLT）。槽位叠加 ABI（被调方参数槽位覆盖调用方出参区，在栈帧布局时锁定）让成本为 O(args)、任意深度任意层都不增长栈，且确定。回溯经尾调用链元数据保持诚实（Lua 在完整 TCO 下仍支持 `debug.traceback`）；保证范围限定在同一效应上下文内，那里处理器入口物化一个栈帧（Koka 的一次性续延是这可接受的证据）。

**落选理由。** (b) 尽力而为让栈行为取决于编译调用方的是哪一层——恰在章程拒绝交易的领域引入不可预测，Ruby 的记录显示 JIT 团队一致把它排在后面。(c) 蹦床每次弹跳付一次间接调用加一次闭包分配，并把 Bounce 约定传染进每个尾递归签名；作为效应上下文边界的逃生口可以，作为机制不行。(d) 只做效应侧尾式恢复在 E1d（v1 无表层效应）之下退化为「完全没有 TCO」——直接违反要求 3。

**证据。** research/03 §b.5（机制证据与逐语言表）、§d（「要尽早锁定的两个设计决策」：槽位叠加 ABI 与 BL-7）。

**联动。** ABI 在分期中最先锁定；按纤程的保证成立（尾循环下段永不增长）；TAILCALL/RET 模板对按两字被调方入口描述符设计。

### H4 — 内存运行时：Perceus RC 加复用加 arena，收集器接口作增长路径

**约束。** 与 C4 同一基底（在那里裁决）；这里裁决的是运行时机制：分配器路径、停顿、环策略、各 JIT 层必须互操作什么；确定性 deinit 与裸指针字符串都依赖不移动的堆。

**获胜理由。** (a) 即 C4(a)+(d) 的运行时机制表述：逐帧 bump arena（分配一次加法、释放一次恢复，线性性逐点证明不逃逸所以可靠）加装箱值的 Perceus RC 与复用穿线（`kk_block_alloc_at` 无候选时落回约 15-25 周期的 mimalloc）。零停顿、零屏障、任何层无安全点或 GC 栈图；释放确定地喂给 deinit。诚实的记账一并写入：被移动的临时值百分之百住在寄存器/arena；装箱/共享残余继续付 RC，复用 pass 按优化器工作预算。(d) 的双钩子收集器接口（环候选注册、弱引用）现在就写进头部格式——共享环状工作负载的升级路径，永远不需要重新设计 VM。

**落选理由。** (b) 带代 GC 是唯一有停顿的选项、每层都要安全点与精确栈图、移动式收集器迫使 B8a 的一根裸指针字符串上 pinning 或句柄；Inko 的轨迹——上线 immix、发布移除文、然后把 GC 整个移除——是十年尺度的信号。(c) 纯 malloc/free 在闭包、持久化集合、续延与纤程栈上断裂——语言自己的核心工作负载；只作为 arena 底下的基底可行，而 (a) 已经是。

**证据。** research/03 §a.8、§b.4、§b.6；research/01 §B.8（Inko）、§B.2（Perceus/kklib）。

**联动。** 无环立场是诚实的 API 面（共享图需要显式收集器或 arena API）；纤程切换无需 arena 动作（每纤程自己的标记、按块链增长）。

## 已解决的开放问题 — 依据

**FFI pinning（问题 1）。** RC/arena 堆从不移动对象，pinning 归结为生存期：调用作用域的借用参数（二等、类型上不可逃逸）、持有指针作为 `~Copyable` 句柄、回调在 VM 栈上、阻塞调用钉住其纤程、需要与调度器并行时以载体线程逃生、取消只在 VM 重入点被观察故进行中的消耗绝不被打断。这是让 C2(d) 模式与 C5(c) deinit 跨边界保持可靠的最小规则集。

**nursery 形态与 token 集（问题 2）。** 块形态（`nursery { }` 加 `spawn { }`）让作用域退出即汇合点——词法结构就是 Trio 需要的全部语义；`with` 形态或尾 lambda 构建器会为同样的定界多付表层。token 按研究结论定稿（带 Zig 包含规则的后缀 `?`；惰性右操作数的 `or` 加提前退出形式；`is`；差集类型的 `.err`/`.ok`），因为 research/04 §11 的记账（整个 optional/错误故事三个 token）就是预算论证。

**`.err` 回退（问题 3）。** 选定 B1(c) 后无必要——回退分支只为纯名义类型内核而存在。

**纤程与隐式生成器（问题 4）。** 游标协议不需要纤程，让 v0 运行时更小；允许日后共享设施保留了选择权而不预付——无论哪种表层完全一致，所以这是纯调度决策。

**生成器箭头（问题 5）。** 公开生成器语法会把语法糖预算花在组合子已覆盖的唯一迭代形态上；「箭头编码类别」思想作为先例记录（04 F2），不会被静默丢失。

**带作用域具名实例（问题 6）。** 延后，因为 B6(a) 的解析尚无已知失败模式；预防性地加逃生口会为可能永不出现的问题花表层，且歧义即错误让任何未来语法糖保持诚实。

**不相交与终止（问题 7）。** 留给实现自定义但需求固定（链接期对最终环境检查；错误点名见证类型；拒绝满足自身的条件实例），因为算法选择不改变任何语言级语义——需求钉死了用户能观察到的一切。

**float 相等（问题 8）。** 按位结构的 `==` 保住自反性（字典键的承重性质），代价是默认拼写的 IEEE 意外；具名比较（`is_float_eq`、`is_approx_eq`）让 IEEE 可达而无需第二个运算符 token。跟随 Roc——调研中唯一正面迎上全体性问题的语言。

**v1 中的 comptime（问题 9）。** derive 每项一个词覆盖热点场景且无需求值器；求值器是真实的机制（要多调试一个执行阶段），所以在内核自我证明之后落地——两者都在 1.0 前，因为 G1(b) 是被采纳的机制，而「只做 derive」会是 G1(a) 的 v1 形态。

**`@` 绑定器（问题 10）。** 排除，因为 `is` 精化覆盖主导模式，剩下的仿射再绑定情形值得被设计的语义而非被继承的语义；日后作为 S1 增量，在预留余量之内。
