### Traits

#### `clone`

The clone derive's target: one member answering the shallow
duplicate; `#[derive(clone)]` synthesizes the impl. The primitives
carry clone themselves (the one-word atom answers itself, byte's
included), so the derived body is a construction over the borrowed
receiver whose Ref parts dup through the placement pass — a count
bump per reference, never a deep copy).

```ds
pub trait clone { fn clone(self) -> Self }
```

#### `hash`

The hash derive's target: hash stays consistent with universal
structural `==`, one member answering the content
hash; `#[derive(hash)]` synthesizes the impl. Every primitive part
carries hash itself: int and bool mix their own word, byte through
its decimal text (the atom sits outside the int conversion family),
string and char through the FNV-1a native over their bytes, and
float through the fold native (which normalizes -0.0 to +0.0 and
every NaN payload to the one canonical NaN, the bit-structural
equality the hash contract requires).

```ds
pub trait hash { fn hash(self) -> int }
```

#### `ord`

The ord derive's target: ordering is never structural, so one
member answers the field-order lexicographic
comparison; `#[derive(ord)]` synthesizes the impl. The primitives
carry ord themselves, each part's sort key an explicit compare
native: float through `total_compare` (the IEEE total order, the one
total comparison the trapping `<`/`>` cannot spell), and string,
char, and byte through their own compare natives (the UTF-8 byte
order, the Unicode scalar order, and the u8 order).

```ds
pub trait ord { fn compare(self, other: Self) -> int }
```

#### `show`

The show derive's target: one member answering the
construction spelling; `#[derive(show)]` synthesizes the impl.

```ds
pub trait show { fn show(self) -> string }
```

### Structs

#### `arena`

The read-side aliasing container: the library
shape for cyclic graphs, node trees, ECS, and cross-call cursors —
no language change. One opaque word behind one heap object on the
owning fiber's store, the payload a slot array of one element word
per handle with a per-slot generation counter: `insert` answers a
copyable handle (the index and generation packed into one int word,
so the handle keeps scalar provenance through every value position),
`remove` tombstones the slot onto the free list with the generation
bumping at the removal, and a stale handle — any copy taken before it
— traps deterministically instead of naming the reused element. Elements stage one word (a scalar or reference
word; a multi-word record or a deinit-carrying value refuses at the
insert's staging), and a reference element is a counted share: the
arena's store owns one edge count per element, released at the
remove or the arena's death. The hand-rolled handle-plus-table
alternative stays observable beside it — the bypass tax the
generational-reference trigger measures against this vocabulary.

```ds
pub struct arena[t] { }
```

#### `chan`

The bounded channel: the one
inter-fiber shared-state vocabulary — no lock, mutex or atomic ever
enters the language. One opaque word behind one heap object on the
creating fiber's store (the one owning heap): the word copies into a
spawned child's captures exactly a list word's, `send` deposits one
payload element — its whole word span at the buffer's element stride,
a scalar or reference word or a pure-word record, tuple, or union
member span — parking the sender on a full buffer, `recv` takes the
head parking the receiver on empty, and a payload crossing fibers
transfers one count per reference word through the claim ledger. A
deinit-carrying payload refuses at the send (the buffer's edge
retention owns counts, never claims), and a channel every fiber has
parked on is the honest deadlock: no sender, no answer.

```ds
pub struct chan[t] { }
```

#### `field`

The comptime reflection vocabulary: the one record `fields`
answers over declared data — a struct's fields and an enum's cases
share the (name, type, tag) triple. A field's record: its declared
name, its type as a type value, and its nominal tag name when its
type is a bare atom (empty for composite field types). A case's
record: its declared name, its payload as a type value (the case's
own minted atom, or none when the case constructs bare), and its own
constructor tag name. The two builtins run inside comptime functions
only; the checker refuses calls elsewhere.

```ds
pub struct field {
  name: string
  type: type
  tag: string
}
```

#### `file_handle`

The file face: the package-owned linear handle over the fsys
capability. `open_file` answers this type directly (its one inline word is
the handle), while `read_exact` and `close_file` are ds-source
handlers over the raw `read_raw`/`close_raw` externs — a native
call cannot borrow a deinit-carrying argument, so the handlers read
the fd word out and hand the raw seam an int. The deinit closes the
handle (a file binding dropped without an explicit close_file still ends
clean), and `close_raw` is idempotent because the deinit may fire on
a handle the owner already closed. The handle word is an opaque
table key, never the OS descriptor, and `read_exact` answers
`bytes | io_err` (the read's payload is one immutable byte string,
one counted block per read).

```ds
pub struct file_handle: ~Copyable { fd: int }
```

#### `net_handle`

The net face: the same shape over the net capability — the
package-owned linear handle whose one inline word is the connection
table's key. `net_connect` answers this type directly (the total
spelling, since the handle is deinit-carrying), while `send`,
`recv`, and `close_conn` are ds-source handlers over the raw
`net_send`/`net_recv`/`net_close` externs — a native call cannot
borrow a deinit-carrying argument, so the handlers read the id word
out and hand the raw seams an int, the fallible reads answering the
`net_err` union. The deinit closes the connection
(a binding dropped without an explicit close_conn still ends clean),
and `net_close` is idempotent because the deinit may fire on a
handle the owner already closed. The handle word is an opaque table
key, never the OS descriptor.

```ds
pub struct net_handle: ~Copyable { conn: int }
```

#### `net_listener`

The net face's server half: the same
discipline as the connection half over the package-owned linear
`net_listener`, whose one inline word is the listener table's key.
`net_listen` answers this type directly — the total spelling for
`net_connect`'s own reason (the handle is deinit-carrying, so a union
member holding it refuses), so a failed bind prints the net error
line and halts — and `accept` is a ds-source handler over the raw
`net_accept` extern, reading the id word out the way `send`/`recv`
do (a native call cannot borrow a deinit-carrying argument) and
answering the connection half's own `net_handle`: the accepted
connection registers like a connecting one, so it owns that face in
full. `accept` keeps the total spelling for the same reason, so a
failed accept (the configured wait's bound expiring with no pending
connection among its classes) halts on the net error line too; a
non-halting accept needs a union member holding a deinit-carrying
handle, which the checker refuses (an open author question). The deinit
closes the listener (a binding dropped without an explicit
close_listener still ends clean), and `net_listener_close` is
idempotent because the deinit may fire on a handle the owner already
closed. `local_addr` answers the bound address, the port-0 bind's
report (the face's one address op, total over the live handle).

```ds
pub struct net_listener: ~Copyable { lid: int }
```

#### `proc_handle`

The process face's capture half: the same discipline as the other
handle faces over the package-owned linear `proc_handle`, whose one
inline word is the process table's key. `proc_spawn` answers this
type directly — the total spelling for the same reason every
deinit-carrying handle keeps it (a union member holding one
refuses), so a failed spawn prints the io error line and halts —
and the child's standard input, output, and error ride pipes, so
`write` hands the child input (the pipe staying open across calls
until `close_in` ends it) while `read_out` takes its captured
output and `read_err` its captured diagnostics, one read of at most
the requested bytes each, the empty string the pipe's orderly end.
`close_in` is the stdin-close seam — the child's end-of-input while
the handle stays live, total and idempotent like the close it
narrows. `wait` answers the child's exit status (a child ended
without a status code answering -1, `proc_run`'s convention) and
answers it idempotently, `try_wait` the non-blocking poll over the
same reaped word (the none member while the child runs), and the
deinit closes the handle: a still-running child is killed and
reaped, so a dropped binding never leaks a child, and `proc_close`
is idempotent because the deinit may fire on a handle the owner
already closed. The blocking rows block the calling fiber like
`proc_run`'s own wait. The handlers read the id word out the way
`send`/`recv` do (a native call cannot borrow a deinit-carrying
argument), and the fallible rows answer the io_err union, binding
their answer before returning it the same way (a tail call to a
fallible native refuses).

```ds
pub struct proc_handle: ~Copyable { id: int }
```

#### `json`

The json value family, the typed face over the JSON grammar: one case
per grammar shape, the number split kept faithful (a token with a
decimal point or an exponent, or an integer literal past the int
range, answers json_float — an in-range integer literal answers
json_int, and the two never narrow into each other). The type stays
pinned at this declaration position (its case atoms mint here, and
the compile seams address ambient mint order positionally); the
parser, serializer, and typed readers live in the @std json face's
own source (std/json.ds), composed after this core.

```ds
pub enum json {
  json_null
  json_bool { value: bool }
  json_int { value: int }
  json_float { value: float }
  json_string { value: string }
  json_array { items: list[json] }
  json_object { fields: map[string, json] }
}
```

#### `args`

The process face (the CLI process surface): `args`
answers the process arguments the host staged (`ds run`'s `--args`
words) as a list of strings, `env` reads one process environment
variable into the checked none member when unset, and `proc_run`
spawns one child over the argument list — inheriting the standard
streams — and answers its exit status, a spawn failure riding the
io_err union and a child ended without a status code answering -1.
`exit(code)` ends the process with a deliberate status — the proc
capability's own op row, so a host refusing the capability refuses
the spelling. The engine prints nothing and decides no exit code (the
installing host owns what the status means), the call never answers,
and the return generic answers whatever the call site expects,
`panic`'s own shape.
