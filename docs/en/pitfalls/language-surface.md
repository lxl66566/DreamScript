# Language-surface spellings

- A declared field name may be a keyword (`field_member` parses `field_name`, the access-side rule), since the reflection record's `type` member needs it; the declaration side must agree or the record struct cannot be spelled.
- The builtin `type` atom lives in every universe beside `none`, so fixture universes and bitset models account for it and mint-order pins shift by one; a `type`-annotated parameter outside the comptime mode refuses (DS2030).
- The type-value reading of a name is expectation-driven and comptime-gated: a type name where a `type` is expected answers the builtin atom only inside a comptime fn's body or a comptime call's arguments (DS2032 otherwise), while with no such expectation it keeps its constructor reading; a guard keyed on the resolution record alone types every bare type name as a value.
- The reflection builtins are wired by name (`fields`, `type_name`, H5.5's admission criterion) and answer only inside comptime functions: redeclaring either name in the ambient's namespace is the duplicate error.
- A comptime parameter's scalar annotation is admitted by name (int, float, bool, string) at the declaration gate and staged by the annotation's shape at the call, so a parenthesized literal, a holed string, a suffixed number, or an omitted defaulted parameter refuses only at the evaluator's staging: a checker-side relaxation moves that refusal with it.
- A trait or impl member declares its receiver as its first parameter (`self`/`mut self`, typed `Self`) unless it is a receiverless inherent member: DS2021 refuses only trait members, while a receiverless inherent member is the static surface called through its type name. The bare-type-name receiver is tiered: the type's own impl member claims it, a tag or case name naming none of its own type's members keeps its constructor-value reading, and any other type names its members alone.
- Adding a `DotRes` variant fans out beyond ds-check's resolver and `type_of`: effects and linearity route the record's edges, and the lowerer's PairWalk, callee_demands, Field-callee arm, and `is_tail_callee` each need their match, with ds-lsp's goto-definition walking it; a missed arm panics at the first e2e.
- A payloaded enum case named `none` claims no atom of its own (`none` is the predeclared unit atom, B4), so construction refuses at the call-form seam (DS2022); a construction-site lookup that would fall back to `empty` refuses instead of typing the binding empty.
- A trait impl member carries no parameter defaults of its own: a re-declared trait default refuses (DS2019) and an impl-only default refuses (DS2020), since the trait member's registered signature is the only default source call sites stage and an impl-only default would stay inert.
- A trait impl's body presence is invisible to call sites, so a member with neither an impl body nor a trait default would check clean and trap only at the dispatch seam: completeness refuses at the impl's own door (DS2023).
- A member signature's generic parameter binds freely to any argument unless the dispatch's substitution binds it first: the member call check solves the trait's generics through the solved instance, so before that binding a mistyped argument checked clean and trapped at the nested dispatch's ABI slide.
- A lambda literal's own arity must match the expected fn type's exactly, over every expectation source (a direct call's parameter, a solved generic's fn-typed parameter, the trailing block's slot), since the call ABI stages the declared parameter count and a zero-parameter block over a `fn(t) -> r` parameter would trap at the hosted per-element arity validation (DS2007).
- An un-annotated `.err` handler under no contextual expectation consumes the whole union (an empty-use cascade), so fallback sites annotate the handler parameter (`(e: net_err) => ...`).
- The extraction family's `ok_or` keys its member entry on the payload side's single atom, so an optional whose payload spans several atoms (`json_member`'s `json | none`) refuses at lowering while `unwrap_or` over the same optional runs (the fallback names one member); a json decode none-tests the member optional first and lets the scalar reader carry the failure.
- The early-exit decode vocabulary is the statement narrow: bind the union, `if x is parse_err { return parse_err }` as a statement, then read the narrowed binder. A `return` in a value-consumed position (an if/match arm answering a join, a bare block initializer, an argument slot) refuses at the checker (DS2039), and a `?` whose kept set is a struct or tuple member refuses at lowering — the kept set extracts a word member's payload in place — so both spellings name this narrow as the alternative.
- `let x = e?` over a fully-contained union reports DS2002 by design, because `expected = none` propagates every member so nothing binds; the honest spellings are `return e?` and the final expression.
- Destructured const binders alias a `var`'s words, so a reassignment through the var is observable through the binders.
- The guard quirk's parenthesization is whole-expression: `x > (m)` before `=>` still steals `(m) =>` as a paren-parameter lambda, so only `if (x > m) =>` parses; DS1016 suggests whole-expression parens while the paren-tail shapes keep the generic error.
- A dot-call's free tier owns the name unconditionally: `x.f()` feeds the free function named `f` before any member candidate, so an inherent member sharing a free function's name never serves a value receiver (`m.len()` answers the free `len`'s one body, whose instance table covers string/list/bytes and refuses a map receiver at lowering), and the type-keyed member tier is the answer only for names the flat value namespace does not already serve.
- A method call's effect row unions every registered candidate's row, so one trait-member body carrying a trapping op stamps `trap` onto every dispatch of that member name in every session: the ambient's `impl show for bytes` builds its byte-list rendering through the `concat` extern and a for-in walk because string `+` and `+=` ride B7's trapping Add/assign rows (a REPL effect line flipped from `world` to `trap | world` the moment a `+`-based draft joined the candidate set).
- A union value crossing modules carries its producing module's tag id, so the linked module's own tag-table rows ride the import surface and seed the consuming compile's table at lowering (before any body mints): the ambient splice already seeds the ambient rows identically in every module (which is why `int?` always narrowed correctly), and the seed extends the same discipline to linked user atoms — it keys only names the consuming compile minted from the linked facts' own installs, drops every other row (a name resolving to a local atom crosses never, because the linked signature naming it refused at the walk), and refuses when two linked modules claim one id (their code immediates are frozen in their artifacts, so no remap exists; the shared mapping round's multi-module id assignment owns that).
