# Language-surface spellings

- A trait or impl member's signature declares its receiver as its first parameter (`self`/`mut self`, typed `Self`) unless it is a receiverless inherent member: DS2021 refuses only trait members, while an inherent member with no receiver is the static surface called through its type name. The bare-type-name receiver position is tiered: the type's own impl member with that name claims it (the value form refuses pointing at the receiver form), a tag or case name naming none of its own type's members keeps its constructor-value reading (the trait dispatch, the free-function UFCS feed, the handlers), and any other type names its members alone, so the checker's static path must own the receiver whenever the receiver has no value reading — a guard keyed on the resolver's record alone types the struct name as a value and cascades a second diagnostic beside the missing-member report.
- Adding a `DotRes` variant fans out beyond ds-check's resolver and `type_of`: effects and linearity route the new record's edges, the lowerer's PairWalk, callee_demands, the Field-callee emission arm, and `is_tail_callee` each need their match, and ds-lsp's goto-definition walks it — a missed arm panics on the unreachable match at the first e2e, not at check time.
- A payloaded enum case named `none` claims no atom of its own (`none` is the predeclared unit atom, B4), so construction refuses at the call-form seam (DS2022); the silent empty fallback it used to take typed the binding empty and surfaced as nonsense match diagnostics downstream. A construction-site lookup that would fall back to `empty` refuses there instead.
- A trait impl member carries no parameter defaults of its own: a re-declared trait default refuses (DS2019) and an impl-only default refuses (DS2020), because the trait member's registered signature is the only default source call sites stage, so an accepted impl-only default would stay inert (an omitted argument keeps its missing-argument refusal).
- A trait impl's body presence is invisible to call sites, so a member with neither an impl body nor a trait default body would check clean at every call and trap only at the dispatch seam: completeness refuses at the impl's own door (DS2023), the bodiless spelled member at its span and the omitted member at the impl's trait reference. A defaulted member stays omittable.
- A member signature's generic parameter binds freely to any argument unless the dispatch's substitution binds it first: the member call check solves the trait's generics through the solved instance (the impl's trait-reference arguments rewritten against the receiver — a covered union receiver or an argument still naming an unbound variable leaves the generic free, exactly as an impl spelling no arguments does), so before that binding a mistyped argument checked clean and trapped at the nested dispatch's ABI slide instead.
- A lambda literal's own arity must match the expected fn type's exactly, over every expectation source (a direct call's parameter, a generic call's solved fn-typed parameter, the trailing block's sugar-fed slot): the call ABI stages the declared parameter count, so a zero-parameter block over a `fn(t) -> r` parameter would trap at the hosted per-element arity validation. The refusal names the callee's written fn type as its second span (DS2007).
- An un-annotated `.err` handler under no contextual expectation consumes the whole union (an empty-use cascade), so fallback sites annotate the handler parameter (`(e: net_err) => ...`).
- `let x = e?` over a fully-contained union reports DS2002 by design, because `expected = none` propagates every member so nothing binds; the honest spellings are `return e?` and the final expression.
- Destructured const binders alias a `var`'s words, so a reassignment through the var is observable through the binders.
- The guard quirk's parenthesization is whole-expression: `x > (m)` before `=>` still steals `(m) =>` as a paren-parameter lambda, so only `if (x > m) =>` parses and a one-name guard (`if m =>`) has no parenthesizable form; DS1016 suggests whole-expression parens while the paren-tail shapes keep the generic error.
