# Front end: scanner, grammar, diagnostics, package format

- The grammar's stack segment belongs to the caller thread, not the parse: a worker thread cached in a thread-local serves one job per parse, because a scoped spawn per parse costs a thread creation (73 us against a ~1.6 us job round trip on the probe host). A job carries its own source copy because the worker outlives the caller's borrow, and an inline fast path for small nesting would break the small-caller-stack contract, since nothing portable reports the remaining stack.
- Never join the grammar worker from a thread-local destructor: joining there aborts every process at exit (status 127) until the drop only dropped the sender.
- Pin union-member render order in goldens from live output: diagnostics follow tag allocation order, not source order.
- Multi-statement one-line blocks are parse errors; write block statements on separate lines.
- Assert on OS error text only through locale-independent facts (the operation plus target prefix, `(os error N)`), never English substrings.
- Checker expression-error poison is subtree-scoped, so a poisoned initializer bound to a name still prints one follow-on at a new use site; threading the poison through `Binding` doubles the state surface.
- Keep inline `.ds` sources inside Rust string literals on one line and let rustfmt pick the break: rustfmt re-wraps literals itself, and a hand-written backslash continuation swallows the next line's indentation, so a split `fn main() \` plus `() -> int` parses as a two-slot param list.
- `ds_mod::Function` stores the wire words and `code()` is the on-disk form: a decode is validation, never storage, and the reader's single decode pass owns the load path's only jump-bound check.
- `loader::install` consumes the module and takes every body over through `Module::into_functions`/`Function::into_parts` (no per-word copy), so a failed install has already eaten the record — a caller retrying after a refusal (the platform-seam probes) rebuilds the module first; the writer and the corpus tests keep the borrowing `code()`/`functions()` accessors.
- New dsmod payload fields go inside the encoders only: the writer runs each encoder twice (a sizing counter, then into the presized buffer), and the per-section start/end `debug_assert_eq!` holds the two passes byte-identical; a field written outside an encoder desynchronises the directory silently.
- The entry descriptor's word 0 is the function-table index for the descriptor's life, so a loader tripwire comparing it against a resolved index belongs in a debug assertion, never the per-call path; word 1 (`tier2_code`) must never be compared against a table index, since tier 2 fills it with a code pointer.
- `Decls`' dense-id tables are `IdTable`s whose public surface mirrors the map's (`get`/`contains_key` take `&K`, iteration yields `(&K, &V)` pairs), which let `ds-lower` compile unchanged. Insert grows the table to the key's own slot, so a key minted after the declaration pass reads as absent instead of as a neighbour's value.
- A per-definition query slice must read the package pass's fact index; re-running a span containment scan over the package restores the O(D^2) it replaced. The index answers a fact to the last block starting at or before it, only when that block also ends at or after it, so a fact spanning two blocks belongs to neither.
- A hash-map type in a public field is a cross-crate compile unit of its own: the checker's switch to `FxHashMap` broke the query crate's `CheckedPackageOutput` at merge time while each lane was green alone, so announce a public table type change to the consuming lane or wrap the field behind an accessor.
- A REPL session cannot ride the script-mode fold: the fold fixes its synthesized `main` at `-> ()` (a tail expression value would be a type error) and a written `main` cannot coexist with top-level statements, so the REPL owns `fn main` and appends statement submissions inside it — the consequence is one churning block per statement (checking is session-length per submission) and full re-execution per submission (side effects repeat; nothing is alive between runs, so every binding's deinit fires at each run's scope exit and `:drop` is textual removal); a failing or trapping line is never committed, but a `:drop` that leaves later referencing lines behind breaks the session text until `:reset`.
