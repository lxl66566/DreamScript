# Front end: scanner, grammar, diagnostics, package format

- Visibility is file-grain (G4): a definition belongs to its defining file alone, so every multi-file fixture and ambient stub needs `pub` on what another file uses (the stdlib ambient is all `pub`); a private stub fails the items it serves with DS4017.
- An impl's trait reference resolves through the type namespace, never the value-first bare-use walk: a free `fn show` once claimed `impl show for int`'s head and the visibility check read the wrong def. Type-position sites use the type tier.
- An LSP client position never converts to a registry line by hand: the client's line is a raw u32 (u32::MAX included) against 1-based registry lines, so use `ds-lsp`'s `convert::offset`, whose clamp folds a past-EOF position onto the last line; a hand conversion overflows and `Files::line_span`'s assert kills the session.
- An LSP test document URI must spell a host-real path (`Url::from_file_path` over a temp path): `Url::to_file_path` refuses a Unix spelling on Windows, so the open is refused with no publish and the harness waits out its budget as if the server deadlocked.
- The grammar's stack segment belongs to the caller thread, so a thread-local worker serves one job per parse (a scoped spawn costs 73 us against a ~1.6 us job round trip) and a job carries its own source copy; an inline fast path for small nesting would break the small-caller-stack contract.
- Never join the grammar worker from a thread-local destructor: joining there aborts every process at exit (status 127).
- An attribute class the derive expansion owns must be named by the per-tree expansion gate (`has_expansion`), or a tree carrying only that attribute passes unexpanded and drops the refusal; the parse layer owns the case-attribute vocabulary (`#[default]` alone), so any other attribute on a case is a syntax error.
- Keep inline `.ds` sources inside Rust string literals on one line and let rustfmt break them: a hand-written backslash continuation swallows the next line's indentation, so a split `fn main() \` plus `() -> int` parses as a two-slot param list.
- `ds_mod::Function` stores the wire words and `code()` is the on-disk form: a decode is validation, never storage, and the reader's decode pass owns the load path's jump-bound check.
- `loader::install` consumes the module, so a failed install has already eaten the record and a caller retrying after a refusal rebuilds it; the writer and the corpus tests keep the borrowing `code()`/`functions()` accessors.
- New dsmod payload fields go inside the encoders only: the writer runs each encoder twice (sizing counter, then the presized buffer) and the per-section `debug_assert_eq!` holds the passes byte-identical; a field written outside an encoder desynchronises the directory silently.
- The entry descriptor's word 0 is the function-table index for the descriptor's life, so a loader tripwire comparing it against a resolved index belongs in a debug assertion; word 1 (`tier2_code`) holds a code pointer at tier 2, never a table index.
- `Decls`' dense-id tables mirror the map's surface (`get`/`contains_key` take `&K`, iteration yields pairs) so `ds-lower` compiled unchanged; insert grows to the key's own slot, so a key minted later reads as absent, not as a neighbour's value.
- A per-definition query slice reads the package pass's fact index instead of re-running a span containment scan (O(D^2)); the index answers a fact to the last block starting at or before it only when that block also ends at or after it, so a fact spanning two blocks belongs to neither.
- A hash-map type in a public field is a cross-crate compile unit of its own (the checker's `FxHashMap` switch broke the query crate's `CheckedPackageOutput` at merge while each lane was green), so announce it or wrap the field behind an accessor.
- An implicit dispatch site (an interpolation hole's `show`) carries no resolved name, so resolution-keyed passes read the checker's span-keyed `Checked::hole_show_dispatches` (the effects walk, the lowerer's implicit-call and demand walk, the affine receiver mode); re-deriving from resolutions misses the hole.
- A REPL session cannot ride the script-mode fold (the fold fixes its `main` at `-> ()`, and a written `main` cannot coexist with top-level statements), so the REPL owns `fn main` and appends submissions inside it: checking is session-length per submission, and a `:drop` leaving later references behind breaks the session text until `:reset`.
- The precompiled ambient blob (`crates/ds-stdlib/src/ambient.ast`) addresses the file id it was generated under, so a later registration loses the hit and pays a fresh parse; `ambient_blob_matches_a_fresh_parse` fails on a grammar or conversion change until `cargo run -p ds-stdlib --example gen-ambient` regenerates it.
- The checked-ambient `.dsi`'s universe logs are captured at the declaration-phase boundary, never from a finished analyze, since the body pass keeps minting atoms and sets and a late log shifts every later id. Def-named atoms replay before the reserve pass and shape-phase mints only between reserve and shape, or a pre-minted `$t#N` surfaces as a bogus `impl head does not name atoms`. A mint log row carries its generation id, and the merged run's landing remap rewrites only the served data's generation-space references (the struct and enum-case field signatures, the replayed sets); the replay's own products — the minted atoms' kinds and the hash-cons maps — already carry landing ids, and re-mapping them folds one landing onto another (the list application answering as the map application beside it).
- A served instance head or condition naming a trait-relative set (`TypeExpr::Trait`/`Not`) could re-solve wider once a user impl lands, so the coherence skip refuses such a prefix and the closure pass keeps probing every pair and cycle a fresh row takes part in; the effects serve also seeds the ambient's solved method rows.
- A stack overflow aborts the process with no unwind, so the parse worker's `catch_unwind` contains parser panics only: every recursion class the grammar can drive without a bracket is refused by the lexscan pre-scan, and a depth-budget test that aborts the runner is a budget bug. Pest backtracks a near-legal prefix's full depth, so the budget binds illegal prefixes too; Pest 2.9's native guard is target-gated and best-effort.
- The unbracketed operator chain right-recurses per term like the arrow and else classes but is guarded after the grammar, at conversion (`MAX_CHAIN_TERMS`): pest's stack backstop holds the descent on default native targets, so the fold guard alone is load-bearing there.
- An import surface keys by the import declaration's whole span, and its link position is the dep-list writer's own first-occurrence index over the same trees: keying by the path's span leaves every surface unlinked with selections silently declarative, and a position walk differing from `dep_list`'s points a linked FuncRef at the wrong dep slot. `import_link_name` feeds the writer, the positions map, and the surface builder.
- A frozen corpus file's `stage: typecheck` items pin the ambient's name choices: an ambient redeclare in the same namespace is a DS2005 landing in the item and turns run-item noise into an exit-1 gate failure, so name ambient declarations apart from every corpus declaration.
- The @std dsmod splice installs function records and member-tag rows (the rows an ambient body's union answer mints, seeded into the merged lowering's tag table and validated against the plan), so an artifact without rows or with a row the plan does not mint is a `ServedDrift` refusal; a tag row's ids must stay unique (a duplicate id fails the validating decode before the serve).
- The store serves the lowest installed identity for a `(name, version)` self-described at two identities (the provider's drift rule), so a dev-loop repin test ships the dep edit as a version bump: a same-version repin leaves two identities under one pair and resolution's pin validation refuses whenever the pin names the one the store's order does not serve.
