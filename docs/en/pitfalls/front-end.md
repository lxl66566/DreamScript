# Front end: scanner, grammar, diagnostics, package format

- Visibility is file-grain (G4): every multi-file fixture and ambient stub needs `pub` on what another file uses, or the items it serves fail with DS4017.
- An impl's trait reference resolves through the type namespace, never the value-first bare-use walk: a free `fn` sharing the trait's name once claimed `impl show for int`'s head and the visibility check read the wrong def.
- Client positions convert through `ds-lsp`'s `convert::offset`, never by hand: a hand conversion overflows and `Files::line_span`'s assert kills the session.
- An LSP test document URI must spell a host-real path (`Url::from_file_path` over a temp path), or `Url::to_file_path`'s refusal on Windows leaves the harness waiting out its budget as if the server deadlocked.
- The grammar's stack segment belongs to the caller thread, so a thread-local worker serves one job per parse and each job carries its own source copy; an inline fast path for small nesting breaks that contract.
- Never join the grammar worker from a thread-local destructor: joining there aborts every process at exit (status 127).
- An attribute class the derive expansion owns must be named by the per-tree expansion gate (`has_expansion`), or a tree carrying only that attribute passes unexpanded and drops the refusal. The case-attribute vocabulary is `#[default]` alone; any other attribute on a case is a syntax error.
- Keep inline `.ds` sources inside Rust string literals on one line: a hand-written backslash continuation swallows the next line's indentation, so a split signature parses as a two-slot param list.
- `ds_mod::Function` stores the wire words and `code()` is the on-disk form, so a decode is validation and never storage, and the reader's decode pass owns the load path's jump-bound check.
- `loader::install` consumes the module, so a caller retrying after a refusal rebuilds it; the writer and the corpus tests keep the borrowing `code()`/`functions()` accessors.
- New dsmod payload fields go inside the encoders only: the writer runs each encoder twice and asserts the passes byte-identical, so a field written outside one desynchronises the directory silently.
- A per-definition query slice reads the package pass's fact index, since the span containment scan is O(D^2); the index answers a fact to the last block starting at or before it only when that block also ends at or after it.
- A hash-map type in a public field is a cross-crate compile unit of its own (the checker's `FxHashMap` switch broke the query crate's `CheckedPackageOutput` at merge while each lane was green), so announce it or wrap the field behind an accessor.
- An implicit dispatch site (an interpolation hole's `show`) carries no resolved name, so resolution-keyed passes read the checker's span-keyed `Checked::hole_show_dispatches`; re-deriving from resolutions misses the hole.
- A REPL session cannot ride the script-mode fold, so the REPL owns `fn main` and appends submissions inside it; a `:drop` leaving later references behind breaks the session text until `:reset`.
- The precompiled ambient blob (`crates/ds-stdlib/src/ambient.ast`) addresses the file id it was generated under, so `ambient_blob_matches_a_fresh_parse` fails on a grammar or conversion change until `cargo run -p ds-stdlib --example gen-ambient` regenerates it.
- The checked-ambient `.dsi`'s universe logs are captured at the declaration-phase boundary, never from a finished analyze, since later mints shift every id; a pre-minted `$t#N` surfaces as a bogus `impl head does not name atoms`. The landing remap rewrites only the served data's generation-space references, since the replay's own products already carry landing ids and re-mapping them folds one landing onto another.
- A served instance head or condition naming a trait-relative set (`TypeExpr::Trait`/`Not`) could re-solve wider once a user impl lands, so the coherence skip refuses such a prefix and the closure pass keeps probing every pair and cycle a fresh row takes part in.
- A stack overflow aborts the process with no unwind, so `catch_unwind` around the parse worker contains parser panics only: every bracket-free recursion class is refused by the lexscan pre-scan instead, and a depth-budget test that aborts the runner is a budget bug. Pest backtracks a near-legal prefix's full depth, so the budget binds illegal prefixes too; the unbracketed operator chain right-recurses per term and is guarded after the grammar at conversion (`MAX_CHAIN_TERMS`).
- An import surface keys by the import declaration's whole span, and its link position is the dep-list writer's own first-occurrence index over the same trees: a position walk differing from `dep_list`'s points a linked FuncRef at the wrong dep slot.
- A frozen corpus file's `stage: typecheck` items pin the ambient's name choices, so name ambient declarations apart from every corpus declaration: a redeclare in the same namespace lands in the item as DS2005 and turns run-item noise into an exit-1 gate failure.
- The @std dsmod splice installs function records and member-tag rows seeded into the merged lowering's tag table and validated against the plan, so an artifact without rows, or with a row the plan does not mint, is a `ServedDrift` refusal.
- The store serves the lowest installed identity for a `(name, version)` self-described at two identities, so a dev-loop repin test ships the dep edit as a version bump: a same-version repin leaves two identities under one pair and resolution's pin validation refuses.
- A query slicing another query's substrate keeps its own identity anchor on the expansion (the `package_linearity` spell): the holder's renewal identity covers its derived payloads, never the substrate's span-keyed side tables, so `analyzed` depending on the checked package alone would serve stale spans through green renewals — the anchor's forced recompute is what slices a fresh bundle every time the trees can move.
