# Runtime: native seam, reentry, memory facts

- Arena grants are raw pointers (a restore frees its range for the next allocation), so the aliasing contract — a restore kills every grant it freed, only the latest grant live — sits on the caller, kept honest by the miri leg over `cargo miri test -p ds-rt`.
- A reference outliving its deriving call (the `&Arena` in a `RestoreOnDrop` guard, any held `&Heap` state) must not materialize through the `UnsafeCell`'s unique re-tag: that tag inherits the `&mut Inner` retag, so a later `inner()` call invalidates it, which miri flags in the guard's drop. Derive such references straight from the cell contents (`&*ptr::addr_of!((*cell.get()).field)`) so they keep the cell's shared tag.
- The ds-ffi export reader's never-panic contract is 64-bit-only: its `usize::try_from` narrowing and unchecked `usize` arithmetic over untrusted ELF/PE fields hold on windows-msvc and linux x86_64/aarch64 alone, so a 32-bit port audits every expect and addition first (`crates/ds-ffi/src/exports.rs`).
- Install natives and the platform before `loader::install` (pool FuncRefs validate at install time), and note `Vm::with_limit` installs only the builtin core, so both CLI run paths call `provide_platform`.
- A world call addresses the source's `platform "..."` name (default `std`): a host installing none under it, or one not serving the site's op capability, fails the install as `UnprovidedPlatformOp`.
- The bound-artifact tier installs before the module, since pool `Constant::Bound` validation reads the registry's bound tables; a refused load leaves the artifact uninstalled, and a declared artifact nothing binds loads nothing, so garbage or foreign-triple bytes staying runnable pins that laziness.
- The fork-join workers' code snapshot strips the bound tier beside the platforms, so a foreign call in a pooled child answers the unresolved-callee trap; bound modules to workers need a `Send + Sync` story for the loader handle.
- `loader::install` bakes pre-resolved ids through `ModuleRegistry::id_for_install` (an installed name's id, else the `id_names` tail the first install assigns), so renumbering or reusing ids misroutes every callee word and deinit hook.
- Reserve ids from both ends and never renumber an op table: unions allocate upward from 0, the platform reserves the u8 top downward (IO_OK 255 through NONE 251), the builtin core keeps its 0-48 run, and pool FuncRefs name positions.
- A new pure builtin lands in four places or source calls silently stay dead: the VM's native table (index, body, drift pins), the ambient declaration, the regenerated artifacts (`gen-ambient`, `gen-ambient-dsi`, `gen-ambient-dsmod` — all three write clean over bodiless externs), and ds-lower's native mirror — the mirror routes calls by name alone, so its absence surfaces only when a source call refuses as an extern non-builtin outside the contract, never at a gate over the ambient itself.
- Fallible natives: the two-word platform span re-spans into the call's failure union over the success-typed ambient, a failure prints `io|net error: <msg>` and halts, and CALLT-to-fallible is Unsupported.
- The net failure classes answer two discriminants paired with the `net_err` case the ambient names (`timeout`/`refused`), so a call-site union spelling them differently refuses at lowering.
- A teardown door can fire while another live fiber is current: the takeover parks that fiber's context and must re-adopt it after the pass, or the caller continues on stale scratch (`crates/ds-vm/tests/teardown_deinit.rs`).
- Every native call opens one borrow window in the placement pass before its operand evaluation and pops it at the flush, so a death firing inside defers to that flush; every `native_done` pairs with exactly one window.
- Hosted calls (`Vm::call_hosted`, from generic builtin bodies holding `&mut Vm`) inc each Ref argument, since the callee's placement owns its parameters. A boundary drive answers `DriveOutcome::Frame` keyed on the sentinel reentry frame (u32::MAX return pc), precise across fiber switches; a yield or HALT escaping it is `ReentrancyRefused`, and only the root frame's native tail may CALLT with abandoned counts.
- The spawn seam's two closure forms stage separately: a `spawn {}` block's child parameters are the captures, while a fork-join closure's captures stage past its element parameters into the frame's leading local slots; evidence crosses a lambda frame the same way.
- The fork-join completion delivery must acquire the receiving fiber's claim row, one per `Ref` word of the answer span, before the joiner's dec: `Heaps::dec`'s exact-ownership gate releases a foreign word only through the dec'ing fiber's row, so a rowless dec strands the count on the dead child's heap.
- A count mutation from a dead-context drive routes through the pool, its copy-in helpers following `ctx_live`; a hardcoded live-context assumption reads a just-died child's word as `UnknownObject`.
- The substrate's debug yield answers a raw word: a host-resumed root drive re-enters the parked fiber with the bare `PLATFORM_NONE` tag, so a row typed `Total(I64)` traps `slot holds Tag where I64 is required` on the second park.
- The list copy natives (cons, tail, collect) copy into the one `Vec` the fresh list adopts and take one branchy `inc_edge` walk; a second `Vec` costs an allocation plus a copy pass per call.
- The join/teardown driver's re-entry of a parked child is a preemption point under the nursery's raised cancel flag, its kept-frame deinits firing through the cancel-cut door; CALLT pc-reset stays outside the observation points, so a self-tail-loop child never observes cancellation.
- Nesting a drive never uses the Rust stack: a joining fiber parks at its join call and the joined drive runs on the interlock stack, and the fork-join unlock parks the CALLG site the same way, so a synchronous unlock aborts at depth ~800 where the park holds a 2048-level pin (`crates/ds-vm/tests/nursery_interlock.rs`).
- A teardown hook must return to its driver: one that parks, dies, traps, observes a raised cancel flag at a backward branch, or calls a nursery control seam refuses with `Trap::ReentrancyRefused`, its effects standing; never cut the fiber whose death walk drives the hook.
- The teardown claim directory comes from each body's own drop shape (`MOV overlay(i) <- body(base+i)` plus `CALL` of `$deinit`), so a hand-assembled fixture staging such a call is a claim site whether or not it is reachable; its establishment band is one Tag body word per claim site, SET at registration and CLEAR at every drop, hand-off, and consuming staging, at or above `FIRST_RESERVED_TAG`, so a user-mintable value would let a stale word fire a never-established claim.
- A word a borrowed registration names never anchors a deinit claim: a const alias, a match binder, or a `_` discard over a borrowed deinit-carrying param binds the owner's word without re-establishing the claim, so e2e goldens over deinit scrutinees read through the scrutinee's own name.
- Every Fn-classified widening proves its word a non-capturing scalar (`scalar_fn_words`): a var's fn slot, a collection or tuple element, a union's fn payload, and every fn-typed answer staging. An unproven callable word may hold a closure's `Ref` and strand the count, so a fn-typed struct field refuses at its own span.
- Generic trait bodies lower once per impl under runtime evidence, the transitive chain riding the module's chain table, where a pair's frame area is its one chain word indexing that table. Refused: an inner callee whose demand the frame never staged, per-branch evidence over a receiver unioning type variables, and a substituted pair variable spanning more than one word.
- The per-call-site check for `Raw`-staged words must admit a `Raw` callee parameter (a Raw parameter being the wildcard), or the first `Raw`-into-`Raw` staging through CALL/CALLS/CALLT traps as a call-site layout mismatch.
- Captures copy by value at CLOSURE_NEW, so mutable-capture shapes stay out of the kernels; pinned refusals: a lambda capturing a closure word, one capturing a callable-defaulted binding, and native or generic fn values minting callable words.
- The module-id space is registry state, not a format fact: ids mint per VM at first install (first-install order, stable across hot-reload swaps, uop modules only), and nothing diagnoses a fn word crossing VMs, so a word minted under one registry aliases the same id under another (`crates/ds-vm/tests/module_ids.rs`).
- A cross-heap count op queues only on the store whose own mutation observed the foreign word, and every routed mutation drains to quiescence, so one store's queue length is the whole pending count and `settle` answers a quiet queue without walking the pool; a second queue site not ending in the drain breaks that shortcut.
- A call site's layout facts (the slide plan, its `Raw`-staged word list, its layout-static refusal) ride the inline-cache entry under the same (caller address, pc, stamp) key as the callee, so they re-derive exactly when the callee does and never on a hit.
- Every hot seam names a version by its `VersionIdx`, a row of the per-VM version table whose `Arc` owns the version's survival, so chain entries, resume points, and inline-cache rows move no Arc count; the arms read through `Registry::pinned`'s address-stable pointer. The install-time sweep judges the registry's detached list alone (O(detached), never the table's width — a second detach site would grow the judge list and the table together) and covers every fiber's kept frames, a `Dead` fiber's included. A swept row's index recycles at a later install through the reuse freelist: the sweep's proof that no frame, parked fiber, or cache names the row is what makes the reuse safe, so a seam holding a `VersionIdx` across an install reads the reuse's version, never a stale one. A slot swap's re-check over the retiring code's pool call sites reads only the version rows a runnable frame or parked fiber pins, since the registry's own slots and a dead fiber's kept frames would break the completed-frame redirect-by-index (`crates/ds-vm/tests/hot_swap_pool_refs.rs`).
- The swap re-check's two judges never merge: a code site judges by the name its pool index holds (a changed frame layout is the ordinary body edit, a signature change traps at the call like a fresh run's), while a staged callable word and a retiring frame's post-swap KCONST mint judge name plus frame layout.
- A dying frame's teardown hook drives through the owning frame's version row, so a swap that recompiled the hook never fires new code for a claim the old code established. A trapped host drive's release fires the kept-frame deinit pass and drains the claims before clearing the chain, or hooks drive through freed versions (`crates/ds-vm/tests/trapped_release.rs`).
- An open nursery dies with its dead owner, never at a frame pin: the release doors tear down every open nursery whose owner fiber is dead, cold in spawn order, so a never-entered child's entry frame and resume point stop pinning the spawn version's row; a nursery whose owner parks or traps-and-waits waits for its own door (`crates/ds-vm/tests/trapped_nursery_release.rs`). The cancel-cut runs the same teardown at the cut door, so a cancelled owner's block nursery releases its parked children promptly instead of waiting for a release door (`crates/ds-vm/tests/cancelled_block_teardown.rs`).
- The peek-next fusion keeps three invariants: a fused op's traps and slot errors attribute to its own pc, never the load's; an intervening word fails the opcode-byte match, so it peeks exactly one word; and a fused branch re-enters the exact arm body with pc bumped first (`crates/ds-vm/tests/load_op_fusion.rs`, `cmp_branch_fusion.rs`).
- A callee answering a word it never writes reads its region's previous occupant, since `Vm::call` never zeroes a recycled frame: a part-less struct's reserved unit word returns the stale word of an earlier call.
- Adding opcode arms to the tier-1 dispatch loop re-lowers its neighbors (five inline shift/bitwise arms cost every pinned kernel measurable Ir while executing no shift), so one contiguous range arm handing the word to a helper fn keeps the hot match stable.
- A host run entry answers the whole span: `Vm::run` and `Vm::resume_fiber` answer `FrameAnswer` (width plus words) and the death value hands one `host_delivery` per `Ref` word, so the pitfall class is ungated width rather than truncation.
- The comptime reflection table is a thread-local slot, never a process global, or concurrently evaluating threads swap each other's tables mid-run and mask as mismatches and `UnknownInstance` traps in shared-process parallel runs.
- A child's pool slot can be recycled while the nursery's children list still holds its id, so re-check `fiber.nursery` before driving and ledger outcomes before recycling. A pooled child's homecoming tail runs the sequential death walk verbatim (`child_death_walk`), holding the cancel payload's `Ref` words back from the claim drain and routing their claims to the joiner, or the count drains on the worker-returned heap (`crates/ds-vm/tests/fork_pool.rs`).
- A map's content probe reads a stored key's payload on the map's own store (`stored_key_matches`) and ids are per-store, so a fresh row under a word foreign to the map's heap would answer no content probe — `Objects::set_map` refuses the insert as `Trap::ForeignMapKey` before any count moves, while a content-equal foreign probe overwriting an existing row and foreign value words stay legal. The refusal sits at the store seam, not the router, because the store alone sees the key word's fiber against its own owner, so every direct caller is caught.
- The heap's class pools are intrusive freelists linked through each pooled block's header, so a heap drop must walk every row to its end: releasing only the head strands the row's deeper nodes, a leak no object-accounting assert sees, caught only by libFuzzer's exit-time LSan over the vm leg (`crates/ds-rt/tests/heap_drop.rs`).
- A ds-rt test over the raw store surface must drive every block's death through `rc_dec_count` plus `rc_dispose` — no drop glue retires a leftover live block, so only miri's leak check sees it while the targeted nextest suite stays green (`crates/ds-rt/tests/rc.rs`).
- A host reporting `Vm::run`'s `Err(trap)` keeps the trapped root's frames alive for the backtrace, so it must call `release_interrupted(FIBER_ROOT)` after the report and before exiting nonzero: the VM fires the kept-frame deinit pass only at the release door, the next run's reset door, or pool-slot reuse.
- A seam that hands a parked fiber words at consumption or completion must allocate in that fiber's own store: `Heaps` with `live: false` routes reads and decs through the pool but still allocates into `self.objects` (the stale stash), so a `Ref` word would name a fiber whose store never held it, reading `UnknownObject` at the answer. The join channel's collection swaps the joiner's objects live for the allocation; a parked wait's completion and wake swap through `Vm::complete_in_store`.
- The boundary's clean join takes the completed answers only when the joiner still stands parked at its resume point: a moved-on joiner (resumed by a child mid-drive) has no call site, so the channel's list would leak beside its acquired rows — the same predicate `reenter_joiner` applies decides collection versus the no-ledger dec walk, and the failed boundary (first failure, interrupted drive) always decs.
- A drive that enters a woken fiber directly (a nursery sweep's own child) must take the fiber's run-queue entry with it (`SchedState::take_ready`): a woken fiber is queued AND delivered, and `wait_world` returns instantly on any queued fiber, so a stale entry answers the executor's wait ready forever while the reactor never polls — a 100%-CPU spin that still fires deadline wheels, masking as a slow wake (`crates/ds-vm/tests/io_sched.rs`).
- A wait's registration-time refusal allocates over the still-live context: the parking fiber IS the current one, so `complete_in_store`'s debug gate passes while its swap parks the fiber's true store into the slot and lands the refusal's message in the stale stash — a `Ref` word naming a store that never held it, reading `UnknownObject` at the answer. The refusal door releases the context first (`register_wait`'s Err branch, pinned by `crates/ds-vm/tests/net_server.rs`, 2026-11-24).
- Epoll holds one row per fd, so a second wait registering a watched handle would silently replace the standing row (ADD's EEXIST falling to MOD) and strand the first waiter's wake — an unbounded accept parks forever on a connection that never reaches it. The driver's token map refuses a cross-token registration loud (the same token's re-arm keeping its replace, the recycled-fd number adding clean past the stale map row since the kernel's row died with the old fd); in-language the linear handle discipline keeps two waits off one fd, so the refusal guards the embedder seam (`crates/ds-vm/src/reactor.rs`).
- A parked accept's IO interest resolves through the listener table, not the connection table: `register_wait` dispatches the raw-handle lookup on the wait's shape, because a listener id names no connection. A wait registered against the wrong table sits with no reactor interest and wakes at its deadline alone — masked as a slow wake, then a timeout (`crates/ds-vm/src/vm.rs`).
- std's `TcpListener` carries no OS accept timeout, so the blocking twin of the parked accept polls the non-blocking listener to its configured bound at a millisecond cadence — the bounded-wait discipline the socket timeouts give the data natives restated over a poll, since that is the only portable shape (`Connections`' timeout and the listener table's set together, one `set_net_timeout`).
- A handle closed while a wait parks on it must wake through the dispatcher's own door, never the native's: the native convention's two host references (the store, the sink) cannot reach the wait table, and the kernel drops the epoll row at the fd's close — a wait left standing wakes at its deadline alone (the unbounded accept never, its park carrying no wheel entry). The close native notes the closed id into the sink, and the native call site drains the note to deregister the interest and stage the waiter's answer (the note never outlives the call that wrote it; the answer allocates in the parked fiber's store through the same swap the wake completions use — `Vm::wake_closed`, the live-context swap safe because a completion allocates but never drives; `crates/ds-vm/tests/io_sched.rs`).
- A channel waiter registers in the channel's own waiter queues, never the scheduler's wait table: the driver routes a `WorldPark` event by `ParkKind`, a world wait registering interest plus a deadline while a channel wait needs neither (the waking peer is the parked fiber's resumer), so a channel-shaped `SchedulerDeadlock` trap is a program shape — the honest deadlock — while a net-shaped one names a scheduler bug. The one-owning-heap rule pins the channel's object to the creating fiber's store, and the parked sender's staged payload rides no count (the parked frame keeps its own, whoever cut the fiber releasing it). The zero-bound rendezvous rides the same queues with two doors the buffered paths must not swallow: a send with no buffer room ever pairs with a live parked receiver through a deposit the release hands straight over, and a receive pairs with a live staged sender through a deposit the immediate pop hands to its own frame — no refill may follow the rendezvous take (leaving the next staged sender's span in the freed slot silently widens the rendezvous into a bound of one), and both pairing doors must verify the peer's liveness before the deposit (a deposit with no live receiver would leave the element buffered while the send answers unit) (`crates/ds-vm/src/vm.rs`, `crates/ds-vm/tests/chan.rs`).
- The executor's eager start must rescan after each driven child before it waits: driving one Ready child to a park or death answers nothing about the rest, and `wait_world`'s stall guard reads only the wake tables, so later Ready siblings stand deadlocked beside them (`crates/ds-vm/tests/chan.rs`).
- A nursery child the executor starts or re-enters must never hand its step to the host loop: `DriveOutcome::Died` ends the host drive with whatever fiber the drive ended on, so an owned child completing there would answer the child's span as the run's own result and its trap would surface as the host's trap — the owned drive runs sweep-shaped inside `executor_continue` (the trap ledgered for the boundary), while the host drive answers its own fiber alone (`crates/ds-vm/tests/chan.rs`, `crates/ds-vm/tests/io_sched.rs`).
- A deinit hook fires only through a frame's own body-slot drop shape: the claim directory's staging-base scan refuses any run whose source is an overlay word (`staging_base` in `crates/ds-vm/src/claims.rs`), and a value consumed by its frame (a channel send's payload, a hand-off into a collection edge) has no drop site in the consuming body at all — so a claimed value whose words left the body slots, or whose death test a consuming staging spent, can fire no hook at any cut, drain, or release door; an armed band alone arms nothing, the directory is the whole witness. The channel queue's parked-sender copies compound it: they ride no count and no claim, whoever cuts the fiber releasing the frame's counts alone. The deinit-carrying channel payload and list/map element refusals stay pinned on this until the per-span deinit-claim seam lands (item 80's composition audit).
- The builtin core table's pinned-index run has three mirrors, so a native appended to the run extends all three: the `builtin_module` install-time debug assert, the `native::tests` name/length contract, and `types_hybrid`'s resolve-native length pin — missing one fails the gate at the length alone (left the new count, right the old).
- The callable-defaulted `Fn` slot (F2) admits a closure object's `Ref` word at four sites, not three: the frame-entry check, the generic dispatch's kind check, the callable-word call — and the ordinary slot write (`write_slot`), which a bodied library wrapper over a generic native hits first (its pass-through stages the callable parameter through a `Fn`-typed temp). The pairing stays one-directional: a `Ref` slot (a value site) never takes a scalar `Fn` word.
- The idempotent close of a child-carrying handle must kill and reap, never wait: a close or deinit that waits on a still-running child blocks the run's exit past the child's own lifetime, so `Procs::close` kills first and reaps after — a dropped `proc_handle` leaks neither a child nor a zombie (`crates/ds-cli/tests/proc_capture.rs`).
- A security-brokered host leaves `getsockopt(SO_ERROR)` polluted: a raw or std loopback socket that connected, accepted, and carried data still reads EPERM from the errno queue, so the textbook non-blocking-connect probe reports failure for success. Probe completion with a second `connect` — 0 or EISCONN connected, EALREADY pending, the errno otherwise — and never trust the SO_ERROR queue where the host mediates socket calls.
- Driving a rustls session per readiness wake maps the session's own wants onto epoll interests, but the mapping has three non-obvious teeth: `Reader::read` answers `WouldBlock` while the session is merely drained (unlike a socket, `Ok(0)` means a received close_notify alone), `wants_read` goes false while received plaintext stands undrained — the session's own backpressure, so the wake loop must drain through `reader()` before re-arming a read interest or the interest waits for a peer that waits for you — and a TCP EOF must answer the exchange's close-tolerant finish rather than an error (`process_new_packets` reports the missing close_notify as `UnexpectedEof`, which the blocking twin's CloseTolerant wrapper and the parked twin's own socket-EOF read map to the orderly close — the same kind a close-delimited blocking TLS read must map or every HTTP/1.0-close https response fails), while a TLS protocol failure carries the InvalidData wrap rustls's own `complete_io` gives it (`crates/ds-vm/src/tls.rs`, `crates/ds-vm/tests/tls_io.rs`).
- A readable wake's filter must take the kernel's HUP/ERR spellings, not the IN bit alone: a pipe whose write end closed with its buffer drained reports EPOLLHUP with no EPOLLIN (the kernel folds that EOF into the HUP bit), so an IN-only filter leaves the level-triggered HUP standing — a 100%-CPU spin over a parked fiber that never wakes. A HUP fd reads now — the pipe's orderly empty string — so decode both EPOLLHUP and EPOLLERR into an event the wake dispatch can name (`crates/ds-vm/src/reactor.rs`, `a_drained_pipe_reports_its_hangup`, `crates/ds-vm/tests/proc_park.rs`).
- A parked machine whose native took the socket itself must flip the stream non-blocking before its first step: every door that hands a std stream to a parked machine flips the flag at the handoff (`net::start_tls_accept`), not at the stage the machine happens to run first, or a connection the native's `try_accept` already answered (queued before the park) enters the handshake step still blocking and the thread sits in the session's `read_tls` past every bound — a hang no deadline wheel can reach (`crates/ds-vm/tests/tls_server.rs`).
- A staged machine whose reactor registration key moves under a step must swap the stored handle at the re-arm and deregister the stale key: `rearm_step` compares the stored handle and resolves the fresh key from the machine's own current transport, or a re-arm that re-registers only the new fd leaves the old fd's level-triggered interest standing — with a second connection queued the executor busy-loops the poll, each event a dead token the wake table drops. The fetch machines never hit this because their pending-connect fd is adopted unchanged into the registered stream, so the invariant is per-machine, not per-family (`crates/ds-vm/src/vm.rs`).
- A helper thread that posts a reactor wake must own its fd through the shared cell, never borrow the parked row's: a canceled wait drops the row (and its interest) before the helper posts, so the fd must close only when the last Arc holder does — the resolver twin's job cell — or the post can write into an fd number the kernel already reused (2026-11-24).
- The staged connect machine takes the first resolved address that connects at once or stands in progress, and a pending attempt that later refuses ends the whole machine with failure (no address fallthrough at the probe): a name like `localhost` resolves to both loopback families in the resolver's own order, so any e2e connecting by name binds a dual-stack (`[::]`) listener so whichever family is tried first connects (2026-11-24).
- A blocking wait twin that a stop flag must cut cannot spell its wait as one un-interruptible OS call: `Procs::wait`'s single `waitpid` keeps a reactor-less host's blocked wait running past a flipped stop flag with no portable interrupt to break it (the pidfd wake being the reactor's own), so the twin polls the child non-blockingly on a bounded sleep loop and reads the child before the flag each round, or a child that exited while the flag stood answers the shutdown trap forever, its reaped status unreachable (`crates/ds-vm/src/proc.rs`, `crates/ds-vm/tests/proc_shutdown.rs`, 2026-11-24).
- The CLI host's signalfd install has two traps: the SIGINT/SIGTERM mask must be blocked before any thread spawns (`pthread_sigmask` in `run` ahead of the resolver and fork-join workers), since an inherited default disposition means the first pool thread to receive the signal kills the process outright; and glibc 2.44 changed `signalfd`'s third parameter from sizemask to flags, so passing `sizeof(sigset_t)` answers EINVAL while `0` passes (`crates/ds-cli/src/shutdown.rs`, 2026-11-24). The Windows console-control twin publishes its handler flag at the install rather than the arm, or a console event arriving between the two is swallowed by the null-flag handler reporting handled.
- A bounded pump of the executor seam must cap the reactor poll even when no deadline stands: an unbounded park (the quiet accept arms no wheel entry) leaves `next_deadline` answering `None`, and a budget applied only inside the deadline's `map` never reaches the poll — the pump blocks in `epoll_wait` past every window and the host loop looks silently dead while its own watch events queue unpolled (`strace` shows the one blocking call; ptrace's EINTR unwedging it masked the bug as passing). The budget bounds the poll's `None` arm too, or the bounded and blocking waits are not the same code (`wait_world` in `crates/ds-vm/src/vm.rs`).
- A world-parked fiber is the scheduler's alone: an ordinary host resume (`resume_fiber`, the REPL's splice resume, dev's round drive) enters the parked frame with the payload as the parked call's answer and abandons the registered wait — the later wake delivers a stale answer onto a frame that moved on. The hosts route world-parked drives through the pump (`resume_fiber_io`/`pump_io`, `repl_continue`), the REPL refuses new submissions and `:drop` while one stands in flight, and the rollback/teardown doors cancel the root's waits first or a re-parked frame keeps a wake delivery aimed at it.
- The REPL's pump runs after the read returns, not only between loop passes: the host's blocking stdin read IS the wait during which wakes land, so a pass that judges the just-read line against the pre-read in-flight state refuses a line whose submission already woke — the pump takes what stands ready or expired before the line is judged (`drive` in `crates/ds-cli/src/repl.rs`).
- A drive's bounced resume orphans the resumee to the scheduler: the join sweep's preemption-shaped re-entry answers a child's `fiber_resume` call with the bare tag the moment its resumee parks (its only bound on a child that parks with no taken backward jump between parks), and no drive waits the foreigner — the join's `waiting` check covers its own children alone, and the executor's owned-children coverage requires no in-language resumer. The wake lands exactly under the next host executor loop: a blocking drive in flight continues on the woken foreign's step and ends at its death by the leftover pattern (the parked fiber a leftover the next pump still serves), while a pump enters no fiber, drives the foreign, and crosses its completion — the REPL's pump guarding its Died and Yielded arms the same way `io_pump` does. The hand is by design: only the executor's owned children drive contained (`crates/ds-vm/tests/io_sched.rs`).
- A budgeted executor loop that drains the scheduler answers spent, never the blocking stall trap: `wait_world`'s can-wake gate is budget-qualified, or a pump that wakes and finishes its last wait answers `SchedulerDeadlock` where its contract idles — and the blocking drives keep the honest deadlock. A consumed wait's wheel row drops lazily on pop, so far stale rows can defer the drain past a short budget; the pin's fixture keeps the orphan sleep-only, no net rows anywhere.

- A `struct tm` row handed to the CRT must be headed through every field the CRT writes, not only the ones the op reads: `localtime_r` fills the trailing `tm_zone` pointer, so a partial row ending at `tm_gmtoff` lets that tail write land in the caller's stack — a SIGSEGV or a cleanup-time runtime abort one frame later, not at the call (`crates/ds-vm/src/tz.rs`). Windows mirrors it with slack past the standard nine the UCRT pair diff, since the private `__tm_gmtoff`/`__tm_zone` rows are the CRT's to fill.
- A heap object's own count must stay unreachable from frame-word rc noise: an implementation where CLOSURE_NEW adopts the staged capture word's count (the lowerer's forward/dup replacing the op-internal kind-based acquire) exposes the object's edge count to any `RcOp::Dec` a frame word can address — the fuzz mirror's random decs then steal holder counts, a stored-element cascade hits a dead id, and the "stored element reference is live" tripwire panics where the op-acquire spelling only ever released the frame's own leak (four closures sharing one interned string, three noise decs, seed 626 of the base mirror). Any new count-holding channel through the overlay must ask first whether the fuzz mirror's `src(rng)` operand space can address the word the count rides on (ruled permanent 2026-11-25).
- A race's racer fiber is never entered from a host drive's own step: the race's owner parks `WorldWait` on the deadline wheel and the sweep drives the racer (a join drive runs no executor), so a deadline cut of a racer parked at its nested boundary is inline with the owned nurseries flagged (`crates/ds-vm/tests/timeout.rs`, 2026-11-26).
- The deadline wheel fires only when `wait_world` sees no runnable fiber, so mid-drive expiry is invisible to it: a parked racer is cut at the wheel's door, a never-parking racer at its back-edge by the interpreter's deadline poll (item 153) — a back-edge door only the race's own deadline arms, every other expired deadline still waiting for a quiet executor (`crates/ds-vm/tests/timeout.rs` pins both doors).
