# Runtime: native seam, reentry, memory facts

- Arena grants are raw pointers (a restore frees its range for the next allocation), so the aliasing contract (a restore kills every grant it freed, only the latest grant live) sits on the caller, kept honest by the miri leg over `cargo miri test -p ds-rt`.
- A reference outliving its deriving call (the `&Arena` in a `RestoreOnDrop` guard, any held `&Heap` state) must not materialize through the `UnsafeCell`'s unique re-tag: that tag inherits the `&mut Inner` retag, so a later `inner()` call invalidates it, which miri flags in the guard's drop; derive such references straight from the cell contents (`&*ptr::addr_of!((*cell.get()).field)`) so they keep the cell's shared tag.
- The ds-ffi export reader's never-panic contract is 64-bit-only: its `usize::try_from` narrowing and unchecked `usize` arithmetic over untrusted ELF/PE fields hold on windows-msvc and linux x86_64/aarch64 alone, so a 32-bit port audits every expect and addition first (`crates/ds-ffi/src/exports.rs`).
- Install natives and the platform before `loader::install` (pool FuncRefs validate at install time), and note `Vm::with_limit` installs only the builtin core, so both CLI run paths call `provide_platform`.
- A world call addresses the source's `platform "..."` name (default `std`): a host installing none under it, or one not serving the site's op capability, fails the install as `UnprovidedPlatformOp`.
- The bound-artifact tier installs before the module, since pool `Constant::Bound` validation reads the registry's bound tables; a refused load leaves the artifact uninstalled, and a declared artifact nothing binds loads nothing, so garbage or foreign-triple bytes staying runnable pins that laziness.
- The fork-join workers' code snapshot strips the bound tier beside the platforms, so a foreign call in a pooled child answers the unresolved-callee trap; bound modules to workers need a `Send + Sync` story for the loader handle.
- `loader::install` bakes pre-resolved ids through `ModuleRegistry::id_for_install` (an installed name's id, else the `id_names` tail the first install assigns), so renumbering or reusing ids misroutes every callee word and deinit hook.
- Reserve ids from both ends and never renumber an op table: unions allocate upward from 0, the platform reserves the u8 top downward (IO_OK 255 through NONE 251), the builtin core keeps its 0-48 run, and pool FuncRefs name positions.
- A new pure builtin lands in four places or source calls silently stay dead: the VM's native table (index, body, drift pins), the ambient declaration, the regenerated artifacts (`gen-ambient`, `gen-ambient-dsi`, `gen-ambient-dsmod` — all three write clean over bodiless externs), and ds-lower's native mirror — the mirror alone routes calls by name, so its absence surfaces only when a source call refuses as an extern non-builtin outside the contract, never at a gate over the ambient itself.
- Fallible natives: the two-word platform span re-spans into the call's failure union over the success-typed ambient, a failure prints `io|net error: <msg>` and halts, and CALLT-to-fallible is Unsupported.
- The net failure classes answer two discriminants paired with the `net_err` case the ambient names (`timeout`/`refused`), so a call-site union spelling them differently refuses at lowering.
- A rustls stream surfaces a peer's EOF without close_notify (the common HTTP/1.0 close) as `UnexpectedEof` rather than `Ok(0)`, so a close-delimited TLS read must map that kind to the orderly close or every such https response fails (`crates/ds-vm/src/tls.rs`).
- A teardown door can fire while another live fiber is current: the takeover parks that fiber's context and must re-adopt it after the pass, or the caller continues on stale scratch (`crates/ds-vm/tests/teardown_deinit.rs`).
- Every native call opens one borrow window in the placement pass before its operand evaluation and pops it at the flush, so a death firing inside defers to that flush; every `native_done` pairs with exactly one window.
- Hosted calls (`Vm::call_hosted`, from generic builtin bodies holding `&mut Vm`) inc each Ref argument, since the callee's placement owns its parameters. A boundary drive answers `DriveOutcome::Frame` keyed on the sentinel reentry frame (u32::MAX return pc), precise across fiber switches; a yield or HALT escaping it is `ReentrancyRefused`, and only the root frame's native tail may CALLT with abandoned counts.
- Keep the spawn seam's two closure forms on separate staging paths: a `spawn {}` block's child parameters are the captures, while a fork-join closure's captures stage past its element parameters into the frame's leading local slots; evidence crosses a lambda frame the same way.
- The fork-join completion delivery must acquire the receiving fiber's claim row, one per `Ref` word of the answer span, before the joiner's dec: `Heaps::dec`'s exact-ownership gate releases a foreign word only through the dec'ing fiber's row, so a rowless dec strands the count on the dead child's heap.
- A count mutation from a dead-context drive routes through the pool, its copy-in helpers following `ctx_live`; a hardcoded live-context assumption reads a just-died child's word as `UnknownObject`.
- The substrate's debug yield answers a raw word: a host-resumed root drive re-enters the parked fiber with the bare `PLATFORM_NONE` tag, so a row typed `Total(I64)` traps `slot holds Tag where I64 is required` on the second park.
- The list copy natives (cons, tail, collect) copy into the one `Vec` the fresh list adopts and take one branchy `inc_edge` walk; a second `Vec` costs an allocation plus a copy pass per call (+117% on containers).
- The join/teardown driver's re-entry of a parked child is a preemption point under the nursery's raised cancel flag, its kept-frame deinits firing through the cancel-cut door; CALLT pc-reset stays outside the observation points, so a self-tail-loop child never observes cancellation.
- Nesting a drive never uses the Rust stack: a joining fiber parks at its join call and the joined drive runs on the interlock stack, and the fork-join unlock parks the CALLG site the same way, so a synchronous unlock aborts at depth ~800 where the park holds a 2048-level pin (`crates/ds-vm/tests/nursery_interlock.rs`).
- A teardown hook must return to its driver: one that parks, dies, traps, observes a raised cancel flag at a backward branch, or calls a nursery control seam refuses with `Trap::ReentrancyRefused`, its effects standing; never cut the fiber whose death walk drives the hook.
- The teardown claim directory comes from each body's own drop shape (`MOV overlay(i) <- body(base+i)` plus `CALL` of `$deinit`), so a hand-assembled fixture staging such a call is a claim site whether or not it is reachable; its establishment band is one Tag body word per claim site, SET at registration and CLEAR at every drop, hand-off, and consuming staging, at or above `FIRST_RESERVED_TAG`, so a user-mintable value would let a stale word fire a never-established claim.
- A word a borrowed registration names never anchors a deinit claim: a const alias, a match binder, or a `_` discard over a borrowed deinit-carrying param binds the owner's word without re-establishing the claim, so e2e goldens over deinit scrutinees read through the scrutinee's own name.
- Every Fn-classified widening proves its word a non-capturing scalar (`scalar_fn_words`): a var's fn slot, a collection or tuple element, a union's fn payload, and every fn-typed answer staging. An unproven callable word may hold a closure's `Ref` and strand the count, so a fn-typed struct field refuses at its own span.
- Generic trait bodies lower once per impl under runtime evidence, the transitive chain riding the module's chain table, where a pair's frame area is its one chain word indexing that table. Refused: an inner callee whose demand the frame never staged, per-branch evidence over a receiver unioning type variables, and a substituted pair variable spanning more than one word.
- The per-call-site check for `Raw`-staged words must admit a `Raw` callee parameter, a Raw parameter being the wildcard, or the first `Raw`-into-`Raw` staging through CALL/CALLS/CALLT traps as a call-site layout mismatch.
- Captures copy by value at CLOSURE_NEW, so mutable-capture shapes stay out of the kernels; pinned refusals: a lambda capturing a closure word, one capturing a callable-defaulted binding, and native or generic fn values minting callable words.
- The module-id space is registry state, not a format fact: ids mint per VM at first install (first-install order, stable across hot-reload swaps, uop modules only), and nothing diagnoses a fn word crossing VMs, so a word minted under one registry aliases the same id under another (`crates/ds-vm/tests/module_ids.rs`).
- A cross-heap count op queues only on the store whose own mutation observed the foreign word, and every routed mutation drains to quiescence, so one store's queue length is the whole pending count and `settle` answers a quiet queue without walking the pool; a second queue site not ending in the drain breaks that shortcut.
- A call site's layout facts (the slide plan, its `Raw`-staged word list, its layout-static refusal) ride the inline-cache entry under the same (caller address, pc, stamp) key as the callee, so they re-derive exactly when the callee does and never on a hit.
- Every hot seam names a version by its `VersionIdx`, a row of the per-VM append-only table whose `Arc` owns the version's survival, so chain entries, resume points, and inline-cache rows move no Arc count; the arms read through `Registry::pinned`'s address-stable pointer, and the install-time sweep's marks cover every fiber's kept frames, a `Dead` fiber's included. A slot swap's re-check over the retiring code's pool call sites reads only the version rows a runnable frame or parked fiber pins, since the registry's own slots and a dead fiber's kept frames would break the completed-frame redirect-by-index (`crates/ds-vm/tests/hot_swap_pool_refs.rs`).
- The swap re-check's two judges never merge: a code site judges by the name its pool index holds (a changed frame layout is the ordinary body edit, a signature change traps at the call like a fresh run's), while a staged callable word and a retiring frame's post-swap KCONST mint judge name plus frame layout.
- A dying frame's teardown hook drives through the owning frame's version row, so a swap that recompiled the hook never fires new code for a claim the old code established. A trapped host drive's release fires the kept-frame deinit pass and drains the claims before clearing the chain, or hooks drive through freed versions (`crates/ds-vm/tests/trapped_release.rs`).
- An open nursery dies with its dead owner, never at a frame pin: the release doors tear down every open nursery whose owner fiber is dead, cold in spawn order, so a never-entered child's entry frame and resume point stop pinning the spawn version's row; a nursery whose owner parks or traps-and-waits waits for its own door (`crates/ds-vm/tests/trapped_nursery_release.rs`).
- The peek-next fusion keeps three invariants, pinned by `crates/ds-vm/tests/load_op_fusion.rs` and `cmp_branch_fusion.rs`: a fused op's traps and slot errors attribute to its own pc, never the load's; an intervening word fails the opcode-byte match, so it peeks exactly one word; and a fused branch re-enters the exact arm body with pc bumped first.
- A callee answering a word it never writes reads its region's previous occupant, since `Vm::call` never zeroes a recycled frame: a part-less struct's reserved unit word returns the stale word of an earlier call.
- Adding opcode arms to the tier-1 dispatch loop re-lowers its neighbors: five inline shift/bitwise arms cost every pinned kernel ~0.6-1.5% Ir while executing no shift, so one contiguous range arm handing the word to a helper fn keeps the hot match stable.
- A host run entry answers the whole span: `Vm::run` and `Vm::resume_fiber` answer `FrameAnswer` (width plus words) and the death value hands one `host_delivery` per `Ref` word, so the pitfall class is ungated width rather than truncation.
- The comptime reflection table is a thread-local slot, never a process global, or concurrently evaluating threads swap each other's tables mid-run and mask as mismatches and `UnknownInstance` traps in shared-process parallel runs.
- A child's pool slot can be recycled while the nursery's children list still holds its id, so re-check `fiber.nursery` before driving and ledger outcomes before recycling. A pooled child's homecoming tail runs the sequential death walk verbatim (`child_death_walk`), holding the cancel payload's `Ref` words back from the claim drain and routing their claims to the joiner, or the count drains on the worker-returned heap (`crates/ds-vm/tests/fork_pool.rs`).
- A map's content probe reads a stored key's payload on the map's own store (`stored_key_matches`) and ids are per-store, so a fresh row under a word foreign to the map's heap would answer no content probe — `Objects::set_map` refuses the insert before any count moves (`Trap::ForeignMapKey`), while a content-equal foreign probe overwriting an existing row and foreign value words stay legal. The refusal sits at the store seam, not the router, because the store alone sees the key word's fiber against its own owner, so every direct caller is caught.
- The heap's class pools are intrusive freelists linked through each pooled block's header, so a heap drop must walk every row to its end: releasing only the head strands the row's deeper nodes, a leak no object-accounting assert sees, caught only by libFuzzer's exit-time LSan over the vm leg (`crates/ds-rt/tests/heap_drop.rs`).
- A host reporting `Vm::run`'s `Err(trap)` keeps the trapped root's frames alive for the backtrace, so it must call `release_interrupted(FIBER_ROOT)` after the report and before exiting nonzero: the VM fires the kept-frame deinit pass only at the release door, the next run's reset door, or pool-slot reuse.
- A seam that hands the parked joiner words at consumption must allocate in the joiner's own store: after the consumption prologue's `host_release` every live context sits in the pool, `Heaps` with `live: false` routes reads and decs through the pool but still allocates into `self.objects` (the stale stash), so the boundary's collected list swaps the joiner's objects live for the allocation exactly the fork stage's pre-park allocation never needed to. The element assembly then rides the ordinary `live: false` routing (child-heap answer words inc/dec through the foreign-post funnel).
- The boundary's clean join takes the completed answers only when the joiner still stands parked at its resume point: a moved-on joiner (resumed by a child mid-drive) has no call site, so the channel's list would leak beside its acquired rows — the same predicate `reenter_joiner` applies decides collection versus the no-ledger dec walk, and the failed boundary (first failure, interrupted drive) always decs.
- A drive that enters a woken fiber directly (a nursery sweep's own child) must take the fiber's run-queue entry with it (`SchedState::take_ready`): a woken fiber is queued AND delivered, and `wait_world` returns instantly on any queued fiber, so a stale entry answers the executor's wait ready forever while the reactor never polls — a 100%-CPU spin that still fires deadline wheels, masking as a slow wake (`crates/ds-vm/tests/io_sched.rs`).
- A parked wait's completion must allocate in the parked fiber's own store (`Vm::complete_in_store` swaps the slot's store into the context for the completion): the same stale-stash lesson the join channel's collection learned — `Heaps` with `live: false` routes reads and decs through the pool but still allocates into `self.objects`, so the wake's answer `Ref` would name a fiber whose store never held it (`crates/ds-vm/tests/io_sched.rs`).
- A parked accept's IO interest resolves through the listener table, not the connection table: `register_wait` dispatches the raw-handle lookup on the wait's shape, because a listener id names no connection. A wait registered against the wrong table sits with no reactor interest and wakes at its deadline alone — masked as a slow wake, then a timeout (`crates/ds-vm/src/vm.rs`).
- std's `TcpListener` carries no OS accept timeout, so the blocking twin of the parked accept polls the non-blocking listener to its configured bound at a millisecond cadence — the bounded-wait discipline the socket timeouts give the data natives restated over a poll, since that is the only portable shape (`Connections`' timeout and the listener table's set together, one `set_net_timeout`).
- `net_close` during a parked wait on the same handle leaves the wait standing with no interest behind it: the kernel drops the epoll row at the fd's close, so the parked fiber wakes at its deadline with the timeout span (bounded and honest), never early — a wake-on-close needs the sink reaching the wait table, which the native convention's two host references do not spell.
- A channel waiter registers in the channel's own waiter queues, never the scheduler's wait table: the driver routes a `WorldPark` event by `ParkKind`, a world wait registering interest plus a deadline while a channel wait needs neither (the waking peer is the parked fiber's resumer), so a channel-shaped `SchedulerDeadlock` trap is a program shape — the honest deadlock — while a net-shaped one names a scheduler bug; the one-owning-heap rule pins the channel's object to the creating fiber's store, the parked sender's staged payload riding no count (the parked frame keeps its own, whoever cut the fiber releasing it).
- The executor's eager start must rescan after each driven child before it waits: driving one Ready child to a park or death answers nothing about the rest, and `wait_world`'s stall guard reads only the wake tables — later Ready siblings stand deadlocked beside them (the benign-first-child probe, `crates/ds-vm/tests/chan.rs`), so the pass answers drove-versus-idle and the loop rescans on every drove.
- A nursery child the executor starts or re-enters must never hand its step to the host loop: `DriveOutcome::Died` ends the host drive with whatever fiber the drive ended on, so an owned child completing there would answer the child's span as the run's own result and its trap would surface as the host's trap — the owned drive runs sweep-shaped inside `executor_continue` (a death discarded like the sweep's, the trap ledgered for the boundary), while the host drive answers its own fiber alone (`crates/ds-vm/tests/chan.rs`, `crates/ds-vm/tests/io_sched.rs`).
- The builtin core table's pinned-index run has three mirrors, so a native appended to the run extends all three: the `builtin_module` install-time debug assert, the `native::tests` name/length contract, and `types_hybrid`'s resolve-native length pin — missing one fails the gate at the length alone (left the new count, right the old).
- The callable-defaulted `Fn` slot (F2) admits a closure object's `Ref` word at four sites, not three: the frame-entry check, the generic dispatch's kind check, the callable-word call — and the ordinary slot write (`write_slot`), which a bodied library wrapper over a generic native hits first (its pass-through stages the callable parameter through a `Fn`-typed temp; the entry had admitted the closure while the write refused it, trapping `slot N holds Ref where Fn is required` inside the wrapper). The pairing stays one-directional: a `Ref` slot (a value site) never takes a scalar `Fn` word.
- The idempotent close of a child-carrying handle must kill and reap, never wait: a close or deinit that waits on a still-running child blocks the run's exit past the child's own lifetime, so `Procs::close` kills first and reaps after — a dropped `proc_handle` leaks neither a child nor a zombie (`crates/ds-cli/tests/proc_capture.rs`).
- A security-brokered host leaves `getsockopt(SO_ERROR)` polluted: a raw or std loopback socket that connected, accepted, and carried data still reads EPERM from the errno queue (the 2026-11-23 parked-connect round found it on the lane's own test machine), so the textbook non-blocking-connect probe reports failure for success. Probe completion with a second `connect` — 0 or EISCONN connected, EALREADY pending, the errno otherwise — which reads the socket's own state, and never trust the SO_ERROR queue where the host mediates socket calls.
- Driving a rustls session per readiness wake maps the session's own wants onto epoll interests, but the mapping has three non-obvious teeth: `Reader::read` answers `WouldBlock` while the session is merely drained (unlike a socket, `Ok(0)` means a received close_notify alone), `wants_read` goes false while received plaintext stands undrained — the session's own backpressure, so the wake loop must drain through `reader()` before re-arming a read interest or the interest waits for a peer that waits for you — and a TCP EOF must answer the exchange's close-tolerant finish rather than an error (`process_new_packets` reports the missing close_notify as UnexpectedEof, which the blocking twin's CloseTolerant wrapper maps to the orderly close; the parked twin reads the socket's own EOF the same way), while a TLS protocol failure carries the InvalidData wrap rustls's own `complete_io` gives it (`crates/ds-vm/src/tls.rs`, `crates/ds-vm/tests/tls_io.rs`).
- A readable wake's filter must take the kernel's HUP/ERR spellings, not the IN bit alone: a pipe whose write end closed with its buffer drained reports EPOLLHUP with no EPOLLIN (the kernel folds that EOF into the HUP bit), so the proc read twin's `event.read` filter left the level-triggered HUP standing — a 100%-CPU spin over a parked fiber that never wakes. The lost wake needs the drain-then-exit window: a quiet single-read fixture and every park-before-write e2e passed while the CLI's read-until-empty loop over a late-writing child hung, so a wake family must be probed at the window between a consumed readiness and the peer's close, not only at data arrival. A HUP fd reads now — the pipe's orderly empty string — so the read interest's wake answers over it; decode both EPOLLHUP and EPOLLERR into an event the wake dispatch can name (`crates/ds-vm/src/reactor.rs`, `a_drained_pipe_reports_its_hangup`, `crates/ds-vm/tests/proc_park.rs`).
