# Runtime: native seam, reentry, memory facts

- Install natives and the platform into the registry before `loader::install`, since pool FuncRefs validate at install time; `Vm::with_limit` installs only the builtin core, so both CLI run paths call `provide_platform`.
- `loader::install` bakes pre-resolved module ids through `ModuleRegistry::id_for_install` (an installed name's id, else the `id_names` tail the first install assigns), so derivation and the registry's assignment stay one rule: renumbering or reusing ids silently misroutes every loaded callee word and deinit hook.
- World calls address the source's `platform "..."` name (default `std`): a host installing no platform under that name, or one not serving the call site's op capability, fails the install as `UnprovidedPlatformOp`.
- Reserve ids from both ends and never renumber an op table: union ids allocate upward from 0, the platform reserves the u8 top downward (IO_OK 255 through NONE 251), the builtin core keeps its historical 0-48 run with the world-surface and generic slots reserved, and pool FuncRefs name positions.
- Fallible natives: the two-word platform span re-spans into the call's failure union over the success-typed ambient, a failure prints `io|net error: <msg>` and halts, and CALLT-to-fallible is Unsupported.
- The net failure classes answer two platform discriminants, and the lowerer pairs each with the union member the ambient `net_err` case name names (`timeout`/`refused`, ruled 2026-11-12), so a call-site union spelling its error members differently refuses at lowering — the class mapping is the ambient taxonomy's, never a shape heuristic over payload-less members.
- A rustls stream surfaces a peer's EOF without close_notify — the common HTTP/1.0 server close — as an `UnexpectedEof` error, not `Ok(0)`, so a close-delimited read over TLS must map that one kind to the orderly close (the plain exchange's own EOF semantics) or every https response without a trailing handshake fails (`crates/ds-vm/src/tls.rs`).
- Hosted calls (`Vm::call_hosted`, reachable from generic builtin bodies holding `&mut Vm`) inc each Ref argument, since the callee's placement owns its parameters and borrowed staging double-decs; a RET span at the reentry frame skips the caller-area bound.
- A boundary drive answers `DriveOutcome::Frame` keyed on the sentinel reentry frame (u32::MAX return pc), precise across fiber switches; a yield or HALT escaping a hosted drive is `ReentrancyRefused`, and only the root frame's native tail may CALLT with abandoned staged counts.
- Every native call opens one borrow window in the placement pass before its operand evaluation and pops it at the flush, pinning each word its CALL reads, so a death firing inside defers to that flush (the `b + "${b}x"` shape); every `native_done` pairs with exactly one window.
- A child's pool slot can be recycled while the nursery's children list still holds the id: re-check `fiber.nursery` before driving and ledger outcomes before recycling.
- Keep the spawn seam's two closure forms on separate staging paths: a `spawn {}` block compiles to a child whose declared parameters ARE the captures, while a fork-join closure callable's captures stage past its element parameters into the frame's leading local slots. Evidence crosses a lambda frame the same way.
- The fork-join completion delivery must acquire the receiving fiber's claim row, one per `Ref` word of the answer span, before the joiner's dec: `Heaps::dec`'s exact-ownership gate releases a foreign word only through the dec'ing fiber's own row, so a rowless dec strands the count on the dead child's heap.
- A count mutation from a dead-context drive routes through the pool, the copy-in helpers following `ctx_live`: a hardcoded live-context assumption reads a just-died child's word as an `UnknownObject`.
- The substrate's debug yield answers a raw word, and a spelled extern must agree: a host-resumed root drive re-enters the parked fiber with the bare `PLATFORM_NONE` tag, so a lowering-table row typed `Total(I64)` traps `slot holds Tag where I64 is required` on the second park.
- The list copy natives (cons, tail, collect) touch their element words exactly once: memcpy into the one `Vec` the fresh list adopts, then one branchy walk taking `inc_edge` per `Ref` word; a second `Vec` costs an allocation plus a copy pass per call (containers regressed +117%).
- The join/teardown driver's re-entry of a parked child is a preemption point under the nursery's raised cancel flag, its kept-frame deinits firing through the cancel-cut door; CALLT pc-reset stays outside the observation points, so a self-tail-loop child never observes cancellation.
- Nesting a drive never uses the Rust stack: a fiber joining another open nursery parks at its join call and the joined drive runs on the interlock stack, and the fork-join unlock parks the CALLG site the same way, a synchronous unlock aborting at depth ~800 while the parked seam holds a 2048-level pin (`crates/ds-vm/tests/nursery_interlock.rs`, `conformance/nursery_deep.ds`).
- A teardown hook must return to its driver: one that parks, dies, traps, observes a raised cancel flag at a backward branch, or calls a nursery control seam refuses with `Trap::ReentrancyRefused`, its effects standing; never cut the fiber whose death walk is driving the hook.
- The teardown claim directory comes from each body's own drop shape (`MOV overlay(i) <- body(base+i)` run plus `CALL` of the module's `$deinit`), so a hand-assembled fixture staging such a call is a claim site whether or not it is reachable.
- The claim establishment band is one Tag body word per claim site with two reserved values, SET at registration and CLEAR at every drop, hand-off, and consuming staging, at or above `FIRST_RESERVED_TAG`: a user-mintable value lets a recycled frame region's stale word fire a never-established claim.
- A word a borrowed registration names never anchors a deinit claim: a const alias, a match binder, or a `_` discard over a borrowed deinit-carrying param binds the owner's word without re-establishing the claim, so e2e goldens over deinit scrutinees read through the scrutinee's own name.
- A teardown door can fire while another live fiber is current: the takeover parks that fiber's context before swapping the dying fiber's parked one in and must re-adopt it after the pass, or the caller continues on stale scratch (pinned in `crates/ds-vm/tests/teardown_deinit.rs`).
- Every Fn-classified widening proves its word a non-capturing scalar (`scalar_fn_words`): a var's fn slot, a collection or tuple element, a union region's fn payload, and every fn-typed answer staging. An unproven callable word may hold a closure's `Ref`, trapping `SlotTypeMismatch` and stranding the count; a fn-typed struct field refuses at its own span instead of reaching the guard.
- Generic trait bodies lower once per impl under runtime evidence, the transitive chain riding the module's chain table. Refused: an inner callee whose demand the frame never staged, per-branch evidence over a receiver unioning type variables, and a substituted pair variable spanning more than one word.
- Transitive evidence: a pair's frame area is its one chain word indexing the module's chain table; the demand walk also collects a constructed receiver's peeled variable, and a nested runtime dispatch stages the tail words itself.
- The per-call-site check for `Raw`-staged words must admit a `Raw` callee parameter, a Raw parameter being the wildcard: without it the first `Raw`-into-`Raw` staging through CALL/CALLS/CALLT traps as a call-site layout mismatch while the lowering is fully staged.
- Captures copy by value at CLOSURE_NEW, so mutable-capture shapes stay out of the kernels. Pinned honest refusals: a lambda capturing a closure word, a lambda capturing a callable-defaulted binding, and native or generic fn values minting callable words (never in 1.0, ruled 2026-11-12).
- The module-id space is registry state, not a format fact: ids mint per VM at first install (first-install order, stable across hot-reload swaps, uop modules only), and nothing diagnoses a fn word crossing VMs, so a word minted under one registry aliases the same id under another (`crates/ds-vm/tests/module_ids.rs`).
- A cross-heap count op queues only on the store whose own mutation observed the foreign word, and every routed mutation drains to quiescence, so one store's queue length is the whole pending count and `settle` answers a quiet queue without walking the pool; a second queue site that does not end in the drain breaks the shortcut.
- A call site's layout facts (the slide plan, its `Raw`-staged word list, and its layout-static refusal) ride the inline-cache entry under the same (caller address, pc, stamp) key as the callee, so they re-derive exactly when the callee does and never on a hit; a refused pair re-raises at the call seam.
- Every hot seam names a module version by its `VersionIdx`, a row of the per-VM append-only version table whose `Arc` owns the version's survival, so chain entries, resume points, and inline-cache rows move no Arc count. The dispatch arms read through `Registry::pinned`'s address-stable raw pointer, valid because a row retires only inside the install-time sweep; the sweep's marks include every fiber's kept frames, a `Dead` fiber's included, or the recycle door reads freed versions (pinned in `crates/ds-vm/tests/calls.rs`).
- A slot swap's re-check over the retiring code's pool call sites must read only the version-table rows a runnable frame or parked fiber pins: the registry's own slots and a dead fiber's kept frames stay out, or the completed-frame redirect-by-index the inline-cache tests pin breaks and the dev loop's differential stalls on its own recompile (pinned in `crates/ds-vm/tests/hot_swap_pool_refs.rs`).
- The swap re-check's two identity judges never merge: a code site judges by the name its pool index holds (a changed frame layout is the ordinary body edit — the inline cache re-derives the site's facts, and a signature change traps at the call like a fresh run's), while a staged callable word and a retiring frame's post-swap KCONST mint judge name plus frame layout, the mint translating the own pool's index into the current table before the word enters the value space.
- A dying frame's teardown hook drives through the owning frame's version row (`collect_teardown_drives` hands the row to the hosted call): the hook body is the frame's own declaration, so a swap that recompiled it must never fire the new code for a claim the old code established.
- A trapped host drive's release must fire its kept frames' deinit pass and drain their claims BEFORE clearing the chain and marking the slot Dead: the pass resolves each hook through the owning frame's version row, so a cleared-first chain drives hooks through freed versions, and the staged words in the frames' segment must truncate away with them or a dead frame's `Fn` words keep refusing swaps the completed-frame semantics would install (pinned in `crates/ds-vm/tests/trapped_release.rs`).
- An open nursery dies with its dead owner, never at a frame pin: the owner link is a lifecycle fact set at open (`open_fresh_nursery` records the current fiber, the host root none), and the release doors tear down every open nursery whose owner fiber is dead — releasing live children cold in spawn order under the per-fiber release pass, entering none, so a never-entered child's entry frame and resume point stop pinning the spawn version's row and its staged words stop gating swaps — while a nursery whose owner merely parks or traps-and-waits stays untouched until its own door (pinned in `crates/ds-vm/tests/trapped_nursery_release.rs`).
- The peek-next fusion keeps one rule set, each invariant pinned in `crates/ds-vm/tests/load_op_fusion.rs` and `crates/ds-vm/tests/cmp_branch_fusion.rs`: a fused op's traps and slot errors attribute to its own pc, never the load's; an intervening word fails the opcode-byte match, so the fusion peeks exactly one word; and a fused branch re-enters the exact arm body with pc bumped first, so a bounds trap and a backward-branch cancel observation fire where the unfused spelling's do.
- A callee answering a word it never writes reads its frame region's previous occupant: `Vm::call` never zeroes a recycled frame's slots, so a part-less struct's reserved unit word returns the stale word of an earlier call on the same region, a kind-matching occupant flowing silently as a stale value.
- Adding opcode arms to the tier-1 dispatch loop re-lowers its neighbors: five inline shift/bitwise arms cost every pinned kernel ~0.6-1.5% Ir while executing no shift. Grouping a new opcode family under one contiguous range arm that hands the word to a helper fn keeps the hot match stable (seven of nine kernels within ±0.23%).
- A host run entry answers the whole answer span: `Vm::run` and `Vm::resume_fiber` answer `FrameAnswer` (width plus words) and the drive's death value hands one `host_delivery` per `Ref` word, so the pitfall class is ungated width rather than truncation (the comptime embed gates every answer against the call's checked type, pinned in `crates/ds-meta/tests/comptime_e2e.rs`); the seam's shape cost every pinned kernel ~0.5-1.5% Ir as layout churn.
- The comptime reflection table is a thread-local slot, never a process global: a process global lets concurrently evaluating threads swap each other's tables mid-run, masking as mismatches and `UnknownInstance` traps in shared-process parallel test runs (`concurrent_evaluations_keep_their_own_reflection`).
- A pooled child's homecoming tail runs the sequential drive's death walk verbatim (`child_death_walk`): the cancel payload's `Ref` words are held back from the claim drain and their claims routed to the joiner before the trap's delivery, or the count drains on the worker-returned heap and the host receives a dead id (pinned in `crates/ds-vm/tests/fork_pool.rs`).
- The heap's class pools are intrusive freelists linked through each pooled block's header, so a heap drop must walk every row to its end: releasing only the head strands the row's deeper nodes, a leak no object-accounting assert sees, since the drain counts objects while pooled nodes are raw blocks — caught only by libFuzzer's exit-time LSan over the vm leg (pinned in `crates/ds-rt/tests/heap_drop.rs`).
