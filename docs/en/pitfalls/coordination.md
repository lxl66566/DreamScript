# Coordination and gates

Working agreements for parallel lanes and the gates that judge a landing.

- One worktree and branch per agent, additive-only root `Cargo.toml` edits, no git in main, the coordinator the only main writer; two lanes in one worktree switch each other off their branch, so move commits with `git cherry-pick`. Never run `cargo fmt` outside your own worktree, since a stray fmt in main rewrites tracked files and breaks merges.
- Corpus-reading tests and benches resolve the corpus at run time through the dev-only `ds-corpus-path` crate (compile-time checkout, else a walk up from the test binary to a root holding `conformance/`) and validate the file rather than the directory, or a spawned `ds check` fails `No such file` blamed on its exit code.
- `DS_BUILD_ID` folds `Cargo.lock`, each bytecode crate's source tree, and each bytecode crate's manifest by file path, so a lock change, a manifest's dependency or feature reshuffle (no source file touched), and a source file's add, rename, or move re-key the checked-in `ambient.dsmod` at its 16-byte header alone, the payload staying byte-identical; the ds-cli run-path files (`run_cache.rs` among them) fold by content, so even a non-semantic edit re-keys it.
- A `rerun-if-changed` path is package-root-relative, so a sibling crate watched as `ds-check/src` (the crates-dir spelling) watches a nonexistent path under ds-cli: cargo records the watch absent and never reruns the build script on sibling edits, and a warm target dir or a build-script output cache then serves a stale `DS_BUILD_ID` — the dsmod regenerates with a header only the generating checkout accepts. The fold set and the watch set derive from one list whose spellings `crates/ds-cli/tests/build_identity_watch.rs` pins. A gate that shares the artifact's baked identity cannot catch that identity's staleness: the drift gates stamp their fresh generation with the same `DS_BUILD_ID`, so a stale script output leaves both sides agreeing and only a clean checkout's rebuild refuses (reproduced live with an mtime-invisible sibling edit — every bin gate green, the fresh-fold gate red). The fresh-fold gate closes the blind spot by re-folding the digest over the working tree's current bytes and requiring the baked identity to match, which is the comparison a clean checkout reaches by rebuilding from scratch; when it fails, rerun the build script (touch `build.rs`) and reseat the ambient dsmod when the seal's header moved.
- `cargo run -p ds-cli --example gen-ambient-dsmod` rebuilds the example target alone, never the `ds` bin, which embeds the ambient sources and artifacts through `include_str!`/`include_bytes!`: rebuild the bin between a regeneration and a manual run probe, or the probe tests the tree the old bin was built from.
- The dsmod generator cannot bootstrap itself: `ds-stdlib` embeds `ambient.dsmod` through `include_bytes!`, so a tree without the artifact fails to compile `gen-ambient-dsmod` itself; seed any stale copy (even one from a tree whose sources have since moved) before regenerating.
- The serve boundary is name-addressed (2026-11-24): relocating a declaration in the ambient text serves identical facts — raw ids ride the names as a checked fast path, a name/id disagreement a loud drift refusal falling back to the fresh path, never a served wrong fact — pinned by the relocation-invariance gates in ds-stdlib and ds-cli. Declaration order stays load-bearing only where bytes address it: the dsmod splice's in-module plan walk, and the natives/tag table positions inside a hash-validated artifact.
- The dsmod regenerates last, after every code edit including `cargo fmt`, since fmt edits are content. An `ambient.ds` edit regenerates three artifacts in the identity's order: `ambient.ast` and `ambient.dsi` fold the identity by content and regenerate before the dsmod, or the serve gates (`SourceDrift`) fail. The payload is a pure function of the tree's content, so a lane regenerating over its own pre-merge or dirty tree commits bytes no merged checkout reproduces, which only another lane's clean checkout reports (the byte gate plus the `@std` `HashMismatch` cascade) — regenerate over the merged tree and re-verify a drift report on a clean checkout. A rebase conflicting on the three binary artifacts (`cannot merge binary files`): take either side to finish the rebase, then regenerate all three at the final base and fold them into the commit — the taken side's bytes are a placeholder the drift gates would reject.
- A payload-stale `ambient.dsmod` (regenerated before a final `ambient.ds` edit) fails outside the drift gates a lib-target run never sees: the package-run e2e refuses at the walk's dep validation (`dependency @std ... linked at <ambient hash> but resolves to content <artifact hash>`) while targeted suite runs stay green, since those gates live in the ds-cli bin test target. Attribute that `HashMismatch` to the checked-in artifact before suspecting the walk.
- The identity and the payload's source hash fold working-tree bytes as-is, so a checkout under `core.autocrlf=true` (the Git-for-Windows installer default) fails the dsmod drift gate on a clean tree, every byte outside the header identical. Keep lanes on `autocrlf=input` (or `false`), and read a same-size byte-gate refusal as line endings.
- An interrupted or parallel nextest run leaves an orphaned test exe locking its output (LNK1104): find the PID by image name and kill it by PID. `target/debug/ds` is shared across worktrees, so run-probes copy it to a private `/tmp` path first.
- A landing from a stale base silently deletes a sibling's just-landed lines, and a `status.md` milestone row is one table line every landing rewrites whole, so after landing, diff each touched doc item and milestone row against the pre-edit HEAD. Verify a claimed residual against merged main before reopening a closed item, since an unrebased worktree re-reports what a landed round already removed.
- Before deleting a clause in a docs-condensing pass, grep the repo for another landing spot: a binding sub-rule whose only doc home was the deleted sentence (memory-arc's gate conditions and ledger clauses, the compare-eagerness ruling) is lost until a full audit round restores it — condense it in place or move it into the pits file first.
- A cost recorded inside a ruling's prose is an open concern with no tracking home: the 2026-11-21 taxonomy ruling's tag-namespace cost vanished in a condense pass and reached the next ruling through the author's memory alone. A condense pass moves such a cost into the todo queue as an open item, and a ruling that accepts a cost writes that item in the same edit.
- A gate script piping cargo through tail and echoing `$?` reads tail's exit code, so every such green is vacuous: run gate scripts under `set -o pipefail` and capture cargo's own status.
- Two lanes can mint the same next free diagnostic code (DS2037 landed twice, renumbered to DS2038), so a lane minting a code greps merged main and the coordinator renumbers at merge. After every automated merge, grep for `refused_by` and diff3 markers: contested hunks leave doubled paragraphs, and a marker inside a code table fails every later compile.
- A doc merge can double a single-line paragraph with no conflict marker and no gate to catch it, and one merge can drop a heading outright: after merging the working records, grep each doc for repeated paragraph-start markers and for headings the diff shows leaving their line, not just diff3 markers.
- The one true test gate is `cargo nextest run --workspace --all-features`, since `--all-targets` fails at listing on `harness = false` benches (exit 104); clippy runs `--workspace --all-targets --all-features -- -D warnings`, and a new test file is selected with `cargo test --test <file>`. Every crate inherits the workspace package fields (clippy's cargo lint group fails on missing readme metadata), and CI runs fmt on nightly only.
- A toolchain update lints or reformats landed code, so verify a workspace clippy failure against pristine main (`git stash push -u`, rerun, pop) before fixing, and write or-patterns nested so fmt and clippy stop fighting. A red can also be the runner's own local toolchain on a pristine tree: a stale local stable clippy (1.98) linted 37 landed `cfg(test)` float asserts (`float_cmp`) that CI's run-time stable and the pinned nightly both accept, and a stable rustfmt ignores the nightly-only options (import granularity and grouping) and wants different bytes on canonical files — fmt pins nightly, clippy floats with CI's stable at run time, so reproduce a tooling red under the CI-pinned toolchain before fixing. An allocation-counting test reads a process-global counter, so its windows serialize inside the file behind a static Mutex.
- A failing crate masks every crate later in the build order, and a failing test target masks the same crate's other targets, so a clippy-drift fix surfaces its residue one wave at a time: enumerate the whole residue in one pass with `cargo clippy --keep-going` before fixing, and confirm a per-target fix with the target-selected run (a full run once skipped an error a targeted run still reported).
- An ambient-name landing re-greps its chosen names against the rebased corpus, since a corpus pin landing in between can declare a name the lane already picked and turn a clean typecheck item into a DS2005 exit-1.
- The run-path and LSP session compositions fold `bodied.ds` into the ambient text, so a user file cannot redeclare one of those private seam externs (DS2005) and a dot call resolves onto the ambient's file-private extern (DS4017); a pooled probe that wants the core ambient alone stages `ds_stdlib::AMBIENT_CORE_SOURCE` rather than the composed session set.
- Corpus fatality scoping is `ds check`-only while `ds run` is fully fatal, so a whole-file run golden needs a file whose items are all run-stage; a ruled refusal class lands in its own all-reject file or stays in the feature's e2e suite.
- Every top-level declaration — a struct the feature file introduces included — needs its own header stage line: `item_stages` pairs header and body positionally, so an unstaged struct silently unstages the whole file (the check gate's reject noise turns into an exit-1 failure at the reject item's own diagnostic).
- Close a round by re-measuring every corpus count on merged main, since worktree counts go stale as landings retire errors, and by rebuilding the corpus byte-diff base binary from the worktree's own HEAD, since a shared-cache binary from another commit shows phantom diffs.
- `cargo run --manifest-path fuzz/Cargo.toml` resolves the workspace only in the main checkout, since cargo walks past a worktree root's `exclude = ["fuzz"]` into main's manifest: append a temporary empty `[workspace]` table (revert it after) and run the seed generator with `fuzz/` as cwd.
- Cargo rejects a dev-dependency cycle as hard as a normal one, so moving a module above its consumer's crate moves its consumer-side tests with it; the move also shifts the ambient dsmod's build identity, so it lands with the regenerated artifact.
- A lane silent past its expected end is checked against the run's status and its run-dir `output-0.log` before any re-dispatch, since a completion wake can drop while the run finishes normally; the committed work sits on its branch either way. `git rebase --continue` needs `GIT_EDITOR=true` there, since the shared editor blocks the coordinator's shell.
- Manual `ds run` probes during parallel lanes pin `DS_CACHE` to a private dir the way every harness's `test_cache()` does, and a one-off anomalous golden is re-verified under a private cache before being called a compiler bug. The serve re-validates the artifact's source hash alone, so a compiler rebuild does not re-key a warm entry for an unchanged source — a stale splice once served a fixed derive bug's output verbatim (2026-11-21) — so clear the pinned dir between probe rounds after a rebuild.
- A probe's `timeout N` guard sends SIGTERM, which a parked ds interpreter outlives: three lane155 run probes each burned ~12h of CPU after their wrappers fired (the timeout process itself stayed as a zombie parent), and `ds dev --hot` watch probes intentionally never return with their strace wrappers living as long. Guard a probe with KILL semantics (`timeout -k <grace> N`), and a session's cleanup greps `ps` for the probe's ds binary path and kills by pid rather than trusting the wrappers to have died.
- Enabling a parked cache tier stays key-neutral only when the fold already carries the tier's shape marker: the enable touches no fold and every warm entry keeps its key, but the same edit re-keys the checked-in `ambient.dsmod` header (run-path sources fold by content), so the enable lands with the regenerated artifact. A cross-shape cache probe source — one program both the ambient and `--no-ambient` shapes check clean — composes from tag/struct/impl alone, since the scalars are ambient declarations (`int` solves only when the ambient declares it) and `tag int` would collide with the ambient's own.
- A dev-loop watch gate never re-baselines `loaded` by a blind read: an edit landing between the round that last set it and the watch's creation spends its inotify event before any watch exists, and a fresh read over the edited bytes then buries the change inside the gate — the session runs the old compile forever while every later window compares equal. The gate moves only through a round that compiles what it moves to (a reconcile read handed to the ordinary round), so an in-gap edit is either caught by the live watch or loaded by the reconcile (`crates/ds-cli/src/dev.rs`).
- CI stays one workflow file: two files sharing one `name:` share one concurrency group keyed by workflow name plus ref, so the duplicate's `cancel-in-progress` kills the other file's in-flight runs on every PR. A new CI job lands in `.github/workflows/ci.yml`.
- An edit spelled with a path that escapes the worktree root (`../../conformance/...` from inside a worktree) lands in the main checkout, not the worktree's own tree: keep every touched path inside the worktree, or the wrong tree goes green while the commit carries nothing.
- The ambient artifacts' regeneration order is load-bearing: the dsmod header's build id folds the bytecode crates' src trees plus ds-cli's run-path files, so any src edit after it was generated (even a test-assertion fix inside src/) re-keys it. Regenerate gen-ambient and gen-ambient-dsi first and gen-ambient-dsmod LAST, then commit all changed artifacts together — the package-serve path refuses a stale dsmod loudly ("the checked-in ambient artifact does not verify") while bare-script runs silently fall back to fresh lowering, so a bare-script-only gate never catches it.
- The corpus stage exemption reads PRIMARY labels alone: a rejection's secondary labels are evidence and may point into another file (the ambiguity refusal naming both declarations reaches the ambient, which stages nothing), so an all-labels rule turns every cross-file naming rejection fatal inside its own reject item while the primary-label rule keeps the staging exact.
- A doc-file conflict resolved by slicing the file's lines pays a sibling-line audit the gate never covers: docs carry no tests, and one merge that spliced `lines[a:b]` around a conflict block dropped the whole Natives row silently (the slice end ran one line past the block; a later merge's conflict on the same row exposed it). After any line-splice resolution, diff the resolved file against both parents for lines that vanished outside the marked block, and count the headline rows per section (each board's key rows) before committing.
