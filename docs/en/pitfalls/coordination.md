# Coordination, cargo cache, and gates

Working agreements for parallel lanes and the gates that judge a landing.

- One git worktree and branch per agent, additive-only edits to the root `Cargo.toml`, one shared `CARGO_TARGET_DIR` across worktrees, no git in the main checkout, and the coordinator as the only writer in main. Two lanes in one worktree let the second `checkout -b` switch the first off its branch and a later rebase target the wrong branch; carry the commits over with `git cherry-pick`.
- Verify a claimed residual against `main` before reopening a closed item: a lane reading an unrebased worktree can re-report something a landed round already removed.
- `Cargo.lock` conflicts resolve by deleting the file and regenerating it with `cargo check`; after any hand-resolved merge run `cargo clean -p <affected>` and a fresh check, since the shared target dir serves stale fingerprints that mask merge breakage.
- The shared target dir serves phantom artifacts, and `cargo clean -p <crate>` plus a fresh build is the remedy (`touch` plus rebuild, or a private `CARGO_TARGET_DIR` for a change window). Symptoms: a workspace test linking a parallel worktree's rlib; a build script panicking over an input its own checkout names differently (a parallel worktree's ds-cli build.rs running against this tree's manifest — its `RUN_PATH_FILES` list named a file this checkout has never held), `cargo build -p <downstream>` recompiling downstream while a touched upstream stays stale (build the touched crate directly and read its `Compiling` line); feature-differentiated builds poisoning each other's ds-abi artifacts; a public-API change landing during parallel builds, where identical metadata hashes share one output path, so downstream compiles fail E0004 on a `Uop` variant no checkout contains and no solo `cargo check` reproduces it; stale test binaries whose compile-time paths dangle, either `env!("CARGO_BIN_EXE_ds")` into a garbage-collected out dir (bin-spawning ds-cli tests fail `NotFound` in one big nextest run while each passes alone) or `env!("CARGO_MANIFEST_DIR")` into a removed lane's worktree. The conformance gates resolve the corpus at run time via the dev-only `ds-corpus-path` crate — compile-time checkout first, else a walk up from the test binary to a checkout root holding `conformance/` — so a stale lane's binary re-anchors instead of failing; every corpus-reading test or bench must go through it, never a baked `env!("CARGO_MANIFEST_DIR")` join. The check must validate the named file, not only the directory: `file()` first checked only `dir().exists()`, so a stale cross-lane bake whose lane lacked a file this lane had just added answered a dangling path and the spawned `ds check` failed `No such file` while the test blamed the exit code; the file-level fallback (the shift-round landing) also needs an ancestor of the shared target dir to hold `conformance/` when the target dir sits outside every checkout root — on this host a `conformance` symlink at `/root` anchors the walk-up for lanes adding corpus files.
- The shared target dir also shares `ds-corpus-path`'s rlib, and the crate bakes `env!("CARGO_MANIFEST_DIR")` at its own compile time, so identical sources let an earlier lane's build keep serving that lane's corpus to every worktree's tests — corpus edits stay invisible to the editing lane's own gates until `cargo clean -p ds-corpus-path` plus a fresh build rebakes the path (the compile-time-checkout branch answers a wrong-but-existing path, so the walk-up fallback never runs).
- A Cargo.lock change silently changes ds-cli's `DS_BUILD_ID`: build.rs folds the lock into the digest but does not watch it, so a warm shared target dir keeps the old identity and masks the ambient dsmod drift gate until a cold build fails it; after a lock-touching landing run the gen-ambient-dsmod example and commit the regenerated artifact (its payload must stay byte-identical, the header alone moves).
- The build identity also folds each bytecode crate's source tree by file path (the digest map is keyed on `ds-<crate>/src/<path>`), so adding, renaming, or moving any source file in those trees moves `DS_BUILD_ID` the same way a lock change does and re-keys the checked-in `ambient.dsmod` at its 16-byte header alone. A full rehearsal of the ds-lower `func.rs` split moved 29 pattern methods into a `func/pattern.rs` child module with fmt and clippy clean and the regenerated artifact's payload byte-identical, and the two ambient gates still failed on the header alone: a tree-reshaping round commits the regenerated artifact in the same landing (run the gen-ambient-dsmod example), and the gates failing there name the identity move, never a bytecode change.
- An interrupted or parallel nextest run leaves an orphaned test exe locking its output (LNK1104); find the PID by image name and kill it by PID. `target/debug/ds` is shared across worktrees and clobbered by parallel builds, so run-probes copy it to a private `/tmp` path first.
- A lane landing a docs edit from a stale base silently deletes a sibling's just-landed lines (the comptime round-two commit rewrote todo item 57 from a base predating the interpolation slice and dropped item 60 whole): after landing, diff the touched doc's whole item list against the pre-edit HEAD, not only your own hunks, and never leave the deleted item's blank-line scar behind.
- Two parallel lanes can each mint a diagnostic code at the next free number and collide at merge (the comptime-admission and default-annotation rounds both landed DS2037; main kept the first-merged spelling, the second renumbered to DS2038 across code, tests, and every doc citation): the coordinator renumbers at merge with a repo-wide context grep so earlier-context citations keep their code, and a lane minting a code greps merged main for its number before landing.
- The coordinator's automated merges leave `// refused_by: ... · collision: ...` marker lines beside their contested hunks and keep both sides of a doubled paragraph where neither deleted the other's lines, so after a merge grep the tree for `refused_by` and fold any doubled bullet back into one before the landing rides.
- Never run `cargo fmt` outside your own worktree: a stray fmt in the main checkout rewrites tracked files and breaks merges. A fmt inside your own worktree can still rewrite files you never touched (main lands occasionally unformatted), so review `git diff` after fmt and revert everything outside your lane.
- The one true test gate is `cargo nextest run --workspace --all-features`; `--all-targets` fails at listing on `harness = false` benches (nextest executes them during list, exit 104) and `test = false` does not filter explicit target selection. Clippy runs `--workspace --all-targets --all-features -- -D warnings`, and a new test file is selected with `cargo test --test <file>`, since nextest name filters match test names.
- An allocation-counting test reads a process-global counter, so its measurement windows must serialize inside the file (a static Mutex each test holds for its whole body): nextest isolates each test in its own process, but a plain `cargo test` run shares one, and two concurrent windows read each other's counter resets (a racing window answers a false low count, flipping the pin run to run).
- Keep `cargo doc` in the verification loop beside clippy and nextest: a single-token bracket reference such as `[C4]` in a doc comment parses as a broken intra-doc link, so write `(C4)` or a slash form, private items included.
- Every crate must inherit the workspace package fields, because clippy's cargo lint group fails on missing readme metadata. Nightly clippy rejects `map(format!).collect::<String>()` and `push_str(&format!())`; compose strings with plain `format!`. CI runs fmt on nightly only because `rustfmt.toml` uses unstable options.
- Keep the corpus header and its items in one order, pinned by `every_corpus_header_aligns_with_its_items` over every conformance file: a count mismatch (an item added without its header line) makes `item_stages` answer None, so the whole file runs unstaged and `ds check` reports every leftover as fatal (`modules_hash_core` ran that way since its seeding), and a right-count-wrong-order header passes the positional zip by luck alone. List header entries in source order and pair a naming item with its position's id; a comment-only body stages `unresolved` (the seed `ds-pkg-manifest` item staged `m7` against one).
- Close a round by re-measuring every corpus count on merged main, since worktree counts go stale as parallel landings retire errors, and rebuild the corpus byte-diff base binary from the worktree's own HEAD, since a shared-cache binary from another commit shows phantom diffs in exactly the files that commit touched.
- The toolchain can drift past what validated main: a clippy update can begin firing a lint on landed code and a rustfmt update can split long flat or-patterns across lines that the new clippy then lints as `unnested_or_patterns` in a file the lane never edited — verify a workspace clippy failure against pristine main (`git stash push -u`, rerun, pop) before concluding your diff broke it, and write or-patterns nested so fmt and clippy stop fighting.
- `cargo run --manifest-path fuzz/Cargo.toml` resolves the workspace only in the main checkout: from a worktree, cargo walks past the worktree root's `exclude = ["fuzz"]` into the main checkout's manifest and refuses. Run the fuzz tools from a worktree with a temporary empty `[workspace]` table appended to `fuzz/Cargo.toml` (revert it after — the emitted artifacts depend only on the crates, not the manifest), and run the seed generator with the `fuzz/` directory as cwd so its relative `corpus/` output lands in the right place.
- Cargo rejects a dev-dependency cycle as hard as a normal one (a scratch pair with `a` depending on `b` and `b` dev-depending on `a` fails resolution), so moving a module above its consumer's crate moves its consumer-side tests with it: the derive engine's move from ds-check to ds-meta left ds-check's tests unable to reach `expand_derives`, and the expansion-dependent scope and conformance-gate tests moved to ds-meta's tests rather than staying behind; the same move shifts the ambient dsmod's build identity (the digested bytecode crates change), so a crate move lands with the regenerated artifact, payload byte-identical and the 16-byte header alone moving.
