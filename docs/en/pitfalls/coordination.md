# Coordination, cargo cache, and gates

Working agreements for parallel lanes and the gates that judge a landing.

- One git worktree and branch per agent, additive-only edits to the root `Cargo.toml`, one shared `CARGO_TARGET_DIR` across worktrees, no git in the main checkout, and the coordinator as the only writer in main. Two lanes in one worktree let the second `checkout -b` switch the first off its branch and a later rebase target the wrong branch; carry the commits over with `git cherry-pick`.
- Verify a claimed residual against `main` before reopening a closed item: a lane reading an unrebased worktree can re-report something a landed round already removed.
- `Cargo.lock` conflicts resolve by deleting the file and regenerating it with `cargo check`; after any hand-resolved merge run `cargo clean -p <affected>` and a fresh check, since the shared target dir serves stale fingerprints that mask merge breakage.
- The shared target dir serves phantom artifacts, and `cargo clean -p <crate>` plus a fresh build is the remedy (`touch` plus rebuild, or a private `CARGO_TARGET_DIR` for a change window). Symptoms: a workspace test linking a parallel worktree's rlib; `cargo build -p <downstream>` recompiling downstream while a touched upstream stays stale (build the touched crate directly and read its `Compiling` line); feature-differentiated builds poisoning each other's ds-abi artifacts; a public-API change landing during parallel builds, where identical metadata hashes share one output path, so downstream compiles fail E0004 on a `Uop` variant no checkout contains and no solo `cargo check` reproduces it; stale test binaries whose compile-time paths dangle, either `env!("CARGO_BIN_EXE_ds")` into a garbage-collected out dir (bin-spawning ds-cli tests fail `NotFound` in one big nextest run while each passes alone) or `env!("CARGO_MANIFEST_DIR")` into a removed lane's worktree (the ds-check conformance gate reads its corpus from a deleted directory).
- An interrupted or parallel nextest run leaves an orphaned test exe locking its output (LNK1104); find the PID by image name and kill it by PID. `target/debug/ds` is shared across worktrees and clobbered by parallel builds, so run-probes copy it to a private `/tmp` path first.
- Never run `cargo fmt` outside your own worktree: a stray fmt in the main checkout rewrites tracked files and breaks merges.
- The one true test gate is `cargo nextest run --workspace --all-features`; `--all-targets` fails at listing on `harness = false` benches (nextest executes them during list, exit 104) and `test = false` does not filter explicit target selection. Clippy runs `--workspace --all-targets --all-features -- -D warnings`, and a new test file is selected with `cargo test --test <file>`, since nextest name filters match test names.
- Keep `cargo doc` in the verification loop beside clippy and nextest: a single-token bracket reference such as `[C4]` in a doc comment parses as a broken intra-doc link, so write `(C4)` or a slash form, private items included.
- Every crate must inherit the workspace package fields, because clippy's cargo lint group fails on missing readme metadata. Nightly clippy rejects `map(format!).collect::<String>()` and `push_str(&format!())`; compose strings with plain `format!`. CI runs fmt on nightly only because `rustfmt.toml` uses unstable options, and the nightly rustfmt stderr quirk around `single_line_if_else_max_width` is harmless.
- Keep the corpus header and its items in one order, pinned by `every_corpus_header_aligns_with_its_items` over every conformance file: a count mismatch (an item added without its header line) makes `item_stages` answer None, so the whole file runs unstaged and `ds check` reports every leftover as fatal (`modules_hash_core` ran that way since its seeding), and a right-count-wrong-order header passes the positional zip by luck alone. List header entries in source order and pair a naming item with its position's id; a comment-only body stages `unresolved` (the seed `ds-pkg-manifest` item staged `m7` against one).
- Close a round by re-measuring every corpus count on merged main, since worktree counts go stale as parallel landings retire errors, and rebuild the corpus byte-diff base binary from the worktree's own HEAD, since a shared-cache binary from another commit shows phantom diffs in exactly the files that commit touched.
- The host's `GIT_EDITOR` is nvim and interactive git (a bare `rebase --continue`, a commit prompt) hangs the shell-proxy session; kill the nvim PID and rerun with `GIT_EDITOR=true`.
- `flock -c` parses its command string with `$SHELL` (fish here), so `$?`, `${PIPESTATUS[0]}`, and bash-only spellings inside the flock string break; put the payload in a bash script file and invoke only `flock ... -c 'bash /tmp/script.sh'`.
