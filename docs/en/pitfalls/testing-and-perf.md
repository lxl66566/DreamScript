# Fuzzing and benchmarks

- cargo-fuzz has no automatic dictionary discovery: pass `-dict=` explicitly. libFuzzer on Windows hangs at exit after `-max_total_time` unless `-runs=<n>` is also set.
- A Rust panic aborts before libFuzzer's deadly-signal callback registers, so crash artifacts and tmin miss it; recover the input from the panic message.
- Valid dsmod modules are unguessable by mutation because the content hash gates acceptance: generate seeds with `fuzz/tools/gen_dsmod_seeds.rs` before fuzzing the reader, and `git add -f` a corpus addition since `fuzz/corpus` is gitignored yet tracked. The reader rejects non-canonical section-directory order (70-byte reproducer kept in the corpus). A format bump re-runs the seed generator and re-patches the reproducer's version byte (its rejection fires at the directory, before the payload), and a byte-patch test's needle must dodge the fixed header: format version 4 followed by three zero bytes is itself `[4, 0, 0, 0]`. Any change to the accepted-bytes set re-runs the seed generator, a payload-version bump as much as a format bump — a stale corpus dies silently at the payload-version gate, its seeds rejected and the never-panic property passing vacuously, so nothing fails until the coverage is already gone.
- Cross-heap count releases ride exact claim ownership: `Heaps::dec` drops a foreign word's count only when the running fiber's ledger holds the row (a freed id still traps), same-heap decs keep the gift-count discipline, and the death-walk doors dec through the claims-taken `dec_walk`. A hand-assembled extra `rc_dec` on a foreign word otherwise steals a capture edge and frees the string under a live closure (`a stored element reference is live`; reproducer `regression-stored-element-ref-dead.bin`, pinned by the corpus-seed sweep in `crates/ds-vm/tests/fuzz_vm_fibers.rs`). `Heaps::concat`'s same-store fast path must keep its `claim_result`, or the STRCAT birth count strands on no ledger.
- The checker generator leg (`fuzz_check_gen` over `fuzz/check_gen.rs`, 240-seed nextest mirror in CI) biases declarations to the well-typed surface with weighted wrong splices; the linearity audit walk stays linear in program size, and a nested loop's duplicate round must stay skipped.
- Give a census field the mirror asserts `> 0` a structural carrier rather than a roll chain, since the draws multiply and left fields at 0-3 over the 240-seed sweep: at least one declared struct per program, a nested-carrier struct whose fields include an earlier one, and a guaranteed Int tuple payload per enum, with the scrutinee preferring dispatch locals half the time.
- A sanitizer leg multiplies memory by its worker count: size the workers to host RAM and keep the host quiet — a multi-worker ASan leg was OOM-killed under parallel-agent load.
- The `fuzz_vm` run limit stays stack words, not steps (the VM has no step budget), so termination rests on the generator's invariants: every backward edge passes the loop template's decrement exactly once, no jump from before a loop block lands inside it, the spawn tree stays depth one, and every switch re-enters a parked fiber at pc+1. A pre-loop jump drawn onto the decrement skips the countdown Kinms and enters the loop on stale recycled-chunk words, and a stale counter never reaches zero, so the join driver hangs; the retarget maps such landings onto the loop entry, pinned by the sweep plus the seed in `crates/ds-vm/tests/fuzz_vm_fibers.rs`. A uop ABI change re-audits the emit path's retargeting rules (forward targets against the fixed-part lower bound, stray loop-tail landings retargeted onto the decrement).
- A gone joiner's boundary answer surfaces to the drive's host, never switching into a continuation-less fiber (pinned in `crates/ds-vm/tests/nursery_joiner_reentry.rs`).
- The execution-source generator leg (`fuzz_exec_gen` over `fuzz/exec_gen.rs`): the checker refuses a guard or arm literal that an earlier arm's failed test already excluded, and the refusal cascades into the following binder arm's union-typed interpolation, so tested literals stay disjoint across arms; a rejection-redraw loop spins forever on a degenerate all-zero input, so every distinct-value draw is a bounded redraw with a deterministic forward-walk fallback; a root frame's native tail transfer abandons its staged owned words, so an interpolated argument on a unit main's final println stays live and a heap-drain assert needs a constant-string closer on the last statement.
- `substring`/`char_at`/`len` answer from a cached per-string char map, so string-heavy benchmarking is unblocked; string lengths stay tracked arithmetically until generic `len[t]` lowers at M6.
- Rust f64 Display prints `250.0` as `250` while Python and Lua print `250.0` and Lua tostring is `%.14g`: float goldens print values every printer agrees on (odd fourths). `ds run` echoes the unit entry result as a trailing `0` line, absorbed by the `^result:` extraction rule.
- `benchmarks/ab.sh` times whole-process wall clock, so its percentages understate in-VM deltas symmetrically.
- A probe cannot spell a float negation (only int negation and boolean not are in the lowering contract), so the float fold's `-0.0` operand is computed arithmetically — `0.0 / (0.0 - 1.0)` — pinned in the ds-lower derive_hash_e2e suite's equality print, never as a negated literal.
- Attribute an adverse A/B wall delta to per-function Ir before hunting dispatch or semantics: the STRCAT slice's +32% loops-arith was 82% the scalar READ path losing its inlining when the `Value::Arena` variant widened the enum and 18% execute growth, while the arm placement hunt moved nothing. Growing the Word/Value set or any helper the hot loop calls can flip an inlining decision wholesale, so a word-set change re-runs the kernel A/B with whole-process callgrind attribution, never perf sampling, which misattributes leaf callees at 2.5k-sample counts.
- Re-baseline a pin on the committed tree before litigating drift against a number that lives in prose: a round's absolute-Ir figures are pre-commit measurements (the dispatch round's scalar_loop pin recorded 6.895G where its own commit and main both measure 7.295G).
- A deletion's whole-process win can exceed the deleted pass's own inclusive attribution: the cold run's derive clone carried 414k inside the expansion pass, but deleting it measured -707k (-10.5%) whole-process because the cloned Vecs' frees and the originals' early drops run outside the pass — size a deletion whole-process, never from the pass's inclusive figure.
- Whole-process wall on the Windows host is floor-dominated for cold start: `ds --version` measures 34.2ms against trivial's 36.3ms, so the entire front-end-plus-VM pipeline occupies ~2.1ms — attribute a pipeline change under that floor by Ir from the recorded callgrind profile on this host, and claim wall only where the delta clears the floor's own spread.
- The checked-prefix serve path costs more Ir than the fresh front-end compute it replaces at trivial scale: on the Linux release binary, whole-process callgrind measured 9.80M Ir fresh (`--no-cache`), 12.06M cold (the ambient `.dsi` tier serving plus the user-prefix store — the store alone ~0.85M), and 11.21M on a prefix hit, with the hit's wall median beating cold by 124 µs (4088 vs 4212, n=31 interleaved), inside the run-to-run band, so no wall saving is claimed. The earlier record that serving the ambient `.dsi` deleted ~0.9M Ir is superseded: the comptime-residual closures made the fresh ambient check cheaper while the span-keyed record rebuild and the per-file payload made the serve costlier, so the serve's win profile belongs to programs whose ambient parse and check are real work — re-attribute on a real-sized program before citing the prefix cache as a cold-start win.
- Whole-process callgrind Ir is a noisy per-run sample, so a kernel A/B treats a sub-0.3% Ir delta as flat and repeats before hunting it (three back-to-back runs spanned 9.35-9.38G with the base-vs-main sign flipping). A layout verdict for a stable wall gap at flat Ir comes from perf-stat aggregate counters, never callgrind's simulated cache model: containers at +22% wall measured equal hardware instructions and branch-misses with +22.6% cycles and doubled icache fetches, while the simulation guessed a +74% records mispredict jump.
- The pin-bake harness (`crates/ds-pins/tests/pin_bake.rs`) asserts the nine gungraun pin kernels' whole-process Callgrind Ir against the committed `PINS` table on every release-profile gate run (`cargo nextest run --cargo-profile bench -p ds-pins --test pin_bake`; debug profiles and valgrind-less hosts skip), so a worktree-vs-tree divergence fails the gate. A count past the ±0.1% band fails with the measured value; re-baseline with `PIN_BAKE_RECORD=1` and update `PINS` in the same commit that changed the codegen. The `PINS` table is keyed to the exact binary the canonical invocation builds under the repo toolchain with no `RUSTFLAGS`: a different rustc, valgrind, or flags produces a different binary and a stable drift across commits, so a gate failure from a scratch environment is litigated against the environment first (the rustc and valgrind versions, `RUSTFLAGS`) before the tree is suspected or the table is re-baselined. Not every drift is a codegen change: a native-table append alone is expected to be pure layout (the compare-natives round flipped `serving_cats` +0.53% back to its pre-derive-ord value), but confirm with a gate run plus whole-process Ir attribution before re-baking on that expectation, a native round landing its re-bake in the same commit once the attribution agrees instead of litigating the delta (the hash-natives append confirmed the class again: `serving_cats` -0.52% with every VM function flat and the whole delta inside libc memcmp at an unchanged call count, the data-dependent compare's early exit moving with the shifted inlining boundaries).
- gungraun's `main!` defines `fn main` itself, so wrapping the invocation in a `fn main()` runs nothing (exit 0, no table); its macros' fully-qualified std paths need a targeted `unused_qualifications` allow in the bench file, and Callgrind pinning needs `[profile.bench] debug = true`. A new pin kernel and its `PINS` row go to `crates/ds-pins`, never `ds-vm`'s benches, and every bench group states its unit: `bench_module_dispatch` measured ~99% `Vm::run` fixed setup until that term became its own `run_setup` group.
- Measure a dec position on a fresh production per iteration (a concat result), not on an interned literal: the release-at-use spelling drops the count to zero before the re-acquire and pays teardown plus re-intern every iteration (1568 Ir/iteration), while the held spelling keeps the interned count at one (the two differ by ~0; `crates/ds-pins/benches/loop_claims.rs`). The loop-claims hold itself is free: the carried claim is a frame fact and the rollover dec at the overwrite is the previous content's exact death.
- A large hot loop can be the reason an I-cache signature appears: the maps kernel measured +45% wall with FEWER instructions after the intern change, and indexing the same rows then took it from 150 ms to 51 ms. Classify a fetch-bound gap by whether the hot loop still contains removable work before calling it layout.
- Wholesale inlining flips are the dominant wall risk and move both directions inside one round (92% fewer L1-icache loads on fib, 781% more on float-loop at 10% FEWER instructions, cache and branch misses flat). An `#[inline]` contract on a reader the dispatch arms call, or a wider inline answer payload, is the same class as widening the Value enum: kernel A/B plus whole-process counters, never a single kernel's wall number.
- A layout regression recorded on one target can invert on another: the float-loop +22%-cycles/8.8x-L1I signature, recorded on the Linux perf-stat target, does not reproduce on the Windows target (the same pair runs 4-6% FASTER there), and a Windows-side bisect of the named inline suspects returns only exoneration — the suspects sit inside the ±2% floor that two byte-different builds of one source establish. Bisect a layout signature on the target that recorded it; a different target's wall numbers can only exonerate. The exonerated `#[inline]` contracts stayed load-bearing for fib (+4-5% wall when dropped), so an exoneration round ends with the contracts kept, not removed on suspicion.
- The load-op fusion's wall A/B stayed inside the noise band while the census says ~14% of the stream's dispatch instances fuse: every non-fusing KIMM/KCONST pays the peek, and growing the two arms can flip layout, so the census share bounds dispatch elimination and never promises wall. Loops-arith (the most fused kernel, 18.7%) came out consistently 3-4% slower across four interleaved ab.sh passes — under the 5% bar, but one-directional, so the Linux Ir re-bake adjudicates whether the instruction count actually dropped before any layout hunt starts.
- A worktree sharing the workspace CARGO_TARGET_DIR leaves its fingerprints behind after removal, and a stale test binary baked with the removed tree's absolute paths can be selected as fresh by the next main-checkout build: every ds-cli integration test then fails at process spawn with NotFound (the removed tree's crates/ds-cli is the missing directory, not the ds binary, and the failure set is deterministic per invocation shape). After deleting a worktree that shared the target dir, wipe the poisoned profile directory (removing target/debug keeps the bench-profile pin artifacts intact) and rebuild before trusting a red full-suite run as evidence.
- A deleted worktree is the poison event, and deletion is avoidable: keep one persistent worktree per writer lane across rounds (repoint its HEAD or re-branch in place, never remove the directory), so the absolute paths baked into shared-target test binaries stay valid and a stale-but-fresh-selected binary from another checkout behaves identically to a local rebuild (its fingerprint only matches identical source content). If a shared-target worktree must truly die, wipe the poisoned profile directory (removing target/debug keeps the bench-profile pin artifacts intact) and rebuild before trusting a red full-suite run as evidence.
- A wall A/B on the gate host is excursion-hostage: float-loop throws single runs of +4..+64% cycles at identical instructions (IPC 5.4 to 3.3, icache misses flat) at a few percent per run on every layout variant including the unperturbed base, so only medians of >=10 interleaved reps per side attribute, and perf-stat instructions must match before any cycles delta is read. Ambient .text placement is flat there (inert pads to 256KB shifting `Vm::execute` and breaking its page alignment, plus environment padding, all sat inside 0.7% at e3fa48d), so a surviving median delta at equal instructions is a code-shape effect of the change, not a layout lottery; the cgu/link-order class cannot vary because the release profile pins codegen-units=1. The host's L1-icache-loads/-misses counts are themselves unstable between passes for the same binary (containers base measured 578k then 200k misses at flat cycles), so icache counters corroborate, never decide.
- The checked-in cold-start artifacts re-key each other through the build identity: `ambient.dsi` and the AST blob sit under ds-stdlib/src, so their bytes fold into the digest the `ambient.dsmod` header pins — after any change that touches the `.dsi` payload (a data-model change, a ds-check table change, an `ambient.ds` edit) regenerate the `.dsi` first (`cargo run -p ds-stdlib --example gen-ambient-dsi`) and the dsmod last (`cargo run -p ds-cli --example gen-ambient-dsmod`), and re-run the dsmod regen after every later bytecode-crate or run-path source edit (a clippy fix included) or its byte gate fails on the identity fold, not the payload.
