# Fuzzing and benchmarks

- cargo-fuzz has no automatic dictionary discovery, so pass `-dict=` explicitly; libFuzzer on Windows hangs at exit after `-max_total_time` unless `-runs=<n>` is also set.
- `cargo fuzz run` on Windows dies at spawn with STATUS_ACCESS_VIOLATION when its own `-artifact_prefix` path ends in a backslash (the quoting swallows the closing quote), so build with `cargo fuzz build` and run the target binary directly with `-runs`/`-max_total_time`; and `fuzz/` under a lane worktree cannot build standalone — cargo's workspace discovery walks past the worktree root's `exclude` into the main tree and claims membership — so a lane's bounded campaign runs from a scratch copy outside the repo with the crate path deps rewritten to absolute worktree paths.
- A Rust panic aborts before libFuzzer's deadly-signal callback registers, so crash artifacts and tmin miss it: recover the input from the panic message.
- Valid dsmod modules are unguessable by mutation because the content hash gates acceptance, so generate seeds with `fuzz/tools/gen_dsmod_seeds.rs` and `git add -f` a corpus addition (`fuzz/corpus` is gitignored yet tracked). Any change to the accepted-bytes set re-runs the generator, since a stale corpus's seeds die silently at the gate.
- A byte-patch test's needle must dodge the fixed header: format version 4 followed by three zero bytes is itself `[4, 0, 0, 0]`, and a corruption fixture must carry the bumped version byte or the reader rejects it before the fixture's own corruption runs.
- Cross-heap count releases ride exact claim ownership: `Heaps::dec` drops a foreign word's count only when the running fiber's ledger holds the row, so a hand-assembled extra `rc_dec` on a foreign word frees the string under a live closure (reproducer `regression-stored-element-ref-dead.bin`, pinned in `crates/ds-vm/tests/fuzz_vm_fibers.rs`).
- The checker generator leg (`fuzz_check_gen` over `fuzz/check_gen.rs`, a 240-seed nextest mirror in CI) biases declarations to the well-typed surface with weighted wrong splices; the linearity audit walk stays linear in program size, and a nested loop's duplicate round must stay skipped.
- A census field the mirror asserts `> 0` needs a structural carrier rather than a roll chain, since the draws multiply: at least one declared struct per program, a nested-carrier struct whose fields include an earlier one, and a guaranteed Int tuple payload per enum.
- A sanitizer leg multiplies memory by its worker count: size the workers to host RAM and keep the host quiet, since a multi-worker ASan leg was OOM-killed under parallel-agent load.
- The `fuzz_vm` run limit stays stack words, not steps (the VM has no step budget), so termination rests on the generator's invariants: every backward edge passes the loop template's decrement exactly once, no jump from before a loop block lands inside it, the spawn tree stays depth one, and every switch re-enters a parked fiber at pc+1. A jump landing on the decrement enters the loop on stale chunk words and hangs the join driver.
- The execution-source generator leg (`fuzz_exec_gen` over `fuzz/exec_gen.rs`): tested literals stay disjoint across arms, since the checker refuses a literal an earlier arm's failed test already excluded and the refusal cascades into the binder arm's union-typed interpolation; every distinct-value draw is a bounded redraw with a deterministic fallback.
- Rust f64 Display prints `250.0` as `250` while Python and Lua print `250.0`: float goldens print values every printer agrees on (odd fourths). `ds run` echoes the unit entry result as a trailing `0` line, absorbed by the `^result:` extraction rule.
- `benchmarks/ab.sh` times whole-process wall clock, so its percentages understate in-VM deltas symmetrically.
- A probe cannot spell a float negation (only int negation and boolean not are in the lowering contract), so the float fold's `-0.0` operand is computed arithmetically (`0.0 / (0.0 - 1.0)`), pinned in the ds-lower derive_hash_e2e suite's equality print.
- Attribute an adverse A/B wall delta to per-function Ir before hunting dispatch or semantics: the STRCAT slice's +32% loops-arith was 82% the scalar READ path losing its inlining when the `Value::Arena` variant widened the enum, while the arm placement hunt moved nothing. A word-set change re-runs the kernel A/B with whole-process callgrind attribution, never perf sampling.
- Re-baseline a pin on the committed tree before litigating drift against a number that lives in prose: a round's absolute-Ir figures are pre-commit measurements (the dispatch round's scalar_loop pin recorded 6.895G where its own commit and main both measure 7.295G).
- A deletion's whole-process win can exceed the deleted pass's own inclusive attribution: the cold run's derive clone carried 414k inside the expansion pass, but deleting it measured -707k (-10.5%) whole-process, since the cloned Vecs' frees run outside the pass — size a deletion whole-process.
- Whole-process wall on the Windows host is floor-dominated for cold start: `ds --version` measures 34.2ms against trivial's 36.3ms, so the whole pipeline occupies ~2.1ms — attribute a pipeline change under that floor by Ir from the callgrind profile, and claim wall only where the delta clears the floor's own spread.
- The checked-prefix serve path costs more Ir than the fresh compute it replaces at trivial scale (9.80M fresh, 12.06M cold, 11.21M on a hit, the hit's wall median 124 µs ahead inside the noise band), so its win profile belongs to programs whose ambient parse and check are real work; re-attribute on a real-sized program before citing the cache as a cold-start win.
- Whole-process callgrind Ir is a noisy per-run sample, so a kernel A/B treats a sub-0.3% Ir delta as flat and repeats before hunting it (three back-to-back runs spanned 9.35-9.38G with the sign flipping). A layout verdict for a stable wall gap at flat Ir comes from perf-stat aggregate counters, never callgrind's simulated cache model.
- A cold-start A/B whose patched side edits any ds-cli run-path file (even a measurement probe alone) moves the ambient dsmod's build identity, so the splice falls back silently to the fresh ambient lowering and the patched side carries a phantom +11M Ir whole-process; regenerate the artifact for the patched side (cargo clean -p ds-cli, then the gen-ambient-dsmod example) before reading any number, because nothing in the run's output distinguishes the fallback. A splice-off comparison side that bypasses the serve before it (never calling `serve()`) needs no regeneration — the artifact's identity never enters the run.
- A silent splice fallback defeats its own gates: the fallback answers the fresh module, so served-vs-fresh byte equality, the install-shape assertions, and even run-output comparisons all pass vacuously, and the artifact can sit dead while every compile pays the serve plus the failed attempt's plan-and-linearity pass (the ambient splice's measured +4.0M Ir per member compile was exactly that dead-splice cost, not the splice's own). Attribute a suspected fallback by the call graph's call counts, never an Ir delta alone — the dead splice showed `linearity_check` at 34x against 17x over a 17-compile graph — and pin the splice's success with a marker a gate can read (`Lowered::spliced`), since byte-identity is the fallback's contract. The refusal class that hid it: an artifact row naming a structural atom (`list[byte]`, the json span members) that only the body walk the splice skips ever mints, so the seed must accept rows that resolve to no atom of the compiling package's universe and the row set stays pinned by the build identity plus the byte-comparison gates.
- The pin-bake harness (`crates/ds-pins/tests/pin_bake.rs`) asserts the nine gungraun pins' whole-process Callgrind Ir against the committed `PINS` table on every release-profile run (`cargo nextest run --cargo-profile bench -p ds-pins --test pin_bake`; debug profiles and valgrind-less hosts skip), failing past the ±0.1% band; re-baseline with `PIN_BAKE_RECORD=1` in the commit that changed the codegen. The table is keyed to the canonical binary with no `RUSTFLAGS`, so litigate a scratch failure against the toolchain first.
- gungraun's `main!` defines `fn main` itself, so wrapping the invocation in a `fn main()` runs nothing; its macros' fully-qualified std paths need a targeted `unused_qualifications` allow, and Callgrind pinning needs `[profile.bench] debug = true`. A new pin kernel goes to `crates/ds-pins`, and every bench group states its unit (`bench_module_dispatch` measured ~99% fixed setup until it became its own `run_setup` group).
- Measure a dec position on a fresh production per iteration (a concat result), not an interned literal: the release-at-use spelling drops the count to zero before the re-acquire and pays teardown plus re-intern every iteration (1568 Ir/iteration; `crates/ds-pins/benches/loop_claims.rs`).
- A large hot loop can be the reason an I-cache signature appears: the maps kernel measured +45% wall with FEWER instructions after the intern change, and indexing the same rows took it from 150 ms to 51 ms. Classify a fetch-bound gap by whether the hot loop still contains removable work before calling it layout.
- Wholesale inlining flips are the dominant wall risk and move both directions inside one round (92% fewer L1-icache loads on fib, 781% more on float-loop at 10% FEWER instructions): an `#[inline]` contract on a reader the dispatch arms call is the same class as widening the Value enum, so kernel A/B plus whole-process counters.
- A layout regression recorded on one target can invert on another: the float-loop +22%-cycles/8.8x-L1I signature does not reproduce on Windows, where the same pair runs 4-6% FASTER, and a bisect there returns only exoneration inside the ±2% floor two byte-different builds establish. Bisect on the target that recorded the signature, and keep a cleared contract (+4-5% wall for fib).
- The load-op fusion's wall A/B stayed inside the noise band while the census says ~14% of the stream's dispatch instances fuse: every non-fusing KIMM/KCONST pays the peek, and growing the two arms can flip layout, so the census bounds dispatch elimination and never promises wall.
- A deleted worktree is the poison event and is avoidable: keep one persistent worktree per writer lane (repoint its HEAD, never remove the directory), since a stale test binary baked with a removed tree's absolute paths can be selected as fresh and every ds-cli integration test then fails at process spawn with NotFound.
- A gone joiner's boundary answer surfaces to the drive's host, never switching into a continuation-less fiber (pinned in `crates/ds-vm/tests/nursery_joiner_reentry.rs`).
- A wall A/B on the gate host is excursion-hostage: float-loop throws single runs of +4..+64% cycles at identical instructions on every layout variant including the base, so only medians of >=10 interleaved reps per side attribute, and perf-stat instructions must match before any cycles delta is read. Ambient `.text` placement is flat there and codegen-units is pinned to 1, so a median delta at equal instructions is a code-shape effect.
- The checked-in cold-start artifacts re-key each other through the build identity: `ambient.dsi` and the AST blob sit under ds-stdlib/src, so their bytes fold into the digest the `ambient.dsmod` header pins. After any change touching the `.dsi` payload regenerate the `.dsi` first (`gen-ambient-dsi`) and the dsmod last (`gen-ambient-dsmod`).
- The dsmod regeneration must come after the final `cargo fmt`, not just after the last source edit: rustfmt rewriting any bytecode-crate file moves the build identity the artifact's header pins, so a regenerate-then-format sequence leaves the drift gates green on the stale binary and red on the next build.
- The build identity folds working-tree bytes, so a dsmod regenerated beside uncommitted files (the parallel-lane main tree always carries them) keys the artifact to a tree no commit contains: every clean checkout — a lane worktree at its base included — then fails the drift gate before the lane's first edit. Test a suspected inherited drift by stashing the lane's edits and rerunning, and regenerate from the lane's own clean tree for the lane's gate; the merge regenerates again over the merged tree. An A/B's base side built from such a base pays the splice fallback per member compile silently — the graph fixture measured 89ms against a splicing side's 63ms, a phantom -24% lever that the drift gate alone exposes.
- A count read from input and handed to a pre-loop `Vec::with_capacity` is an unbounded reservation: a five-byte uleb demanded ~900GB and OOMed the reader before its own rejection loop could run. Every table in `ds-mod`'s reader clamps its capacity hint to the bytes the cursor still holds (`Cursor::capacity_for`, or `run` before the reservation), so a new table added without the clamp reintroduces the class — the chain table was the one hit, pinned in `crates/ds-mod/tests/corruption.rs` and carried as the seed `fuzz/corpus/fuzz_read_dsmod/regression-chain-count-reserve.dsmod`.
- A process-static tree serve parks its decode behind a shared handle on the first serve and hands refcount clones out, so the one-serve path pays the decode plus one allocation and the many-serve path pays no clone; the earlier by-value first-serve dance (a one-shot cold run tripping the pin_bake band at +1.0M Ir) exists only for serves whose consumer must own the value, and the shared-tree bundle retired it (the tree share measured +0.026% on the trivial cold run, pin_bake green against the unchanged table). A decode whose output is rebuilt per call anyway (the `.dsi`'s table conversion) needs no such care, its memo is free on the one-serve path.
- Attribute a clone-or-drop cost on a release binary by a gated probe, never by callgrind's symbol names alone: identical-code-folding merges drop-glue symbols (the consts table's LocalDecl row drops appeared as the universe's Vec<AtomDecl> drop glue) and the Clone recursion cycle overcounts inclusive arcs (the walk's LocalDecl clones hid inside an anonymous Expr::clone cycle), so a temporary skip-the-insert probe measured the whole lever (-33.4M whole-process) where the profile's own attribution could not; and read the table's content from the grammar, not the name — every bodied top-level `fn` is a const-of-lambda `Local` item (F2), so "the const table" carries whole fn bodies, which is why one 33-row table dominated both the walk and the teardown.
Measure a member-compile lever on a package-graph fixture, never the trivial cold run: the decodes the lever removes are once-per-process there and once-per-member on `ds run` over a resolved store (N leaf packages plus a pinning root), where the win scales with the member count (−7.0% at 9 compiles, −7.9% at 17).
A cache-root helper that returns the first artifact below the root breaks the day a second artifact family lands beside the first (the dep-member dsmod artifacts beside the root's broke `the_cached_artifact`'s single-artifact assumption): pick the artifact by the module name the test means, never by count or order.
- Size a per-member share whole-process and read its clone/rebuild split from direct-call arcs: the state's teardown (the frees and drops of what the share stopped copying) runs outside the serve function, so the tree share measured −44.4M whole-process where the clone's own inclusive attribution was 24.2M, and callgrind's inclusive numbers overcount recursive `Clone` cycles besides — the honest split came from the arcs into the clone family (24.2M tree clone, 17.3M per-member teardown, 10.8M table rebuild, before the share).
- A hand-assembled fixture's deinit drop shape stages the value into the overlay word, which sits at the frame's body_len boundary: growing the frame (adding a slot for a new snippet) moves the boundary while the staging MOV keeps its old dst, so the directory scan (`hook_sites`) stops recovering the site and the hook never fires — a silent empty-output failure with no trap. Restage into the new overlay slot whenever a fixture frame grows.
