# Fuzzing, benchmarks, and measurement traps

- cargo-fuzz has no automatic dictionary discovery, so pass `-dict=` explicitly; libFuzzer on Windows hangs at exit after `-max_total_time` unless `-runs=<n>` is also set.
- `cargo fuzz run` on Windows dies at spawn with STATUS_ACCESS_VIOLATION when its `-artifact_prefix` ends in a backslash, so build with `cargo fuzz build` and run the target binary directly.
- A Rust panic aborts before libFuzzer's deadly-signal callback registers, so crash artifacts and tmin miss it: recover the input from the panic message.
- Valid dsmod modules are unguessable by mutation because the content hash gates acceptance, so seeds come from `fuzz/tools/gen_dsmod_seeds.rs` and a corpus addition needs `git add -f` (`fuzz/corpus` is gitignored yet tracked); any change to the accepted-bytes set re-runs the generator, since stale seeds die silently at the gate. A byte-patch needle must dodge the fixed header (the format-version byte plus three zero bytes), and a corruption fixture carries the bumped version byte.
- Cross-heap count releases ride exact claim ownership: `Heaps::dec` drops a foreign word's count only when the running fiber's ledger holds the row, so a hand-assembled extra `rc_dec` on a foreign word frees the string under a live closure (`crates/ds-vm/tests/fuzz_vm_fibers.rs`).
- The checker generator leg (`fuzz_check_gen`, a 240-seed nextest mirror in CI) biases declarations to the well-typed surface with weighted wrong splices, and a census field the mirror asserts `> 0` needs a structural carrier rather than a roll chain, since the draws multiply. The execution leg (`fuzz_exec_gen`) keeps tested literals disjoint across arms, since the checker refuses a literal an earlier arm's failed test already excluded, and every distinct-value draw is a bounded redraw with a deterministic fallback.
- The generator legs draw every parser budget at both sides (`fuzz/check_gen.rs`, `fuzz/exec_gen.rs`, the parse leg), because byte noise and the well-typed surface never write a hundred-term type chain: a past-cap `?`/`|`/`~` chain aborts at the AST's recursive drop with no diagnostic reaching the renderers. A census field per side keeps a weighting regression loud.
- A sanitizer leg multiplies memory by its worker count: size the workers to host RAM and keep the host quiet under parallel-agent load.
- The `fuzz_vm` run limit stays stack words, not steps (only the comptime fence runs under `Vm::run_with_budget`), so termination rests on the generator's invariants: every backward edge passes the loop template's decrement exactly once, no jump from before a loop block lands inside it, the spawn tree stays depth one, and every switch re-enters a parked fiber at pc+1. A jump landing on the decrement hangs the join driver.
- A gone joiner's boundary answer surfaces to the drive's host, never switching into a continuation-less fiber (`crates/ds-vm/tests/nursery_joiner_reentry.rs`).
- A hand-assembled fixture's outgoing-argument area is the frame's tail slots, so a native's answer overlays the last slot, never one beside the params: a probe that subtracts a slot the call never wrote answers the staged argument itself and passes vacuously — bracket against an independent witness (the clock's second read) so the expected value cannot come from the staged word alone (`crates/ds-vm/tests/time_sched.rs`).
- A count read from input and handed to a pre-loop `Vec::with_capacity` is an unbounded reservation (a five-byte uleb demanded ~900GB and OOMed the reader before its own rejection loop could run): every table in `ds-mod`'s reader clamps its capacity hint to the bytes the cursor still holds (`Cursor::capacity_for`), so a new table added without the clamp reintroduces the class (`crates/ds-mod/tests/corruption.rs`).
- The pin-bake harness (`crates/ds-pins/tests/pin_bake.rs`) asserts the nine gungraun pins' whole-process Callgrind Ir against the committed `PINS` table on every release-profile run, failing past the ±0.1% band (debug profiles and valgrind-less hosts skip); re-baseline with `PIN_BAKE_RECORD=1` in the commit that changed the codegen. The table is keyed to the canonical binary with no `RUSTFLAGS`.
- gungraun's `main!` defines `fn main` itself, so wrapping the invocation in a `fn main()` runs nothing; its macros' fully-qualified std paths need a targeted `unused_qualifications` allow, and Callgrind pinning needs `[profile.bench] debug = true`. A new pin kernel goes to `crates/ds-pins`, and every bench group states its unit.
- Whole-process callgrind Ir is a noisy per-run sample, so a kernel A/B treats a sub-0.3% Ir delta as flat, and a layout verdict for a stable wall gap at flat Ir comes from perf-stat aggregate counters, never callgrind's simulated cache model. A wall A/B on the gate host is excursion-hostage: only medians of >=10 interleaved reps per side attribute, and perf-stat instructions must match before any cycles delta is read.
- Re-baseline a pin on the committed tree before litigating drift against a prose number, since a round's absolute-Ir figures are pre-commit measurements. A layout regression recorded on one target can invert on another, so bisect on the target that recorded the signature, not on the host that exonerates.
- Attribute a pipeline change by Ir from the callgrind profile and claim wall only where the delta clears the floor's own spread: whole-process wall on the Windows host is floor-dominated for cold start (`ds --version` measures within noise of trivial).
- Attribute an adverse A/B wall delta to per-function Ir before hunting dispatch or semantics: a variant widening the `Value` enum once cost most of a loops-arith regression through the scalar READ path losing its inlining while the arm placement hunt moved nothing. A word-set change re-runs the kernel A/B with whole-process callgrind attribution, never perf sampling.
- Wholesale inlining flips are the dominant wall risk and move both directions inside one round, so an `#[inline]` contract on a dispatch-armed reader is the same class as widening the Value enum: kernel A/B plus whole-process counters. A large hot loop can itself explain an I-cache signature, so classify a fetch-bound gap by whether the hot loop still holds removable work.
- A census bounds dispatch elimination and never promises wall: the load-op fusion's wall A/B stayed inside the noise band while the census said ~14% of the stream's dispatch instances fuse, with every non-fusing KIMM/KCONST still paying the peek.
- Size a deletion whole-process: the frees of what it removed run outside the deleted pass, so its own inclusive attribution understates the win. Size a per-member share the same way and read its clone/rebuild split from direct-call arcs, since callgrind's inclusive numbers overcount recursive `Clone` cycles.
- Attribute a clone-or-drop cost on a release binary by a gated probe: identical-code-folding merges drop-glue symbols and the Clone recursion cycle overcounts inclusive arcs, so a temporary skip-the-insert probe measures the whole lever where the profile's attribution cannot. Read a table's content from the grammar, not the name: every bodied top-level `fn` is a const-of-lambda `Local` item (F2).
- Measure a member-compile lever on a package-graph fixture, never the trivial cold run: the decodes the lever removes are once-per-process there and once-per-member on `ds run` over a resolved store, where the win scales with the member count.
- The checked-prefix serve path costs more Ir than the fresh compute it replaces at trivial scale, so its win profile belongs to programs whose ambient parse and check are real work. A process-static tree serve parks its decode behind a shared handle on the first serve and hands refcount clones out; a decode rebuilt per call anyway (the `.dsi` table conversion) needs no such care.
- A cache-root helper that returns the first artifact below the root breaks the day a second artifact family lands beside the first, so pick the artifact by the module name the test means (`the_cached_artifact`).
- A self-compare micro-bench of a memoized output lies: std's `Arc` equality answers pointer-identical arcs without a walk, so `v == v.clone()` times a fast path the real renewal compare never gets. Pin a memo's renewal decision through a reader's compute count, never through served-value arc identity, since the engine stores the freshly computed value even when the renewal compare answers equal.
- A cold-start A/B whose patched side edits any ds-cli run-path file (even a measurement probe) moves the ambient dsmod's build identity (a side bypassing the serve needs no regeneration), and a dsmod regenerated from a tree no commit contains keys the artifact to that tree — both pay the splice fallback silently, the patched side carrying a phantom Ir delta, and every clean checkout failing the drift gate before its first edit (test a suspected inherited drift by stashing the lane's edits). A silent splice fallback defeats its own gates: it answers the fresh module, so byte equality, the install-shape assertions, and run-output comparisons pass vacuously while every compile pays the serve plus the failed attempt's plan-and-linearity pass. Attribute a suspected fallback by the call graph's call counts, never an Ir delta alone, and pin the splice's success with a marker a gate can read (`Lowered::spliced`). The refusal class that hid it: an artifact row naming a structural atom (`list[byte]`, the json span members) that only the body walk the splice skips ever mints.
- Measure a dec position on a fresh production per iteration (a concat result), not an interned literal: the release-at-use spelling drops the count to zero before the re-acquire and pays teardown plus re-intern every iteration (`crates/ds-pins/benches/loop_claims.rs`).
- A hand-assembled fixture's deinit drop shape stages the value into the overlay word at the frame's body_len boundary, so growing the frame moves the boundary while the staging MOV keeps its old dst: the directory scan (`hook_sites`) stops recovering the site and the hook never fires — a silent empty-output failure with no trap. Restage into the new overlay slot whenever a fixture frame grows.
- A deleted worktree is the poison event and is avoidable: keep one persistent worktree per writer lane (repoint its HEAD, never remove the directory), since a stale test binary baked with a removed tree's absolute paths can be selected as fresh and every ds-cli integration test then fails at process spawn with NotFound.
- `benchmarks/ab.sh` times whole-process wall clock, so its percentages understate in-VM deltas symmetrically.
- An ambient signature change lands with its corpus sweep in the same commit: after any ambient rename or a new check-stage refusal class, sweep the old spelling over `benchmarks/kernels/`, `examples/`, and `conformance/`, and run `sh benchmarks/run.sh check` locally before pushing — HEAD's own check gate is the only signal, since a gate helps only while CI actually runs.
- Float test spellings: a probe cannot spell a float negation (only int negation and boolean not are in the lowering contract), so the float fold's `-0.0` operand is computed arithmetically (`0.0 / (0.0 - 1.0)`), and float goldens print values every printer agrees on (odd fourths), since Rust prints `250.0` as `250` while Python and Lua keep the fraction. `ds run` echoes the unit entry result as a trailing `0` line, absorbed by the `^result:` extraction rule.
- The to_json derive e2e fixture's `main` sits exactly at the 256-slot frame cap, so a row added straight to `main` refuses the whole run at lowering (`needs 258 slots`): new rows ride their own helper fn, whose call site alone leaves the frame at the cap.
- A nursery child's answer `Ref` lives in the child's own store, so a host-side test reading it through the main store's `vm.objects()` reads an aliased id (a same-numbered string from another heap): resolve through `vm.objects_of(id)` the way `io_sched`'s `answer_string` does, or a joined-children test reports a sibling's body in every slot.
- A hand-written FFI struct over a kernel ABI asserts its size and field offsets at compile time: a packed-vs-aligned `epoll_event` mismatch compiled cleanly and passed every single-event test, because an `Instant`-ordered lone wake never reads the bytes the layout moved. The deciding observations for a suspected lost wake: `ss`'s Recv-Q showing data sitting in the parked socket's receive queue (user-side interest loss, not late writers), and an env-gated trace's repetition count (a multi-million-line log is a spin or drop loop, not a blocked one). An observation that makes a race disappear — strace spacing batches apart, eprintln tracing, quiet runs — is itself evidence the window is timing-shaped.
- Every e2e harness routes its temp dirs through the per-thread `tempfile::TempDir` guard lists in `tests/support/mod.rs`, dropped at the test thread's exit under both cargo test and nextest (a single-test process drops its main thread's TLS at main's return, panic paths included): a hand-rolled `env::temp_dir().join(format!("...-{pid}"))` with remove-first has no cleanup owner, and a pid reuse can collide two runs onto one root. A suite whose tests write MiB-scale stores under `/tmp` must keep that shape or the tmpfs fills — the exhaustion surfaces as `LLVM ERROR: IO failure on output stream: No space left on device` inside an unrelated cdylib-fixture link, so check `df /tmp` before blaming the fixture or the latest commit.
- The ds-cli bin tests race under cargo test's thread-parallel harness: two ambient-served compiles interleaving inside one process can answer `no lowerable \`main\` entry in the package` at a cold `source::compile` (`dsi_cache`'s round-trip and equivalence tests, varying per run), while the nextest gate never reproduces it (each test runs in its own process) and `--test-threads=1` runs green — verified flaky on a clean tree, so attribute a parallel `cargo test` failure there to the harness before bisecting a member edit.
