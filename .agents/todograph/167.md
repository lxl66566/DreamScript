The @std documentation pass (ruled 2026-11-27; landed 2026-11-27): every `pub` declaration across the @std sources (the ambient core, the json/string/codec/datetime/error faces, the bodied members, std_members) carries a `///` doc run — one or two objective lines over what the member does and its answer shape — and the renderers carry it: `ds doc` renders the parse layer's attached run per entry into docs/en/reference.md (a plain `//` run above the declaration stays maintainer notes that never render), and the LSP hover answers the signature spelling with the doc run before the checked type — the declaration tier for `pub` package declarations, the member tier for trait member fns and inherent impl functions over the member's own `fn` signature. The comment stays optional surface with no gate on user code. Residual: the linked tier (an import-bound name, the data-shaped std_members declarations among them) reads the cached `.dsi` alone, which carries no docs, so those hovers answer no doc until a doc field crosses the `.dsi`; struct fields and enum-case payload doc slots render nowhere; a trait impl's own member fn carries no `///` of its own (the trait member's doc serves every hover at it).
